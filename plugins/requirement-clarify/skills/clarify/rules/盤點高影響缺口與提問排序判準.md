# 盤點高影響缺口與提問排序判準

## Rule 1 -- 先問影響範圍最大的缺口

**強度：MUST**

必須依「答案不同時，呼叫者後續產出要改動的範圍」排序：會改變產出的整體範圍、主要結構或難以回頭的決策者最先問；只影響命名、措辭、枝節格式或可延後補充的細節，不得排在這些缺口之前。呼叫者已指定提問面向時，先問該面向，只在不違反呼叫者要求時，才依影響範圍補充其他缺口。

### Good Example

這個範例先確認第一版範圍與審核流程，兩者的答案不同時，後續產出的整體範圍與主要流程都要跟著改。

```text
需求：我要做公司內部請假系統。
先問：
1. 第一版只做請假申請與主管審核，還是也要納入 HR 後台？
2. 請假流程是單層審核、雙層審核，還是依條件切換？
```

### Bad Example

這個範例先問按鈕文案與配色，第一版範圍仍未確認，使用者若在第一輪後停止，影響最大的缺口不會被問到。

```text
需求：我要做公司內部請假系統。
先問：
1. 送出按鈕要寫「提交」還是「送出」？
2. 主色要藍色還是綠色？
```

## Rule 2 -- 每題只聚焦一個決策軸

**強度：MUST**

每題只能處理一個決策軸；兩個疑點會導向不同選項集合時，必須拆成不同題。前因後果可寫在 `Context`，但 `總結之提問` 只能要求使用者決定一件事。

### Good Example

這個範例把「第一版範圍」與「通知整合方式」拆成兩題，每題都能用一個選項作答。

```text
題 1：第一版希望先交付哪一種範圍？
題 2：第一版通知與整合最希望先做到哪一種程度？
```

### Bad Example

這個範例在一題中同時問範圍、通知與時程，使用者無法用單一選項作答，回答也難以對應到選項。

```text
你第一版要不要做 HR 後台、要不要串 Slack，而且希望兩週內上線嗎？
```

## Rule 3 -- 題數依呼叫者指定

**強度：MUST**

每輪題數與題數上限依呼叫者指定；呼叫者未指定時，每輪最多 3 題、累計最多 5 題。呼叫者指定「只問一輪」時，本輪回答後即交還呼叫者；指定「不設上限」時，只在缺口已收斂或使用者喊停時結束。高影響缺口多於每輪題數時，先問最關鍵者，其餘留待下一輪；達到題數上限仍無法收斂時，交還呼叫者並列出剩餘風險與卡點，不得繼續追加題目。

### Good Example

這個範例在呼叫者未指定題數時，依預設先問 3 題，等使用者回答後才判斷是否需要第二輪。

```text
Round 1：
1. 第一版範圍
2. 審核流程
3. 通知整合
```

### Bad Example

這個範例在呼叫者未指定題數時一次列出 8 題，超過預設的每輪 3 題，使用者必須一次處理所有缺口，低影響的題目也稀釋了關鍵決策。

```text
Round 1：
1. 第一版範圍
2. 審核流程
3. 通知整合
4. 權限角色
5. 假別規則
6. 報表需求
7. UI 風格
8. 上線時程
```

## Rule 4 -- 不為湊題數而問

**強度：SHOULD**

使用者已明確拍板的決策，或可由既有上下文推出唯一合理解讀的缺口，預設不提問；只屬於可安全採用預設值的低風險缺口，交由呼叫者帶著明示的假設繼續。實際存在的高影響缺口少於每輪題數時，只問實際存在的缺口。

### Good Example

這個範例中使用者已說明只需主管單層審核，因此只問尚未拍板的通知方式，按鈕文字交由呼叫者以假設處理。

```text
已知：使用者說「主管核准就好，不用 HR 再看」。
本輪提問：
1. 第一版的通知與整合，你最希望先做到哪一種程度？
交由呼叫者假設：送出按鈕文字採「送出」。
```

### Bad Example

這個範例重問使用者已拍板的審核層級，又為湊滿 3 題加入按鈕文字，使用者被迫重複回答，也會懷疑先前的回答沒被採納。

```text
已知：使用者說「主管核准就好，不用 HR 再看」。
本輪提問：
1. 請假流程要採單層審核還是雙層審核？
2. 第一版的通知與整合，你最希望先做到哪一種程度？
3. 送出按鈕要寫「提交」還是「送出」？
```
