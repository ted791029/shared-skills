# Context與選項題撰寫判準

## Rule 1 -- Context 必須足以支撐判斷

**強度：MUST**

每題的 `Context` 必須說明這題為什麼重要、答案會影響什麼，以及使用者回答前需要知道的最小背景；涉及專有名詞、流程節點、技術架構或角色分工時，必須先用白話解釋。不得寫成空泛開場白，也不得把未經確認的假設寫成既定事實。文字難以說清流程或結構時，可附上 Mermaid 圖。

### Good Example

這個範例說明範圍選擇會影響哪些後續決策，並先解釋 MVP，使用者知道自己正在拍板什麼。

```text
你目前已明確的是「要做請假系統」，但還沒有明確第一版要做到多大範圍。
這會直接影響畫面數量、資料表設計、權限模型與開發時程。
這裡的 MVP 指的是第一版最小可用範圍，也就是先把最核心、最不能錯的流程做對。
```

### Bad Example

這個範例沒有任何決策背景，使用者只能猜測這題影響什麼，容易憑直覺作答而選錯。

```text
我需要你回答這個問題，這很重要。
```

## Rule 2 -- 總結之提問必須一句可答

**強度：MUST**

`總結之提問` 必須延續 `Context`，濃縮成一句讀完就知道要決定什麼、可直接由選項作答的問題；不得寫成多重追問、模糊追問或口語碎片。

### Good Example

這個範例只用一句話問第一版交付範圍，使用者能直接從選項中作答。

```text
第一版你希望先交付哪一種範圍？
```

### Bad Example

這個範例在一句話中混入範圍與通知兩件事，又附帶「還沒想好」的開放追問，使用者無法對應到任何一個選項。

```text
所以你現在是想先做小一點還是說也可能要把通知那些一起弄，或者你其實還沒想好？
```

## Rule 3 -- Options 必須是可比較的表格

**強度：MUST**

選項必須寫成含 `編號`、`選項`、`說明` 三欄的 Markdown 表格，標題標示單選或多選，最後一列固定為 `Others`。每個選項的說明以 1 至 2 句寫出該選項的邊界，以及與其他選項的區隔。

### Good Example

這個範例使用三欄表格、標示單選，每個說明都寫出範圍邊界，最後保留 `Others`。

```markdown
**Options（單選）**

| 編號 | 選項 | 說明 |
| --- | --- | --- |
| 1 | 只做請假申請與主管審核（推薦：先鎖定核心流程，最快驗證需求） | 先聚焦最核心流程，不先做 HR 後台與報表。 |
| 2 | 請假申請 + 主管審核 + HR 後台 | 同時納入 HR 的管理需求，但第一版範圍會比較大。 |
| 3 | Others | 我的需求不是以上兩種，想補充真正想做的範圍。 |
```

### Bad Example

這個範例沒有表格、編號與說明，看不出各選項的差異，也沒有 `Others`，使用者的真實情況不在選項內時只能硬選一個。

```text
A. 小版
B. 大版
C. 其他
```

## Rule 4 -- 推薦選項必須附理由

**強度：MUST**

每題必須推薦一個選項，並在選項文字後以 `（推薦：<理由>）` 寫出簡短理由。理由必須指向目前上下文中的效益、風險控制、驗證速度或資訊完整性；呼叫者已指定決策偏好或限制時，推薦必須對齊該限制。

### Good Example

這個範例的推薦理由指出驗證速度的效益，呼應第一版要先驗證核心流程。

```text
只做請假申請與主管審核（推薦：先鎖定核心流程，最快驗證需求）
```

### Bad Example

這個範例只標示推薦、沒有理由，使用者無法判斷推薦依據是否適用自己的情況，只能盲從或忽略。

```text
只做請假申請與主管審核（推薦）
```

## Rule 5 -- 直接在對話中提問

**強度：MUST**

提問必須以一般對話訊息直接輸出，讓使用者在同一段上下文中閱讀 `Context`、Mermaid、問題與選項；不得改用 Ask Tool 或其他表單式互動。

### Good Example

這個範例以對話訊息輸出完整題目，Context、問題與選項表格都在同一則訊息中。

```markdown
## 問題 1

**Context**  
你目前已經明確的是「要做公司內部請假系統」，但還沒有明確第一版要做到多大範圍。

**總結之提問**  
第一版你希望先交付哪一種範圍？

**Options（單選）**

| 編號 | 選項 | 說明 |
| --- | --- | --- |
| 1 | 只做請假申請與主管審核（推薦：先鎖定核心流程，最快驗證需求） | 先支援員工送出請假、主管核准或退回。 |
| 2 | Others | 我想補充第一版真正要做的範圍。 |
```

### Bad Example

這個範例改用 Ask Tool 表單，表單只容得下短標籤，Context 與選項說明都被省略，使用者看不到判斷依據。

```text
AskUserQuestion(question="第一版範圍？", options=["小", "大"])
```
