# 基準格式規範

## Rule 1 -- 來源必須可追溯且轉錄方式只能是逐字或摘要

**強度：MUST**

檔頭的「來源」必須寫出 skill 以外的原始文件名稱或路徑與版本，來源沒有版本時改寫取得日期；條目由使用者補充時寫「使用者補充」與日期。不得把目標 skill 內會被改寫或刪除的檔案（例如被抽出資料的 RuleFile、腳本的資料檔）寫成來源。條目不是全部取自同一份來源時，檔頭列出每一份來源，條目表加上「出處」欄逐條寫出；基準不是 Markdown 時，補充的條目放在另一個檔案，由索引檔標示出處。「轉錄方式」只能是「逐字」或「摘要」，不得使用其他字詞。

### Good Example

這個範例的來源寫出原始文件的路徑與版本，使用者補充的條目以「出處」欄逐條標示，轉錄方式使用允許的字詞。

```markdown
- 來源：`docs/api/error-codes.md`（2026-10 版）；使用者補充（2026-11-28）
- 轉錄方式：逐字

| code | HTTP 狀態 | 訊息句型 | 出處 |
|---|---|---|---|
| ORDER_NOT_FOUND | 404 | 找不到訂單 <訂單編號> | `docs/api/error-codes.md` |
| ORDER_LOCKED | 423 | 訂單 <訂單編號> 結帳中，請稍後再試 | 使用者補充 |
```

### Bad Example

這個範例把來源寫成抽完基準就會刪除的腳本資料檔，之後無從核對原始出處；轉錄方式寫「整理」，無法判斷內容能否逐字比對。

```markdown
- 來源：`scripts/codes.json`
- 轉錄方式：整理
```

## Rule 2 -- 條目結構必須一致

**強度：MUST**

同一份基準的每個條目必須使用相同的欄位與順序。條目的欄位含多行內容、無法寫成表格的一列時，改為每個條目使用同一層標題與相同的欄位清單。條目沒有某個欄位的資料時填「無」，不得省略欄位。

### Good Example

這個範例的兩個條目使用同一層標題與相同的欄位。

```markdown
### ORDER_NOT_FOUND

- HTTP 狀態：404
- 訊息句型：找不到訂單 <訂單編號>

### PAYMENT_DECLINED

- HTTP 狀態：402
- 訊息句型：信用卡授權失敗，請改用其他付款方式
```

### Bad Example

這個範例的第二個條目省略欄位並改用敘述，腳本無法以相同方式解析，agent 也無法判斷缺少的欄位是沒有還是漏寫。

```markdown
### ORDER_NOT_FOUND

- HTTP 狀態：404
- 訊息句型：找不到訂單 <訂單編號>

### PAYMENT_DECLINED

授權失敗時回 402。
```

## Rule 3 -- 條目必須有唯一名稱

**強度：MUST**

每個條目必須有一個在該基準內不重複的名稱（表格的第一欄或條目標題），Rule 與產出以這個名稱指明對照的是哪一個條目。來源本身沒有不重複的名稱時，由轉錄者編訂名稱，並在檔頭加一個「條目名稱」列表項目說明名稱由轉錄者編訂與編訂方式；編訂的名稱不算改寫原文。

### Good Example

這個範例的第一份基準以來源既有的 `code` 作為條目名稱；第二份的來源沒有不重複的名稱，由轉錄者編訂並在檔頭說明。

```markdown
| code | HTTP 狀態 | 訊息句型 |
|---|---|---|
| ORDER_NOT_FOUND | 404 | 找不到訂單 <訂單編號> |
| ORDER_CANCELLED | 409 | 訂單 <訂單編號> 已取消 |
```

```markdown
# 找不到資源的訊息句型

- 來源：`docs/api/messages.md`（2026-10 版）
- 轉錄方式：逐字
- 條目名稱：來源沒有名稱，由轉錄者以「資源-序號」編訂

| 條目 | HTTP 狀態 | 訊息句型 |
|---|---|---|
| 訂單-1 | 404 | 找不到訂單 <訂單編號> |
| 商品-1 | 404 | 找不到商品 <商品編號> |
```

### Bad Example

這個範例以 HTTP 狀態作為第一欄，兩列名稱相同，產出寫「對照 404」時無法判斷是哪一列。

```markdown
| HTTP 狀態 | 訊息句型 |
|---|---|
| 404 | 找不到訂單 <訂單編號> |
| 404 | 找不到商品 <商品編號> |
```

## Rule 4 -- 選讀的型錄拆成索引與一項一檔

**強度：SHOULD**

每次使用只需要讀其中部分條目，且單一條目本身是多行區塊（例如一張圖、一段程式、一份範本）時，應在 `rules/baselines/` 底下建立一個資料夾，一個條目一個檔案，並以 `索引.md` 列出每個條目的名稱、檔案與選讀條件。條目是單行或每次都要整份對照時，維持單一檔案。

### Good Example

這個範例每個條目是一份多行的回應範本，使用時只需讀本次端點所屬領域的檔案，因此拆成一項一檔並附索引。

```text
rules/baselines/錯誤回應範本/
  索引.md
  訂單.md
  付款.md
```

```markdown
# 錯誤回應範本 索引

- 來源：`docs/api/error-samples/`（2026-10 版）
- 轉錄方式：逐字

| 條目 | 檔案 | 選讀條件 |
|---|---|---|
| 訂單 | 訂單.md | 端點路徑以 `/orders` 開頭 |
| 付款 | 付款.md | 端點路徑以 `/payments` 開頭 |
```

### Bad Example

這個範例把每個領域的多行範本全部寫在同一個檔案，agent 每次都要讀完所有領域，才找得到本次端點需要的那一份。

```text
rules/baselines/錯誤回應範本.md   （含訂單、付款、會員、物流等所有領域的完整範本）
```
