# 基準連動調整

## Rule 1 -- Rule 必須移除已抽出的資料並宣告基準

**強度：MUST**

改寫指定 Rule 時，必須在描述中以相對連結指明基準檔，寫出對照的方式（例如逐字相同、只換佔位符、取自其中一個條目），並把已抽成基準的資料從描述中移除，只在描述最後保留 Example 用到的條目。Rule 的要求與強度不得改變。以下 Example 皆對照此基準與 Rule 的 Example：

```text
rules/baselines/錯誤代碼表.md：14 個條目
Rule 3 的 Good Example 與 Bad Example 只用到 ORDER_CANCELLED
```

### Good Example

這個範例以連結宣告基準並寫出對照方式，描述最後只保留 Example 用到的一個條目。

```markdown
## Rule 3 -- code 與 message 必須照錯誤代碼表

**強度：MUST**

`code` 必須是[錯誤代碼表](baselines/錯誤代碼表.md)中的一個條目，`message` 必須與該條目的訊息句型逐字相同，只把 `<佔位符>` 換成實際值。以下 Example 皆對照此條目：

| code | HTTP 狀態 | 訊息句型 |
|---|---|---|
| ORDER_CANCELLED | 409 | 訂單 <訂單編號> 已取消，無法再修改 |
```

### Bad Example

這個範例抽出基準後仍在描述中保留全部 14 個條目，同一份資料出現在兩處，新增代碼時只改其中一處就會分歧。

```markdown
## Rule 3 -- code 與 message 必須照錯誤代碼表

**強度：MUST**

`code` 必須是[錯誤代碼表](baselines/錯誤代碼表.md)中的一個條目，`message` 必須與該條目的訊息句型逐字相同，只把 `<佔位符>` 換成實際值：

| code | HTTP 狀態 | 訊息句型 |
|---|---|---|
| ORDER_NOT_FOUND | 404 | 找不到訂單 <訂單編號> |
| ORDER_CANCELLED | 409 | 訂單 <訂單編號> 已取消，無法再修改 |
（其餘 12 列）
```

## Rule 2 -- 只差條目的多條 Rule 必須合併

**強度：MUST**

指定 Rule 與同一份 RuleFile 中的其他 Rule 要求相同、只差對照的條目時，必須合併成一條宣告基準的 Rule，並依 skill-form-rule 重新連續編號。要求不同的 Rule 不得合併。

### Good Example

這個範例把只差錯誤代碼的三條 Rule 合併成一條。

```markdown
調整前：
- Rule 3 -- 找不到訂單時回 ORDER_NOT_FOUND
- Rule 4 -- 授權失敗時回 PAYMENT_DECLINED
- Rule 5 -- 訂單已取消時回 ORDER_CANCELLED

調整後：
- Rule 3 -- code 與 message 必須照錯誤代碼表
```

### Bad Example

這個範例抽出基準後仍保留一個代碼一條的 Rule，新增代碼時要同時加一個條目與一條 Rule，Rule 的數量隨型錄無限增加。

```markdown
調整後：
- Rule 3 -- 找不到訂單時回 ORDER_NOT_FOUND（對照錯誤代碼表）
- Rule 4 -- 授權失敗時回 PAYMENT_DECLINED（對照錯誤代碼表）
- Rule 5 -- 訂單已取消時回 ORDER_CANCELLED（對照錯誤代碼表）
```

## Rule 3 -- 指向原資料的文字必須改為指向基準

**強度：MUST**

資料抽出後，同一份 RuleFile 中仍以「下表」、「表中」、「上述清單」等用語指向該資料的文字，必須改為指向基準：其他 Rule 的描述改為連結基準檔，Example 的說明句改為寫出基準的名稱。這些 Rule 的要求、強度與 Example 的 code block 不得改變。以下 Example 皆對照此調整前的內容：

```markdown
Rule 3 的 Good Example 說明句：這個範例的 `code` 取自表中的 ORDER_CANCELLED。
Rule 4 的描述：錯誤代碼表沒有涵蓋的 5xx 錯誤，HTTP 狀態必須依下表的錯誤類別選擇：（其後為 Rule 4 自己的 3 列類別表，未抽出）
```

### Good Example

這個範例把說明句的「表中」改為基準的名稱，Rule 4 提到已抽出資料之處改為連結；Rule 4 自己未抽出的類別表仍稱「下表」。

```markdown
Rule 3 的 Good Example 說明句：這個範例的 `code` 取自錯誤代碼表的 ORDER_CANCELLED。
Rule 4 的描述：[錯誤代碼表](baselines/錯誤代碼表.md)沒有涵蓋的 5xx 錯誤，HTTP 狀態必須依下表的錯誤類別選擇：
```

### Bad Example

這個範例沒有調整指向原資料的文字，Rule 3 的 14 列表格搬走後，說明句的「表中」只剩描述最後的一列可指，Rule 4 的「錯誤代碼表」在 RuleFile 內找不到，agent 無從得知要去哪裡查有沒有涵蓋。

```markdown
Rule 3 的 Good Example 說明句：這個範例的 `code` 取自表中的 ORDER_CANCELLED。
Rule 4 的描述：錯誤代碼表沒有涵蓋的 5xx 錯誤，HTTP 狀態必須依下表的錯誤類別選擇：
```

## Rule 4 -- 持有同一份資料的樣板與腳本必須改為引用基準

**強度：MUST**

基準抽出後，目標 skill 中持有同一份資料的樣板骨架與腳本必須改為引用基準：骨架中這份資料改為重複區塊，並在重複區塊的註解連結基準；腳本改為讀取基準檔，原本的資料檔刪除。不得在基準以外留下可以單獨修改的完整副本。樣板範例是完成的產出，保留基準的內容不算副本。以下 Example 皆對照此情境：

```text
rules/baselines/錯誤代碼表.md 已抽出（14 個條目）
scripts/codes.json：14 個代碼，由 scripts/check_codes.py 讀取
templates/錯誤回應.md：附錄寫死全部 14 個代碼
templates/錯誤回應.example.md：附錄列出全部 14 個代碼
```

### Good Example

這個範例讓腳本改讀基準檔並刪除原資料檔，骨架的附錄改為重複區塊並在註解連結基準；範例檔是完成的產出，附錄保留不動。

```markdown
- scripts/check_codes.py：改讀 rules/baselines/錯誤代碼表.md 的條目表；刪除 scripts/codes.json
- templates/錯誤回應.md：附錄改為重複區塊，註解寫「每個代碼一列，取自[錯誤代碼表](../rules/baselines/錯誤代碼表.md)」
- templates/錯誤回應.example.md：不變
```

### Bad Example

這個範例只改寫 Rule，腳本與骨架各自保留一份代碼，新增代碼時只改基準，檢查腳本會把新代碼判為錯誤，產出的附錄也少一列。

```markdown
- rules/api-錯誤回應規範.md Rule 3：改為宣告錯誤代碼表
- scripts/codes.json、templates/錯誤回應.md：未變動
```
