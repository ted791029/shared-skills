# 基準邊界判斷

## Rule 1 -- 只有型錄才抽成基準

**強度：MUST**

抽取前必須先判斷指定 Rule 的對照資料是否為型錄。符合下列任一項才抽成基準；都不符合時不新增基準，資料留在 Rule 的描述中，並在回覆中說明不抽取的理由。

| 條件 | 判斷方式 |
|---|---|
| 條目數量多 | 對照資料有 10 個以上的條目 |
| 外部來源的逐字轉錄 | 資料取自 skill 以外的文件，且 Rule 要求逐字對照 |
| 被共用 | 兩條以上的 Rule 或任何腳本使用同一份資料 |
| 只需選讀 | 每次使用只需要讀其中部分條目 |

### Good Example

這個範例的第一份資料有 30 個條目且逐字對照，因此抽成基準；第二份只有 3 列、只被一條 Rule 使用，因此不抽。

```markdown
指定 Rule：Rule 3 -- code 與 message 必須照錯誤代碼表
對照資料：30 列錯誤代碼，訊息句型逐字對照 → 條目數量多、外部來源的逐字轉錄 → 抽成基準

指定 Rule：Rule 4 -- HTTP 狀態必須對應錯誤類別
對照資料：3 列類別對照表，只有本條使用，每次整張對照 → 不抽，留在 Rule 4 的描述
```

### Bad Example

這個範例把只有 3 列、只被一條 Rule 使用的小表也抽成基準，agent 多讀一個檔案才看得到 3 列資料，Rule 也不再能獨立判讀。

```markdown
指定 Rule：Rule 4 -- HTTP 狀態必須對應錯誤類別
對照資料：3 列類別對照表 → 抽成 rules/baselines/錯誤類別對照表.md
```

## Rule 2 -- 基準資料只能取自 Rule 原文或使用者材料

**強度：MUST**

基準的內容只能來自指定 Rule 已內嵌的資料，或使用者提供的材料（檔案、貼上的內容）。兩者都沒有或不完整時，必須停止並請使用者提供材料；不得憑記憶或常識補寫，即使資料是廣為人知的標準。

### Good Example

這個範例的 Rule 要求對照錯誤代碼表，但 Rule 與對話中都沒有這份表，因此停止並詢問。

```text
Rule 3 要求 `code` 必須取自錯誤代碼表，但 Rule 的描述與你提供的材料中都沒有這份表。
請提供錯誤代碼表的檔案或內容，我會逐字轉錄成基準。
```

### Bad Example

這個範例在沒有材料時依常見的 API 慣例自行寫出錯誤代碼，基準與專案實際的代碼不符，卻被 Rule 當成必須逐字遵守的依據。

```markdown
未提供錯誤代碼表 → 依常見慣例撰寫：
| NOT_FOUND | 404 | 找不到資源 |
| UNAUTHORIZED | 401 | 尚未登入 |
```

## Rule 3 -- 只處理指定的 Rule

**強度：MUST**

只為使用者指定的 Rule 抽取基準。其他 Rule 即使也內嵌型錄，只在回覆中提出建議，由使用者決定。

### Good Example

這個範例只處理指定的 Rule 3，對 Rule 7 只提出建議。

```markdown
指定 Rule：Rule 3
已抽取：rules/baselines/錯誤代碼表.md

建議（未執行）：Rule 7 內嵌 15 列欄位命名對照表，也符合抽成基準的條件。
```

### Bad Example

這個範例順手把未指定的 Rule 7 也抽成基準並改寫，修改超出使用者指定的範圍，未經審視的 Rule 被改動。

```markdown
指定 Rule：Rule 3
已抽取：
- rules/baselines/錯誤代碼表.md（Rule 3）
- rules/baselines/欄位命名對照表.md（Rule 7）
```

## Rule 4 -- 既有基準以引用取代重寫

**強度：MUST**

抽取前必須檢查目標 skill 的 `rules/baselines/`。已有基準包含相同資料時，不得另建新檔，改為讓指定 Rule 宣告既有基準；既有基準只缺部分條目時，在既有基準補上。

### Good Example

這個範例發現既有基準已包含同一份資料，讓指定 Rule 直接宣告它。

```markdown
既有：rules/baselines/錯誤代碼表.md（Rule 3 已宣告）
指定 Rule：Rule 5 -- message 必須照訊息句型撰寫
處理：不新增基準，Rule 5 宣告既有的錯誤代碼表。
```

### Bad Example

這個範例為同一份資料另建名稱相近的基準，兩份檔案日後各自更新，Rule 3 與 Rule 5 對照的內容開始分歧。

```markdown
既有：rules/baselines/錯誤代碼表.md
預計抽取：rules/baselines/錯誤訊息句型表.md
```

## Rule 5 -- RuleFile 尚未被 Step 掛載時不抽取

**強度：MUST**

抽取前必須確認目標 skill 的 SOP 至少有一個 Step 掛載指定 Rule 所屬的 RuleFile。沒有任何 Step 掛載時，基準無法與 RuleFile 掛在同一個 Step，必須停止並回報，不得自行挑選 Step 掛載。以下 Example 皆對照此 SOP：

```markdown
### Phase 2 --- 撰寫錯誤回應

1. WRITE 撰寫每個錯誤情況的回應。
```

### Good Example

這個範例發現沒有 Step 掛載該 RuleFile，停止並回報。

```text
rules/api-錯誤回應規範.md 沒有被任何 Step 掛載，基準抽出後沒有 Step 可以掛。
請先以 skill-derive-rule 把這份 RuleFile 掛到使用它的 Step，再抽取基準。
```

### Bad Example

這個範例自行挑了一個 Step 掛載 RuleFile 與基準，RuleFile 該由哪個 Step 使用沒有經過使用者確認，掛錯 Step 時 agent 會在不相干的步驟讀取整份代碼表。

```markdown
1. WRITE 依 [API 錯誤回應規範](rules/api-錯誤回應規範.md) 與 [錯誤代碼表](rules/baselines/錯誤代碼表.md) 撰寫每個錯誤情況的回應。
```
