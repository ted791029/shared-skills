# 零基推導規範

## Rule 1 -- 不得以既有 SOP 為底稿

**強度：MUST**

優化時，目標 SOP 必須從確認後的預期與根因重新推導，推導期間不得複製或逐句改寫既有 SOP；與既有 SOP 的比對留到存留判定再做。

### Good Example

這個範例依確認後的預期重新排出 Phase，推導出既有 SOP 沒有的「界定抽取範圍」Phase。

```markdown
確認的預期：只為指定 Step 的產出抽樣板
推導：
### Phase 1 --- 界定抽取範圍
### Phase 2 --- 撰寫樣板
### Phase 3 --- 連動調整
```

### Bad Example

這個範例複製既有 SOP 後只在原步驟後追加一步，原本的結構問題原封不動，修改退化成最小補丁。

```markdown
### Phase 1 --- 判斷需求
3. THINK 依 [樣板邊界判斷](rules/樣板邊界判斷.md) 判斷指定步驟中應抽成樣板的格式內容。
4. THINK 過濾掉未指定 Step 的產出。
```

## Rule 2 -- 每個 Step 必須追溯到預期

**強度：MUST**

目標 SOP 的每個 Step 必須能指出它服務於哪項預期、哪個閘門或哪個產出的前置條件；指不出的 Step 不得寫入。

### Good Example

這個範例的每個 Step 都能對應到預期或前置條件。

```markdown
1. READ 讀取目標 skill 的 SKILL.md 與指定 Step。     → 前置：界定範圍需要的輸入
2. THINK 界定指定 Step 中有固定結構的產出。          → 預期：只為指定 Step 抽樣板
3. ASK 未指定 Step 時詢問使用者。                    → 閘門：避免推測範圍
```

### Bad Example

這個範例的第 3 步無法對應任何預期或前置條件，是沿用習慣寫入的步驟，會讓目標 SOP 帶入多餘流程。

```markdown
1. READ 讀取目標 skill 的 SKILL.md 與指定 Step。
2. THINK 界定指定 Step 中有固定結構的產出。
3. WRITE 整理目標 skill 所有 Step 的產出清單。
```
