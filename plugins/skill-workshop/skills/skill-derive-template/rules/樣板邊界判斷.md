# 樣板邊界判斷

## Rule 1 -- 無固定產出格式的步驟不抽樣板

**強度：MUST**

抽取前必須先判斷指定 Step 是否產出具有固定結構的檔案或內容。若 Step 沒有產出（如 READ、ASK），或產出結構每次都不同，則不新增樣板，並在回覆中說明不抽取的理由。

### Good Example

這個範例判斷指定 Step 只是判斷動作，沒有固定產出格式，因此不抽樣板。

```markdown
指定 Step：2. THINK 判斷需要規範的項目。

判斷：產出是判斷結果而非固定結構的檔案 → 不抽樣板。
```

### Bad Example

這個範例為沒有固定產出格式的 Step 硬造樣板，多出沒有對應產出的檔案，增加維護成本，也讓 AI 誤以為判斷結果必須套用固定格式。

```markdown
指定 Step：2. THINK 判斷需要規範的項目。

預計抽取：
- templates/規範項目清單.md
- templates/規範項目清單.example.md
```

## Rule 2 -- 樣板只承載結構，判斷留在 Rule

**強度：MUST**

只有描述產出結構的內容（區塊、欄位、順序、固定語法）可以抽入樣板。判斷標準、取捨條件與避免事項無法以樣板表達，必須留在 RuleFile，不得改寫成骨架中的說明文字。

### Good Example

這個範例的骨架只保留 `## SOP` 區塊、Phase 標題與 Step 行的結構，「每個 Step 只放一個動作」的判斷標準留在 RuleFile，不會殘留到產出。

```markdown
## SOP

### Phase {{phase_number}} --- {{phase_name}}

{{step_number}}. {{action_verb}} {{step_behavior}}
```

### Bad Example

這個範例把判斷標準寫成骨架註解，複製後會殘留在產出中，且與 RuleFile 重複、可能分歧。

```markdown
## SOP

### Phase {{phase_number}} --- {{phase_name}}

<!-- 每個 Step 只放一個動作，不得寫入完成條件或範例 -->
{{step_number}}. {{action_verb}} {{step_behavior}}
```

## Rule 3 -- 樣板只涵蓋指定步驟

**強度：MUST**

抽出的樣板只能對應使用者指定 Step 的產出。其他 Step 的產出即使也適合抽成樣板，只在回覆中提出建議，由使用者決定。

### Good Example

這個範例只為指定的 Phase 2 Step 1 抽樣板，對其他 Step 只提出建議。

```markdown
指定 Step：Phase 2 Step 1 在 `## SOP` 區塊撰寫重點步驟

預計抽取：
- templates/sop.md
- templates/sop.example.md

建議（未執行）：Phase 2 Step 2 的掛載連結也有固定格式，可另行抽取。
```

### Bad Example

這個範例順手為未指定的 Phase 2 Step 2 也抽了樣板，修改超出使用者指定的範圍，未經使用者審視的樣板被加入 skill。

```markdown
指定 Step：Phase 2 Step 1 在 `## SOP` 區塊撰寫重點步驟

預計抽取：
- templates/sop.md（Phase 2 Step 1）
- templates/sop.example.md（Phase 2 Step 1）
- templates/掛載連結.md（Phase 2 Step 2）
- templates/掛載連結.example.md（Phase 2 Step 2）
```

## Rule 4 -- 既有樣板以引用取代重寫

**強度：MUST**

抽取前必須檢查目標 skill 的 `templates/`。已有樣板涵蓋指定 Step 的產出時，不得另建新樣板，改為掛載既有樣板；既有樣板只缺部分結構時，修改既有樣板。

### Good Example

這個範例在既有樣板完整涵蓋時直接掛載，只缺部分結構時修改既有樣板，都不另建新樣板。

```markdown
情境一
已涵蓋：templates/sop.md 與 templates/sop.example.md
處理：不新增樣板，在指定 Step 掛載既有兩份檔案。

情境二
部分涵蓋：templates/sop.md 缺少 Step 行的重複區塊標示
處理：在既有骨架補上重複區塊標示、在範例補上多個 Step，不新增樣板。
```

### Bad Example

這個範例在已有樣板的情況下另建名稱相近的新樣板，造成兩份樣板可能分歧。

```markdown
既有：templates/sop.md

預計抽取：
- templates/標準作業流程.md
- templates/標準作業流程.example.md
```

## Rule 5 -- 產出要對照的資料不抽成樣板

**強度：MUST**

指定 Step 的產出必須對照的既定資料（如代碼表、句型、外部來源的原文）不是產出檔案的結構，不得抽成樣板，也不得寫進骨架或範例作為清單。這類資料只在回覆中建議以 skill-derive-baseline 抽成基準。以下 Example 皆對照此指定 Step 與資料：

```markdown
指定 Step：1. WRITE 撰寫每個錯誤情況的回應。
產出：每個錯誤情況一段 JSON，含 `code` 與 `message`
對照資料：錯誤代碼表（30 個代碼，各有 HTTP 狀態與訊息句型）
```

### Good Example

這個範例只把回應的結構抽成樣板，錯誤代碼表列為建議。

```markdown
預計抽取：
- templates/錯誤回應.json
- templates/錯誤回應.example.json

建議（未執行）：錯誤代碼表是產出要對照的資料，可用 skill-derive-baseline 抽成基準。
```

### Bad Example

這個範例把錯誤代碼表也抽成樣板，AI 會把它當成要產出的檔案骨架，每次都輸出一份代碼表，引用它的 Rule 也找不到對照的基準。

```markdown
預計抽取：
- templates/錯誤回應.json
- templates/錯誤回應.example.json
- templates/錯誤代碼表.md
```
