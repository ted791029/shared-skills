# 規範邊界判斷

## Rule 1 -- 簡單步驟不展開

**強度：MUST**

展開前必須先判斷指定 Step 是否值得抽成 RuleFile。若 Step 是單一機械動作，且沒有 agent 易偏離的判斷標準或專案慣例，則不新增 RuleFile，並在回覆中說明不展開的理由。

### Good Example

這個範例判斷指定 Step 只是插入連結，沒有需要展開的規範，因此不產出 RuleFile。

```markdown
指定 Step：1. WRITE 在指定 SOP Step 加入對應 RuleFile 的連結引用。

判斷：單一機械動作，唯一的慣例（掛載連結格式）已由 skill-form-sop 規範 → 不展開。
```

### Bad Example

這個範例為一個簡單動作硬湊出多條 Rule，增加 context 成本卻沒有降低出錯率。

```markdown
指定 Step：1. WRITE 在指定 SOP Step 加入對應 RuleFile 的連結引用。

預計展開：
- ## Rule 1 -- 只修改指定 Step
- ## Rule 2 -- 不得改寫 Step 原有動作
- ## Rule 3 -- 已有引用時以「與」合併
```

## Rule 2 -- 規範只涵蓋指定步驟

**強度：MUST**

展開的規範只能約束使用者指定的 Step。其他 Step 的規範即使相關也不得寫入；若判斷其他 Step 也需要展開，只在回覆中提出建議，由使用者決定。

### Good Example

這個範例指定第 2 步，預計展開的兩條 Rule 都在約束「怎麼判斷要規範哪些項目」，屬於第 2 步的範圍。

```markdown
目標 SOP：
1. READ 讀取使用者需求與目標 RuleFile。
2. THINK 判斷需要規範的項目。
3. WRITE 撰寫每條 Rule。

指定 Step：2. THINK 判斷需要規範的項目。

預計展開：
- ## Rule 1 -- 規範項目必須對應使用者需求
- ## Rule 2 -- 單一規範項目只對應一條 Rule
```

### Bad Example

這個範例同樣指定第 2 步，但 `Example 必須成對出現` 約束的是第 3 步「撰寫每條 Rule」的產出格式，與第 2 步的判斷無關，超出指定範圍。

```markdown
目標 SOP：
1. READ 讀取使用者需求與目標 RuleFile。
2. THINK 判斷需要規範的項目。
3. WRITE 撰寫每條 Rule。

指定 Step：2. THINK 判斷需要規範的項目。

預計展開：
- ## Rule 1 -- 規範項目必須對應使用者需求
- ## Rule 2 -- Example 必須成對出現
```

## Rule 3 -- 意圖留在 SOP，做法寫入 RuleFile

**強度：MUST**

SOP Step 保留「做什麼」；RuleFile 只寫該動作「怎麼做才合格」的限制、判斷標準與避免事項。不得把 Step 的意圖原句改寫成 Rule。以下 Example 皆對照此 Step：

```markdown
1. WRITE 撰寫每條 Rule。
```

### Good Example

這個範例讓 Step 保留「撰寫每條 Rule」的意圖，Rule 只描述標題格式這項合格標準。

```markdown
## Rule 1 -- Rule 標題必須使用固定格式

**強度：MUST**

Rule 標題格式固定為 `## Rule N -- <規範名稱>`。
```

### Bad Example

這個範例把 Step 的意圖原句搬成 Rule，沒有提供任何合格標準，agent 讀完仍不知道怎樣才算合格。

```markdown
## Rule 1 -- 必須撰寫每條 Rule

**強度：MUST**

撰寫 RuleFile 時必須撰寫每條 Rule。
```

## Rule 4 -- 既有規範以引用取代重寫

**強度：MUST**

判斷邊界前必須檢查目標 skill 的 `rules/` 與 SOP 已引用的其他 skill。已被既有 RuleFile 涵蓋的規範不得重寫，改為引用既有 RuleFile；若全部已涵蓋，則不新增 RuleFile。以下 Example 皆對照此既有規範：

```text
skill-form-rule 的 rules/rule-file-格式規範.md 已涵蓋：Rule 標題格式
尚未涵蓋：規範項目必須對應使用者需求
```

### Good Example

這個範例發現標題格式已被既有 RuleFile 涵蓋，只展開尚未涵蓋的項目。

```markdown
已涵蓋：Rule 標題格式 → 引用 skill-form-rule 的 `rules/rule-file-格式規範.md`

預計展開：
- ## Rule 1 -- 規範項目必須對應使用者需求
```

### Bad Example

這個範例在目標 skill 重寫已被涵蓋的「Rule 標題格式」，同一規範出現在兩處，日後修改時可能分歧。

```markdown
預計展開：
- ## Rule 1 -- 規範項目必須對應使用者需求
- ## Rule 2 -- Rule 標題必須使用固定格式
```

## Rule 5 -- 型錄只展開成一條 Rule

**強度：MUST**

規範項目要對照的是一份型錄（多個條目的要求相同，只差對照的資料）時，只能列為一個規範項目，Rule 只寫要求與對照方式；不得每個條目列一條 Rule，也不得把整份型錄寫進 Rule 的描述。該項目必須標記為交由 skill-derive-baseline 抽出基準。

### Good Example

這個範例把 30 個錯誤代碼的要求列為一個規範項目，並標記交由 skill-derive-baseline。

```markdown
指定 Step：2. WRITE 撰寫錯誤回應。
材料：錯誤代碼表（30 個代碼，各有 HTTP 狀態與訊息句型）

預計展開：
- ## Rule 3 -- code 與 message 必須照錯誤代碼表（對照資料為型錄 → 交由 skill-derive-baseline）
```

### Bad Example

這個範例一個代碼列一條 Rule，RuleFile 變成 30 條內容幾乎相同的 Rule，新增代碼時還要再加一條。

```markdown
預計展開：
- ## Rule 3 -- 找不到訂單時回 ORDER_NOT_FOUND
- ## Rule 4 -- 授權失敗時回 PAYMENT_DECLINED
- ## Rule 5 -- 訂單已取消時回 ORDER_CANCELLED
（其餘 27 條略）
```
