# 樣板範例規範

## Rule 1 -- 範例檔名必須對應骨架

**強度：MUST**

範例路徑固定為 `templates/<樣板名稱>.example.<副檔名>`，樣板名稱與副檔名必須和對應骨架完全相同。每份骨架都必須有一份範例。以下 Example 皆對照此骨架：

```text
templates/sop.md
```

### Good Example

這個範例的範例檔與骨架同名、同副檔名，只在副檔名前多加 `.example`。

```text
templates/sop.example.md
```

### Bad Example

這個範例的範例檔改了分隔方式、放到子目錄或把 `.example` 放在副檔名之後，AI 無法從骨架檔名推得對應範例的位置。

```text
templates/sop-example.md
templates/example/sop.md
templates/sop.md.example
```

## Rule 2 -- 範例結構必須與骨架一一對應

**強度：MUST**

範例必須保留骨架的所有區塊、順序與固定內容，只把填位符號替換為實際內容。以下 Example 皆對照此骨架：

```markdown
# {{feature_name}} 需求規格書

## 背景

{{background}}

## 驗收條件

<!-- 重複開始：每條驗收條件一行 -->
- {{acceptance_criterion}}
<!-- 重複結束 -->
```

### Good Example

這個範例保留骨架的標題格式、區塊順序與固定段落名稱，只替換填位符號。

```markdown
# 購物車結帳 需求規格書

## 背景

客服反映使用者結帳時無法得知運費，導致放棄率偏高。

## 驗收條件

- 結帳頁顯示運費與總金額
- 運費隨配送地址即時更新
```

### Bad Example

這個範例對調區塊順序、把固定段落名稱「驗收條件」改成「驗收標準」，並新增骨架沒有的「備註」段，AI 會學到可以自行調整結構，產出開始偏離骨架。

```markdown
# 購物車結帳 需求規格書

## 驗收標準

- 結帳頁顯示運費與總金額
- 運費隨配送地址即時更新

## 背景

客服反映使用者結帳時無法得知運費，導致放棄率偏高。

## 備註

後續可能加入免運門檻。
```

## Rule 3 -- 範例必須是完成的產出

**強度：MUST**

範例必須呈現 AI 最終產出的樣子，不得殘留任何 `{{snake_case}}` 填位符號，也不得保留骨架中的重複區塊註解。

### Good Example

這個範例所有填位符號都已替換，且移除重複區塊註解，可直接作為產出。

```markdown
# 訂單查詢 需求規格書

## 背景

使用者無法查詢超過三個月的歷史訂單。

## 驗收條件

- 訂單列表可查詢近兩年的訂單
- 可依訂單日期區間篩選
```

### Bad Example

這個範例殘留填位符號與重複區塊註解，AI 會誤以為產出可以保留這些標記。

```markdown
# 訂單查詢 需求規格書

## 背景

{{background}}

## 驗收條件

<!-- 重複開始：每條驗收條件一行 -->
- 訂單列表可查詢近兩年的訂單
- 可依訂單日期區間篩選
<!-- 重複結束 -->
```

## Rule 4 -- 範例必須使用真實情境內容

**強度：MUST**

範例內容必須取自真實可能出現的業務情境，讓 AI 能從範例推斷每個欄位的粒度與寫法。不得使用 `foo`、`bar`、`階段一`、`範例一` 等無意義的佔位內容。

### Good Example

這個範例使用程式碼審查情境，每個 Step 寫出具體的動作對象，AI 能推斷 Step 行為的粒度。

```markdown
### Phase 1 --- 判斷需求

1. READ 讀取使用者指定的 PR 與變更檔案。
2. THINK 判斷變更涉及的模組與風險。
```

### Bad Example

這個範例使用無意義名稱，AI 無法判斷 Phase 名稱與 Step 行為應寫到多細。

```markdown
### Phase 1 --- 階段一

1. READ 讀取 foo。
2. THINK 判斷 bar。
```
