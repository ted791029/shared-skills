# 驗證任務規範

## Rule 1 -- 全端點 verify 只由 [驗證] 任務委派

**強度：MUST**

只有執行標 `[驗證]` 的任務時才委派 `/bdd verify`（不帶範疇，全端點，含 e2e）。紅燈、綠燈、重構任務完成後，Phase 結束時，或範圍內最後一個任務完成後，都不得自行委派 `/bdd verify` 或執行測試指令。階段任務的回歸檢查由 bdd 在任務結尾自行完成（範疇與快速端點資料夾）；跨端點的回歸交給 `[驗證]` 任務。

### Good Example

這個範例在 Phase 3 到 Phase 10 都不跑 verify，只在 T027 委派一次。

```text
T013 [重構] 勾為 [X]（Phase 5 frontend/改答案.feature 完成）→ 繼續 T014，不跑 verify
T026 勾為 [X]（Phase 10 Polish 完成）→ 繼續 T027
T027 [驗證] → /bdd verify（整份 tasks.md 唯一一次）
```

### Bad Example

這個範例沿用每個 Phase 結尾跑一次 verify 的習慣，Phase 3～10 各跑約 16 分鐘，整份多花兩個小時。

```text
T007 勾為 [X]（Phase 3 完成）→ /bdd verify
T010 勾為 [X]（Phase 4 完成）→ /bdd verify
```

## Rule 2 -- 收尾引用 [驗證] 的結果

**強度：MUST**

收尾必須引用範圍內 `[驗證]` 任務的 verify 結果（含重試後再次 verify 的結果），不得再委派一次 `/bdd verify`。範圍不含 `[驗證]` 任務時，不得委派 verify，完成報告的驗證結果必須寫「未執行全端點 verify：範圍不含 [驗證] 任務 <任務編號>」，建議下一步寫「完成其餘任務後由 [驗證] 任務執行，或手動執行 `/bdd verify`」，並由收尾驗證將驗收標準標為無法判定。

### Good Example

這個範例的範圍只到 Phase 5，收尾不跑 verify，在報告寫明未執行與建議下一步。

```text
範圍：T005～T013（Phase 3～5），不含 [驗證] T027
完成報告 › 驗證結果：未執行全端點 verify：範圍不含 [驗證] 任務 T027
建議下一步：完成其餘任務後由 [驗證] 任務執行，或手動執行 `/bdd verify`
驗收標準：AC-01～AC-03 無法判定（沒有 verify 結果）
```

### Bad Example

這個範例在範圍不含 [驗證] 時自行補跑 verify，多花 16 分鐘；Phase 6～10 還沒做，結果很快過時，T027 執行時又要再跑一次。

```text
範圍：T005～T013 完成 → 收尾 /bdd verify
```
