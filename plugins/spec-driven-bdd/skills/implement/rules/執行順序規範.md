# 執行順序規範

## Rule 1 -- 取腳本的 next 逐一執行

**強度：MUST**

下一個任務必須是以範圍的任務編號執行 `tasks_state.py --scope <範圍> --summary` 輸出的 `next`（tasks.md 順序中第一個未完成、且之前的任務都已完成的範圍內任務；它的標記、範疇、適用的必讀與所屬 Phase 標頭在 `next_task`）。不得依個人判斷跳到後面的任務，也不得同時執行多個任務或委派 sub-agent 並行。

### Good Example

這個範例依 next 執行 T008，完成後重新取得 next 才執行 T009。

```text
next：T008 → /bdd red specs/truth/features/backend/改答案.feature（附 Phase 4 標頭）
T008 勾為 [X] → 重新執行 tasks_state.py → next：T009
```

### Bad Example

這個範例看到 database 與 backend 的紅燈範疇不同，委派兩個 sub-agent 同時呼叫 bdd，兩邊都要清空並重建同一個 MySQL 測試資料庫，彼此的起點資料互相覆蓋，Example 隨機失敗。

```text
委派 2 個 sub-agent 並行
  /bdd red specs/truth/features/database/改答案.feature
  /bdd red specs/truth/features/backend/改答案.feature
```

## Rule 2 -- 範圍內仍有未完成任務卻無可執行任務時停止

**強度：MUST**

腳本的 `scope_remaining_count` 不為 0，但 `next` 為 null 時，必須停止並列出 `scope_blocked` 中每個任務的 `unfinished_earlier_tasks`。不得自行忽略順序以繼續執行。

### Good Example

這個範例在 T012 之前的 T011 未完成時停止並說明原因。

```text
範圍內剩餘 T012，但無法執行：
- T012 之前未完成：T011
```

### Bad Example

這個範例判斷前端綠燈只是畫面，先執行 T012 再回頭補 T011 紅燈，bdd green 因範疇內 step 未定義而停下，使用者被打斷處理一個順序就能避免的停下。

```text
T011 尚未完成，但 T012 只是前端畫面，先執行 /bdd green specs/truth/features/frontend/改答案.feature
```

## Rule 3 -- Phase 完成時不停下等待確認

**強度：MUST**

Phase 的任務全部完成後，必須直接繼續下一個 Phase，不得在 Phase 之間停下詢問使用者是否繼續。只有遇到 SOP 中的停止條件時才停止。

### Good Example

這個範例完成 Phase 5 最後一個任務後直接開始 Phase 6。

```text
T013 完成（Phase 5 frontend/改答案.feature 完成）→ 繼續 T014
```

### Bad Example

這個範例在每個 Phase 結束時停下詢問，使用者已選擇一次執行到底，Feature Phase 有 6 個，每個都要再回覆一次才會繼續。

```text
Phase 5 已完成，是否繼續 Phase 6？(yes/no)
```
