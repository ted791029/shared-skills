# 靜態檢查規範

## Rule 1 -- 只修正本任務造成的錯誤

**強度：MUST**

只能修正本任務建立或修改的檔案中的錯誤，以及本任務的修改在其他檔案引發的錯誤（如改了匯出名稱導致 import 失敗）。lint 回報的錯誤位於本任務未修改的檔案、且與本任務的修改無關時，視為無法在任務範圍內修正。

### Good Example

這個範例修正本任務檔案中的 lint 錯誤，並把與本任務無關的錯誤判為範圍外。

```text
frontend/src/skills.js:12 'ROLE_LABELS' is assigned a value but never used → 本任務檔案，修正
frontend/src/pages/GameBoard.jsx:40 no-undef 'copy' → 本任務未修改且無關 → 範圍外，停止回報
```

### Bad Example

這個範例為了讓 lint 通過，順手修改先前任務的 GameBoard.jsx，GameBoard.jsx 的錯誤原因沒有被記錄，建立它的任務也仍標著已完成。

```text
lint 失敗 → 修正 skills.js 與 GameBoard.jsx，lint 通過
```

## Rule 2 -- 不得以放寬檢查讓錯誤消失

**強度：MUST**

修正必須改正程式本身。不得加入停用檢查的註解（如 `eslint-disable`、`oxlint-disable`、`# noqa`、`# type: ignore`、`//nolint`、`@SuppressWarnings`、`#[allow(...)]`）、修改 lint 設定、刪除仍有功能的程式碼或把檔案排除在檢查之外來讓檢查通過。

### Good Example

這個範例移除真正未使用的變數。

```js
const { skill } = props;
```

### Bad Example

這個範例以 disable 註解壓掉錯誤，未使用的 `remaining` 其實是漏實作的剩餘次數顯示，錯誤被藏起來直到 bdd 綠燈時才發現技能面板永遠顯示可用。

```js
// oxlint-disable-next-line no-unused-vars
const { skill, remaining } = props;
```

## Rule 3 -- Setup 完成後依賴未安裝時先安裝

**強度：MUST**

lint 失敗的原因是依賴尚未安裝，而不是程式錯誤時（腳本回報找不到 techstack.md 選用的工具，或輸出顯示找不到工具、模組或套件，如 `not found`、`Cannot find module`、`ModuleNotFoundError`、`no required module provides package`），若 Setup Phase 已全部完成，必須依 techstack.md 的套件管理方式在該 workspace 安裝依賴，再重新執行靜態檢查。Setup Phase 未完成時不安裝，視為 lint 未執行，只看語法檢查結果。

### Good Example

這個範例在 Setup 完成後的第一個任務判斷 lint 失敗是因為依賴未安裝，依 techstack.md 的 npm 在 frontend 安裝後重跑檢查。

```text
T010 檢查：npm --prefix frontend run lint 失敗，輸出「sh: oxlint: not found」→ 依賴未安裝，Setup 已完成 → npm --prefix frontend install → 重新檢查，lint 通過
```

### Bad Example

這個範例把依賴未安裝造成的 lint 失敗當成程式錯誤，試圖修改程式碼讓 lint 通過，兩次修正失敗後停止回報，實際上只差一次安裝。

```text
T010 檢查：npm --prefix frontend run lint 失敗，輸出「sh: oxlint: not found」→ 修改 skills.js → 仍失敗 → 停止回報
```

## Rule 4 -- 同一錯誤修正兩次仍失敗即停止

**強度：MUST**

同一個錯誤修正後重新檢查仍失敗，第二次修正後依然失敗時，視為無法在任務範圍內修正，不得繼續嘗試不同寫法直到通過。

### Good Example

這個範例在兩次修正都無法解決 import 錯誤後停止回報。

```text
第 1 次：改為相對路徑 '../skills.js' → 仍失敗
第 2 次：改為 './skills.js' → 仍失敗
→ 停止回報
```

### Bad Example

這個範例反覆嘗試第五種寫法，最後把技能名稱常數複製一份到 components/SkillPanel.jsx 讓檢查通過，技能名稱從此有兩份定義，特效與面板可能顯示不同名稱。

```text
第 5 次：把 frontend/src/skills.js 的 SKILL_NAMES 複製到 frontend/src/components/SkillPanel.jsx → 通過
```
