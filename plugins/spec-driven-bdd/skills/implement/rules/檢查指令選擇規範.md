# 檢查指令選擇規範

## Rule 1 -- 語法檢查指令依語言取自對照表

**強度：MUST**

語法檢查指令只能為 techstack.md「執行環境」表選用的程式語言依下表提供，格式為腳本 `--syntax` 的「副檔名=指令」，以 `{file}` 代入檔案路徑。標示「不傳」的語言不得自行編造單檔指令，改由 Rule 2 的 lint 指令涵蓋；表中沒有的語言，只能使用該語言官方工具鏈提供、不需專案設定即可檢查單一檔案的指令，沒有這種指令時不傳。

| 語言 | `--syntax` |
|---|---|
| JavaScript | `.js,.mjs,.cjs=node --check {file}` |
| TypeScript | 不傳（單檔檢查會忽略 tsconfig） |
| Python | 不傳（腳本內建 py_compile） |
| JSON | 不傳（腳本內建） |
| Go | `.go=gofmt -l -e {file}` |
| Ruby | `.rb=ruby -c {file}` |
| PHP | `.php=php -l {file}` |
| Shell | `.sh=bash -n {file}` |
| Java、Kotlin、C#、Rust、C、C++、Swift | 不傳（需要專案建置才能檢查） |

### Good Example

這個範例的 techstack.md 選用 Go 與 Shell，依對照表各傳一個語法檢查指令。

```text
techstack.md › 執行環境：Go 1.23、Bash（部署腳本）
--syntax ".go=gofmt -l -e {file}" --syntax ".sh=bash -n {file}"
```

### Bad Example

這個範例為 TypeScript 自行編造單檔指令，`tsc` 單檔執行時不讀 tsconfig.json，`paths` 別名與 `strict` 設定都失效，正確的 import 被誤報為錯誤。

```text
techstack.md › 執行環境：TypeScript 5.6
--syntax ".ts,.tsx=npx tsc --noEmit {file}"
```

## Rule 2 -- lint 指令依 techstack.md 選用的檢查工具

**強度：MUST**

`--lint` 只能傳入 techstack.md 選用的 lint 或型別檢查工具，以及 Rule 1 標示「需要專案建置」或 TypeScript 等語言的工具鏈建置檢查（如 `npx tsc --noEmit`、`go vet ./...`、`cargo check`、`mvn -q compile`、`dotnet build`）。不得加入 techstack.md 沒有選用的工具；techstack.md 沒有選用 lint 工具、語言也沒有建置檢查時不傳 `--lint`，並在完成報告的 lint 寫明未執行與原因。

### Good Example

這個範例的 techstack.md 選用 TypeScript 與 ESLint，lint 傳入兩者，TypeScript 檔案由型別檢查涵蓋。

```text
techstack.md › 開發工具：`eslint`、`typescript`
--lint "npx tsc --noEmit" --lint "npm run lint"
```

### Bad Example

這個範例在 techstack.md 只選用 golangci-lint 的專案另外傳入 staticcheck，staticcheck 未列在 techstack.md，Setup 不會安裝它，每個任務都回報找不到指令。

```text
techstack.md › 開發工具：golangci-lint
--lint "golangci-lint run" --lint "staticcheck ./..."
```

## Rule 3 -- 專案已定義 lint 入口時優先使用

**強度：SHOULD**

專案已定義 lint 入口（如 `package.json` 的 `scripts.lint`、`Makefile` 的 `lint` target、`composer.json` 的 `scripts.lint`）時，`--lint` 應呼叫該入口，讓檢查套用專案自己的參數與範圍；沒有入口時才直接呼叫工具。

### Good Example

這個範例的 `frontend/package.json` 定義了 `"lint": "oxlint"`，以 `--prefix` 在專案根目錄呼叫該入口。

```text
--lint "npm --prefix frontend run lint"
```

### Bad Example

這個範例繞過已定義的入口，在專案根目錄直接呼叫 oxlint，掃描範圍從 frontend 變成整個專案，`backend/.venv/` 與 `frontend/node_modules/` 的第三方檔案也被檢查，回報大量與任務無關的錯誤。

```text
--lint "npx oxlint ."
```

## Rule 4 -- 不得以其他語言的指令代替

**強度：MUST**

沒有適用語法檢查指令的副檔名不得對應到其他語言的指令，必須留給腳本列入 `unchecked`，並寫入完成報告的「未檢查的檔案」。

### Good Example

這個範例的 `.vue` 沒有單檔語法檢查，不傳 `--syntax`，由 lint 檢查並在 `unchecked` 中如實列出。

```text
--syntax ".js=node --check {file}" --lint "npm run lint"
unchecked：frontend/src/App.vue（沒有 .vue 檔案的語法檢查指令）
```

### Bad Example

這個範例把 `.vue` 對應到 `node --check`，Node.js 無法解析 `<template>` 區塊，每個 Vue 檔案都被誤報為語法錯誤。

```text
--syntax ".js,.vue=node --check {file}"
```
