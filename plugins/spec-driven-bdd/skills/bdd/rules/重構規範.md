# 重構規範

## Rule 1 -- 依任務描述或 BDD 重構清單決定重構內容

**強度：MUST**

呼叫者附帶任務描述時（如端點資料夾範疇的 NFR 重構），必須依描述寫出的重構目標與附帶的 NFR 原文重構，描述指定新增的產品檔案可以建立，不得另依清單擴大到描述以外的程式。沒有任務描述時，必須逐項檢查範圍內的程式碼：相近的 step definitions 能否合併成一個帶參數的 step、重複出現的領域值轉換能否抽成自訂參數型別、step 本體中的邏輯能否移進 Driver 或 helper、產品程式是否有重複或命名不清。

### Good Example

這個範例依任務描述把兩個對話框各自的焦點處理抽成共用 hook，只動描述點名的檔案，frontend 資料夾仍全數通過。

```text
refactor 範疇：specs/truth/features/frontend/
任務描述：把改答案與連猜三次對話框各自的焦點處理抽成 frontend/src/hooks/useDialogFocus.js，ChangeSecretDialog.jsx 與 BurstConfirmDialog.jsx 改用它（附 spec.md › NFR-016）
修改：新增 frontend/src/hooks/useDialogFocus.js；ChangeSecretDialog.jsx、BurstConfirmDialog.jsx 改用 hook；step 與 Driver 未修改
```

### Bad Example

這個範例只看產品程式就結束重構，step 中重複出現的玩家轉角色邏輯沒有抽成參數型別，下一個用到玩家的 step 又複製一份。

```text
檢查：app/skills.py 無重複 → 重構完成
（modules/技能/改答案.py 有 3 個 step 各自寫 {"甲": "host", "乙": "guest"}[玩家]）
```

## Rule 2 -- 沒有可重構內容時不修改

**強度：MUST**

沒有任務描述、依清單檢查後沒有需要整理的地方時，視為重構完成，不得為了有改動而修改程式碼。

### Good Example

這個範例檢查後沒有重複與命名問題，不修改任何檔案。

```text
modules/技能/改答案.py 只有 2 個 step、無重複；drivers/modules/技能.py 無重複 → 不修改
```

### Bad Example

這個範例為了有改動而重新命名方法，沒有改善結構，還要同步修改所有呼叫處，增加出錯的機會。

```text
把 replace_answer 改名為 replace_secret_answer，並修改 4 個呼叫處
```

## Rule 3 -- 重構後失敗時修正或還原

**強度：MUST**

重構後修正迴圈的執行有項目失敗或有回歸時，只能修正這次重構造成的錯誤或還原造成失敗的那項重構，不得修改斷言、feature 或 dsl.md，也不得改變產品行為讓測試通過。

### Good Example

這個範例在合併 step 後發生 ambiguous，還原該項合併，其餘重構保留。

```text
重構：合併兩個「系統拒絕這次…」step → 執行 → AmbiguousStep
處理：還原這項合併，保留 Driver 的 _auth 抽取 → 重新執行全部通過
```

### Bad Example

這個範例在重構後斷言失敗，改寫斷言讓它通過，重構實際上改變了行為卻被掩蓋。

```text
重構後：AssertionError: history 筆數 2 != 3
處理：把斷言改成 len(history) >= 2
```

## Rule 4 -- 完成說明列出修改的檔案與原始碼段以外的產品檔

**強度：MUST**

重構完成說明必須分別列出這次修改的 step definitions、Driver 與產品檔案，並依綠燈規範 Rule 3 的判定對照進行中 plan 的 plan.md「原始碼（repo 根目錄）」目錄樹，另列「原始碼段以外的產品檔」：新增、改名或修改的產品檔既不是目錄樹列出的檔案，也不在目錄樹中沒有列出子項目的目錄底下，沒有時寫「原始碼段以外的產品檔：無」；依 Rule 2 沒有修改時寫「沒有可重構的內容，未修改任何檔案」。不得只寫「refactor 完成」。

### Good Example

這個範例分別列出產品程式與測試程式的修改，新增的 hook 位在原始碼段沒有列子項目的 hooks/ 底下，寫明沒有原始碼段以外的產品檔。

```text
refactor 完成：specs/truth/features/frontend/
產品程式：新增 frontend/src/hooks/useDialogFocus.js；ChangeSecretDialog.jsx、BurstConfirmDialog.jsx 改用它
step definitions、Driver：未修改
原始碼段以外的產品檔：無（plan.md 原始碼的 hooks/ 沒有列子項目）
存回的最後一次執行：regressions 0
```

### Bad Example

這個範例只寫完成，implement 不知道重構新增了 frontend/src/lib/focus.js，plan.md 的原始碼段沒有 lib/，沒有交 system-analysis 修正，後續任務照原始碼段找不到這個共用模組，又在 hooks/ 另寫一份。

```text
refactor 完成，regressions 0
```
