# 需求覆蓋分類法

## Rule 1 -- 必須逐一判定全部分類

**強度：MUST**

覆蓋地圖必須包含下表的全部 10 個分類，每個分類都要對照「檢查子項」逐項比對這次範圍內的「對應章節」與這次的需求變更後給出判定，不得只判定看起來有問題的分類，也不得新增或合併分類。範圍依 Rule 4 決定；「對應章節」為「全文」的分類，必須掃描範圍內的所有章節。

| 分類 | 檢查子項 | 對應章節 |
|---|---|---|
| 功能範圍與行為 | 核心使用者目標與成功標準；明確宣告不做的範圍；使用者角色之間的差異（可做的事、可看的資料）；對既有功能的影響（這次的需求新增、拿掉或改變了哪些既有功能的行為，對照 `specs/truth/features/用語表.md` 的「模組」表） | 使用者故事、成功標準、假設、受影響的既有功能 |
| 領域與資料 | 實體、屬性與實體間關係；識別與唯一性規則（什麼算同一筆、可否重複）；生命週期與狀態轉換（有哪些狀態、誰能觸發轉換）；資料量與規模假設 | 關鍵實體、容量 NFR |
| 互動與使用流程 | 關鍵使用者旅程與操作順序；錯誤、空資料、載入中狀態；無障礙與在地化（語系、時區、格式） | 驗收情境、易用性與一致性 NFR、無障礙 NFR |
| 非功能品質 | 效能（回應時間、吞吐量目標）；擴展性（同時使用人數、資料上限）；可靠性與可用性（可用時間、故障後復原期望）；可觀測性（需要記錄或追蹤的操作與事件）；安全與隱私（身分驗證、權限、資料保護、威脅假設）；法規遵循 | 效能、容量、可靠性與資料完整性、安全與隱私、可維護性與可測試性 NFR |
| 外部整合與依賴 | 外部服務及其失效時使用者看到的行為；資料匯入匯出格式；協定與版本相容假設 | 功能需求、邊界情況、相容性 NFR、假設 |
| 邊界與失敗處理 | 負面情境（錯誤輸入、權限不足、資源不存在）；頻率限制與節流；衝突處理（如多人同時編輯、重複送出） | 邊界情況、驗收情境 |
| 限制與取捨 | 使用者明定的限制（如必須離線可用、必須沿用既有帳號）；明確的取捨或被否決的方案 | 假設 |
| 術語一致性 | 標準用語；應避免的同義詞或已停用的舊稱 | 全文 |
| 完成訊號 | 驗收情境可測試；完成指標可量測 | 驗收情境、成功標準 |
| 雜項與佔位 | 待決事項與未拍板的決定；未量化的形容詞（如「穩健」、「直覺」、「快速」、「友善」） | 全文 |

### Good Example

這個範例為 10 個分類都給出判定，沒有問題的分類也列出。

```markdown
| 分類 | 判定 |
|---|---|
| 功能範圍與行為 | Partial |
| 領域與資料 | Missing |
| 互動與使用流程 | Clear |
| 非功能品質 | Partial |
| 外部整合與依賴 | Clear |
| 邊界與失敗處理 | Partial |
| 限制與取捨 | Clear |
| 術語一致性 | Partial |
| 完成訊號 | Clear |
| 雜項與佔位 | Clear |
```

### Bad Example

這個範例只列出有問題的 3 個分類，其他分類是判定為 Clear 還是根本沒檢查無從得知，結尾的覆蓋總表也會缺少這些分類。

```markdown
| 分類 | 判定 |
|---|---|
| 功能範圍與行為 | Partial |
| 領域與資料 | Missing |
| 非功能品質 | Partial |
```

## Rule 2 -- 判定必須依狀態標準

**強度：MUST**

每個分類依下列標準判定，同一分類的子項狀態不一時取最差者：

| 狀態 | 標準 |
|---|---|
| Clear | 每個適用的子項都有可驗證的內容，或已在「釐清紀錄」的任一場次得到使用者的回答（「假設」還留著同一個預設值時也算）；子項不適用於本功能或這次的範圍時也視為 Clear |
| Partial | 子項有提及但內容模糊、未量化、只涵蓋部分情境，或只有使用者還沒回答過的 AI 自選預設值寫在「假設」中 |
| Missing | 本功能會用到該子項，但 spec.md 中沒有任何對應內容 |

### Good Example

這個範例的請假系統 spec 只寫「主管審核」，沒寫代理人與逾期，依標準判為 Partial；AI 自選的預設值只寫在假設中，也判為 Partial；假設中的另一個預設值已在先前的場次由使用者回答，判為 Clear。

```markdown
- 功能範圍與行為：Partial —— 使用者故事 2 只寫「主管審核後通知員工」，未區分主管請假時由誰代理審核。
- 邊界與失敗處理：Partial —— 假設寫「主管 3 天未審核時自動核准」，屬 AI 自選的預設值，使用者未確認。
- 互動與使用流程：Clear —— 假設仍寫「申請送出後預設顯示在『我的申請』最上方」，但場次 2026-10-25 已由使用者確認。
```

### Bad Example

這個範例因為章節有內容就判為 Clear，「審核要快」是未量化的形容詞，「假設」中的值也未經使用者確認，真正的缺口在覆蓋地圖上消失。

```markdown
- 功能範圍與行為：Clear —— 使用者故事 2 有寫主管審核。
- 非功能品質：Clear —— NFR-003 寫「審核通知要快」。
- 邊界與失敗處理：Clear —— 假設已寫明逾期處理方式。
```

## Rule 3 -- Partial 與 Missing 必須附證據

**強度：MUST**

判為 Partial 或 Missing 的分類，必須寫出缺口所在的 spec.md 位置（章節名稱或 FR／NFR／SC 編號）與缺口內容；判為 Missing 時，寫出本功能為何會用到該子項。不得只給狀態。

### Good Example

這個範例寫出位置與缺口內容，Missing 也說明了為何需要。

```markdown
- 非功能品質：Partial —— NFR-003「審核通知要快」未寫出時間上限。
- 領域與資料：Missing —— 關鍵實體未定義「假別餘額」，但使用者故事 1 的驗收情境 2 會扣除特休餘額。
```

### Bad Example

這個範例只給狀態，後續挑選面向與撰寫問題 Context 時都無法得知缺口在哪，只能重新掃描一次 spec。

```markdown
- 非功能品質：Partial
- 領域與資料：Missing
```

## Rule 4 -- 只為修改需求時只判定變更涉及的範圍

**強度：MUST**

只為修改需求而執行（使用者或 PM 提出需求變更，或被交辦修正指定的需求，例如 dev-finding review 的保留並取代）時，覆蓋地圖只比對這些變更，以及 spec.md 中會被它們改變的章節（所屬的故事與驗收情境、相關的需求與成功標準、邊界情況、假設與受影響的既有功能）；仍要為全部 10 個分類給出判定，變更不涉及的分類判為 Clear，範圍外的既有內容即使有缺口也不列入。使用者要找出規格盲點時，範圍才是 spec.md 全文。以下 Example 皆對照此需求變更與 spec.md：

```text
需求變更（PM 在實作途中提出）：結果畫面要顯示這場對局的總回合數
spec.md：使用者故事 2「對局結束後查看結果」含驗收情境 1～3 與 FR-008～FR-010，寫「每輪房主先猜、加入者後猜」；「假設」另有 3 條 AI 自選的預設值，分屬使用者故事 1 的配對規則與使用者故事 3 的聊天訊息文字
```

### Good Example

這個範例只比對總回合數與它會改變的使用者故事 2、邊界情況，仍判定全部 10 個分類；使用者故事 1、3 的預設值不在範圍內，沒有列入。

```markdown
- 功能範圍與行為：Clear —— 總回合數顯示在使用者故事 2 的結果畫面，雙方都看得到。
- 領域與資料：Partial —— 「總回合數」是否包含因技能被跳過的回合沒有寫。
- 互動與使用流程：Clear —— 只多一項顯示，沒有新的操作。
- 非功能品質：Clear —— 變更不涉及。
- 外部整合與依賴：Clear —— 變更不涉及。
- 邊界與失敗處理：Partial —— 對手中途離開而提前結束時，總回合數算到哪一回合沒有寫。
- 限制與取捨：Clear —— 變更不涉及。
- 術語一致性：Partial —— 需求變更寫「回合」，使用者故事 2 寫「輪」。
- 完成訊號：Clear —— 可在結果畫面的驗收情境驗證顯示的數字。
- 雜項與佔位：Clear —— 變更不涉及。
```

### Bad Example

這個範例掃描 spec.md 全文，把使用者故事 1、3 的預設值也列為缺口；PM 只想加一項顯示，卻被問到配對規則與聊天訊息文字，答案還可能改到不相干的需求，讓已經完成的下游產物無故成為待補跑。

```markdown
- 功能範圍與行為：Partial —— 使用者故事 1 的配對規則只有 AI 自選的預設值。
- 領域與資料：Partial —— 「總回合數」是否包含因技能被跳過的回合沒有寫。
- 互動與使用流程：Partial —— 使用者故事 3 的聊天訊息文字只有 AI 自選的預設值。
- 非功能品質：Clear —— NFR-001～NFR-004 皆含數值。
- 外部整合與依賴：Clear —— 沒有外部服務。
- 邊界與失敗處理：Partial —— 對手中途離開而提前結束時，總回合數算到哪一回合沒有寫。
- 限制與取捨：Clear —— 假設寫明不含觀戰與排行榜。
- 術語一致性：Partial —— 需求變更寫「回合」，使用者故事 2 寫「輪」。
- 完成訊號：Clear —— SC-001～SC-003 皆含數值。
- 雜項與佔位：Clear —— 沒有待決事項。
```
