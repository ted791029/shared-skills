# 前端設計前置規範

## Rule 1 -- 只看這次要執行的前端介面列

**強度：MUST**

只有在這次要執行的 Wave 中，有介面 ID 前綴為 UI、異動為 ADD 或 MOD 的介面列時，才檢查前端設計的前置條件。前端介面列全部是「無」或 DEL，或這次範圍內沒有前端端點時，不適用本規範，照常進入 Phase 4。

### Good Example

這個範例只把這次要執行、異動為 ADD 或 MOD 的前端介面列當成檢查的依據。

```text
這次的範圍：Wave 1 前端（UI-01 ADD、UI-02 無）、Wave 2 後端（API-01 MOD）
→ UI-01 為 ADD，檢查前端設計的前置條件
```

### Bad Example

這個範例在前端介面列只有 DEL 時也要求先執行 ui-direction，移除畫面不需要原型，使用者被擋下來做一件不必要的事。

```text
這次的範圍：Wave 1 前端（UI-03 DEL）
→ 有前端介面列，檢查前置條件：DESIGN.md 不存在 → 停止，請先執行 /ui-direction
```

## Rule 2 -- 任一條件成立即為不齊

**強度：MUST**

下列任一條件成立時，前端設計的前置條件即為不齊：`specs/truth/ui/DESIGN.md` 不存在、`specs/truth/ui/tokens.css` 不存在、Phase 3 Step 2 的 check 在 pending 列出 ui-direction。三者都不成立時照常進入 Phase 4；不得以「設計可以之後再補」或「這次改動很小」為由略過。

### Good Example

這個範例的 DESIGN.md 與 tokens 都存在，但 ui-direction 在這個 plan 還沒執行，仍判為不齊。

```text
specs/truth/ui/DESIGN.md：存在；specs/truth/ui/tokens.css：存在
check：pending 有 ui-direction（本 plan 沒有紀錄）
→ 不齊：這個 plan 的 ui/PRODUCT.md 還沒產出
```

### Bad Example

這個範例只看 DESIGN.md 存在就繼續，這個 plan 的產品背景沒有產出，Wave 中的 ui-ux-plan 只能沿用上一個功能的使用者假設畫原型。

```text
specs/truth/ui/DESIGN.md：存在 → 前置條件齊全，進入 Phase 4
（check 的 pending 有 ui-direction，未處理）
```

## Rule 3 -- 不齊時以改了記錄後停止

**強度：MUST**

前置條件不齊時，plan.md 已通過 Phase 2 的檢查與核對，必須以「改了」記錄本 skill，不執行任何 Wave、不寫 wave-report.md；各 Planner 沒有紀錄，維持待補跑，之後由依差異入口重跑。不得在不記錄的情況下停止，也不得在不齊時執行任何 Wave。

### Good Example

這個範例在停止前記錄改了，接續時依差異入口只重跑待補跑的端點，plan.md 不會重新規劃。

```text
plan-package record：system-analysis 改了
pending：ui-direction、ui-ux-plan、api-plan、data-plan
→ 停止；之後執行 /system-analysis 時，依差異範圍規範由 pending 中的 Planner 決定重跑的端點，不改 plan.md
```

### Bad Example

這個範例停止時沒有記錄，下次執行 /system-analysis 時因沒有紀錄照完整流程重新規劃，已經寫好的 plan.md 被整份重寫，介面 ID 也可能改變。

```text
前置條件不齊 → 停止（未記錄）
下次執行 /system-analysis → 沒有紀錄，照完整流程重寫 plan.md
```

## Rule 4 -- 停止時說明缺什麼與怎麼接續

**強度：MUST**

停止時必須說明：成立的條件與缺少的檔案位置；請使用者先執行 /ui-direction，DESIGN.md 或 tokens.css 不存在時，即使 ui-direction 在這個 plan 已有紀錄也要重新執行；完成後執行 /system-analysis，由依差異入口重跑待補跑的端點；不要直接執行各個 Planner，以免跳過 Wave 的順序與相依。

### Good Example

這個範例寫出缺的檔案、要執行的 skill 與接續方式，並提醒不要直接執行 Planner。

```text
前端設計的前置條件不齊，這次只完成了 plan.md（已記錄），分析 Wave 還沒執行：
- 缺少 specs/truth/ui/DESIGN.md 與 specs/truth/ui/tokens.css
- ui-direction 在這個 plan 還沒執行
請先執行 /ui-direction 建立設計方向，完成後再執行 /system-analysis，它會依 Wave 順序重跑前端、後端與資料庫端。
請不要直接執行 /ui-ux-plan 或其他 Planner，Wave 之間有相依，跳過順序會讓後端讀不到前端的契約。
```

### Bad Example

這個範例只說要先跑 ui-direction，沒有說明缺什麼與怎麼接續，使用者跑完後直接執行 /api-plan，後端在前端契約還不存在時就開始設計 API。

```text
請先執行 /ui-direction。
```
