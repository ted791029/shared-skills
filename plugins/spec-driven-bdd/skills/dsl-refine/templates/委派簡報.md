## 回傳格式

完成後只回傳以下內容：

```markdown
### {{endpoint_folder}}

- 產出：新增、修改、刪除的 feature 各 N 份、Rule 各 N 條、Example 各 N 個，句型新增 N 個、修改 N 個、刪除 N 個
- 檢查：`check_features.py --endpoint {{endpoint_folder}}` 的結果（PASS 或 FAIL 與未解決的問題）
- 涵蓋表異動：與涵蓋表「AC 涵蓋表」「補充案例」不同的列（新增、改名或拆分的 Rule），每項寫「AC 或來源需求、When 組、feature、Rule、異動」，沒有時寫「無」
- 句型異動：修改或刪除的既有句型，每項寫「句型、改了什麼、既有 step 要不要改」，沒有時寫「無」
- 待確認事項：依待確認事項規範逐項列出，沒有時寫「無」
- 規格沒寫的行為：spec.md 與 acceptance 都沒寫、要先記錄才能衍生的行為，每項寫「位置、行為、依據」，沒有時寫「無」
- 上游的事實問題：介面文檔與 acceptance 不一致的內容，以及標了擬定、家在介面文檔的識別碼（testid、API 路徑與欄位、錯誤碼、推播事件、資料表與欄位），每項寫「位置、內容、依據、出錯的文檔」，沒有時寫「無」
- 增量衝突：沒有時寫「無」
- AC 句型對照異動：為了沿用或避開本端點既有的句型而改用的句型，每項寫「AC 句型 → 本端點句型（沿用或換句）」，沒有時寫「無」
- 新增技術說法：用語表沒有、自訂業務說法的技術說法，每項寫「技術說法 → 業務說法」，沒有時寫「無」
```
