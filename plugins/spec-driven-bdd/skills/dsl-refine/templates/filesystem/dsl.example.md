# 檔案系統端 DSL

## 參數對照

多列句型共用的「業務值 → 技術目標」對照，型別名稱就是小標題。只有一兩列用到的對照，直接寫在該列。值中獨立的 N 代表數字，X 代表任意名稱。

### `{檔案種類}`

| 值 | 正式路徑 |
|---|---|
| 原始檔 | `originals/<hash 前兩碼>/<content_hash>.<副檔名>`，副檔名依寫入格式：JPEG 為 `jpg`、PNG 為 `png`、HEIC 為 `heic`，沒指定格式時為 `jpg` |
| 縮圖 | `thumbnails/<hash 前兩碼>/<content_hash>.jpg`，不論原始格式 |

## Given 句型

差異句：起點句（Background 或 Example 的第一句 Given）只建立起點，之後的 Given 用 When 句型把狀態推進到需要的樣子。step definition 要讓這些句型在 Given 與 When 都能使用；寫在 Given 時只執行動作，不算進「這次操作」，也不更新操作前的快照；失敗時不攔截錯誤，讓測試直接失敗。

| Given 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `系統處於 {前置狀態}` | 系統處於 {"空儲存區"} | ・**前置狀態** `{前置狀態}`（字串）：起點名稱，只限 空儲存區 | 不支援 | 動作：只寫在 Background 或 Example 的第一句 Given。在暫時目錄建立儲存區根目錄，依本 feature 起點句上方的 `# 預設值：` 註解建立；其他狀態由 Example 的差異句推進<br>保存：儲存區根目錄 → 給之後所有步驟組出路徑 |

## When 句型

| When 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `寫入照片 {照片}` | 寫入照片 {"P1"} | ・**照片** `{照片}`（字串）：要寫入的照片，檔案取自測試資料夾中同名的 JPEG | 不支援 | 動作：`fileStore.createUpload`（擬定），只寫入原始檔；不攔截錯誤<br>保存：回傳的 `content_hash` 與 `stored_path`（擬定）→ 給 Then 的回應斷言與組出正式路徑 |
| `寫入照片 {照片} 與它的縮圖` | 寫入照片 {"P1"} 與它的縮圖 | ・**照片** `{照片}`（字串）：要寫入的照片，檔案取自測試資料夾中同名的 JPEG | 不支援 | 動作：`fileStore.createUpload`（擬定），同時寫入原始檔與縮圖；不攔截錯誤<br>保存：回傳的 `content_hash` → 給組出正式路徑 |
| `寫入格式為 {格式} 的照片 {照片}` | 寫入格式為 {"JPEG"} 的照片 {"P1"} | ・**格式** `{格式}`（字串）：JPEG、PNG 或 HEIC<br>・**照片** `{照片}`（字串）：之後步驟用來指稱這張照片的名稱 | 不支援 | 動作：`fileStore.createUpload`（擬定），只寫入一張該格式的原始檔；不攔截錯誤<br>保存：回傳的 `content_hash`、`stored_path`（擬定）與格式 → 給 Then 的回應斷言與組出正式路徑 |
| `寫入下列照片與它們的縮圖：` | 寫入下列照片與它們的縮圖： | （無） | ・**照片**（字串，必填）：之後步驟用來指稱這張照片的名稱<br>・**格式**（字串，選填）：JPEG、PNG 或 HEIC，沒寫時為 JPEG | 動作：依表格順序，每一列以 `fileStore.createUpload`（擬定）寫入該格式的原始檔與縮圖，內容每張不同；不攔截錯誤<br>保存：每張照片的 `content_hash` 與格式 → 給組出正式路徑 |
| `刪除照片 {照片} 的檔案` | 刪除照片 {"P1"} 的檔案 | ・**照片** `{照片}`（字串）：要刪除檔案的照片 | 不支援 | 動作：`fileStore.removeFiles`（擬定），帶入該照片保存的 `content_hash`；不攔截錯誤 |

## Then 句型

| Then 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `回傳的內容雜湊是 {照片} 內容的 SHA-256` | 回傳的內容雜湊是 {"P1"} 內容的 SHA-256 | ・**照片** `{照片}`（字串）：寫入的照片 | 不支援 | 回應斷言：回傳的 `content_hash` 等於測試以 `crypto` 獨立計算該檔案內容的 SHA-256<br>查證斷言：<br>・權威狀態：讀出正式路徑上的原始檔，以 `crypto` 計算的 SHA-256 也等於回傳值 |
| `{照片} 的 {檔案種類} 在正式路徑` | {"P1"} 的 {"原始檔"} 在正式路徑 | ・**照片** `{照片}`（字串）：寫入的照片<br>・**檔案種類** `{檔案種類}`（字串）：要檢查的檔案 | 不支援 | 回應斷言：回傳的 `stored_path`（擬定）等於該檔案種類的正式路徑<br>查證斷言：<br>・權威狀態：`fs.stat` 該路徑，檔案存在且大小等於寫入的來源檔 |
| `{照片} 的 {檔案種類} 不在正式路徑` | {"P1"} 的 {"原始檔"} 不在正式路徑 | ・**照片** `{照片}`（字串）：刪除的照片<br>・**檔案種類** `{檔案種類}`（字串）：要檢查的檔案 | 不支援 | 回應斷言：無，因為 `fileStore.removeFiles` 沒有回傳值<br>查證斷言：<br>・權威狀態：`fs.stat` 該路徑，回報檔案不存在 |
| `下列檔案仍在正式路徑：` | 下列檔案仍在正式路徑： | （無） | ・**照片**（字串，必填）：寫入的照片<br>・**檔案種類** `{檔案種類}`（字串，必填）：要檢查的檔案 | 回應斷言：無，因為 `fileStore.removeFiles` 沒有回傳值<br>查證斷言：<br>・權威狀態：每一列以 `fs.stat` 該路徑，檔案存在 |
| `暫存區沒有任何檔案` | 暫存區沒有任何檔案 | （無） | 不支援 | 回應斷言：無，因為 `fileStore.createUpload` 的回傳值不含暫存區的資訊<br>查證斷言：<br>・不該發生：`fs.readdir(tmp/)` 的檔案數為 0 |

## Step 檔對照

每個句型歸屬一個模組與能力。Step 檔路徑相對於專案測試設定中本端點載入的 step 目錄；`shared` 只收不屬於任何模組領域的句型。

| 模組 | 能力 | Step 檔 | 句型 |
|---|---|---|---|
| shared | 系統狀態 | `shared/系統狀態.js` | `系統處於 {前置狀態}` |
| 照片 | 寫入檔案 | `modules/照片/寫入檔案.js` | `寫入照片 {照片}`<br>`寫入照片 {照片} 與它的縮圖`<br>`寫入格式為 {格式} 的照片 {照片}`<br>`寫入下列照片與它們的縮圖：`<br>`回傳的內容雜湊是 {照片} 內容的 SHA-256` |
| 照片 | 刪除檔案 | `modules/照片/刪除檔案.js` | `刪除照片 {照片} 的檔案` |
| 照片 | 檔案位置 | `modules/照片/檔案位置.js` | `{照片} 的 {檔案種類} 在正式路徑`<br>`{照片} 的 {檔案種類} 不在正式路徑`<br>`下列檔案仍在正式路徑：`<br>`暫存區沒有任何檔案` |
