# 資料庫端 DSL

## 參數對照

多列句型共用的「業務值 → 技術目標」對照，型別名稱就是小標題。只有一兩列用到的對照，直接寫在該列。值中獨立的 N 代表數字，X 代表任意名稱。

### `{玩家}`

| 值 | 對應欄位 |
|---|---|
| 甲 | 房主：`rooms` 的 `host_` 開頭欄位，`guesses.guesser_role` 為 `host` |

## Given 句型

差異句：起點句（Background 或 Example 的第一句 Given）只建立起點，之後的 Given 用 When 句型把狀態推進到需要的樣子。step definition 要讓這些句型在 Given 與 When 都能使用；寫在 Given 時只執行動作，不算進「這次操作」，也不更新操作前的快照；失敗時不攔截錯誤，讓測試直接失敗。

| Given 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `系統處於 {前置狀態}` | 系統處於 {"對戰開始輪到甲"} | ・**前置狀態** `{前置狀態}`（字串）：起點名稱，只限 對戰開始輪到甲 | 不支援 | 動作：只寫在 Background 或 Example 的第一句 Given。以 alembic 遷移建立空的測試資料庫，依該 feature 起點句上方的 `# 預設值：` 註解以 pymysql 直接寫入 `players` 與 `rooms` 並提交（註解的回合寫入 `round_number`、輪到的玩家寫入 `current_turn`、技能剩餘次數寫入四個 `*_left` 欄位，`status` 為 playing、`action_seq` 為 0）；不呼叫任何 API；其他狀態由 Example 的差異句推進<br>保存：資料庫連線設定與房間 id → 給之後所有步驟使用 |
| `{玩家} 已在動作序號 {序號} 猜 {四碼}` | {"甲"} 已在動作序號 {1} 猜 {"1234"} | ・**玩家** `{玩家}`（字串）：誰猜<br>・**序號** `{序號}`（整數）：動作序號<br>・**四碼** `{四碼}`（字串）：猜測的四碼 | 不支援 | 動作：以 pymysql 直接新增一筆 `guesses`，`room_id` 為該房間、`seq` 為序號、`round_number` 為 1、`guesser_role` 為該玩家的角色、`guess` 為四碼、`a_count` 與 `b_count` 為對 5678 計算的值、`burst_index` 為 NULL，並提交；不攔截錯誤 |

## When 句型

| When 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `把 {玩家} 的 {技能} 剩餘次數寫成 {次數}` | 把 {"甲"} 的 {"連猜三次"} 剩餘次數寫成 {2} | ・**玩家** `{玩家}`（字串）：誰的次數<br>・**技能** `{技能}`（字串）：改答案對應 `*_change_left`，連猜三次對應 `*_burst_left`<br>・**次數** `{次數}`（整數）：要寫入的剩餘次數 | 不支援 | 動作：先以新的資料庫連線讀取該欄位目前的值，再以 pymysql 直接把該欄位更新為次數並提交；預期被資料庫拒絕，攔截錯誤<br>保存：攔截到的錯誤、寫入前的欄位值 → 給「資料庫拒絕這次寫入，因為 {原因}」 |
| `再寫入 {玩家} 在動作序號 {序號} 猜 {四碼} 的紀錄` | 再寫入 {"甲"} 在動作序號 {1} 猜 {"5678"} 的紀錄 | ・**玩家** `{玩家}`（字串）：誰猜<br>・**序號** `{序號}`（整數）：已被使用的動作序號<br>・**四碼** `{四碼}`（字串）：猜測的四碼 | 不支援 | 動作：先以新的資料庫連線讀取該房間 `guesses` 的列數，再以 pymysql 直接新增一筆 `seq` 為序號的 `guesses`，其他欄位取合法值；預期被資料庫拒絕，攔截錯誤<br>保存：攔截到的錯誤、寫入前的列數 → 給「資料庫拒絕這次寫入，因為 {原因}」 |
| `寫入 {玩家} 連猜第 {次數} 次猜 {四碼} 的紀錄` | 寫入 {"甲"} 連猜第 {4} 次猜 {"1357"} 的紀錄 | ・**玩家** `{玩家}`（字串）：誰猜<br>・**次數** `{次數}`（整數）：連猜的第幾次<br>・**四碼** `{四碼}`（字串）：猜測的四碼 | 不支援 | 動作：先以新的資料庫連線讀取該房間 `guesses` 的列數，再以 pymysql 直接新增一筆 `guesses`，`seq` 為目前最大序號加 1、`burst_index` 為次數，其他欄位取合法值；預期被資料庫拒絕，攔截錯誤<br>保存：攔截到的錯誤、寫入前的列數 → 給「資料庫拒絕這次寫入，因為 {原因}」 |

## Then 句型

| Then 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `資料庫拒絕這次寫入，因為 {原因}` | 資料庫拒絕這次寫入，因為 {"技能次數超過每局次數"}<br>資料庫拒絕這次寫入，因為 {"動作序號已被使用"}<br>資料庫拒絕這次寫入，因為 {"連猜次數超過三次"} | ・**原因** `{原因}`（字串）：被拒絕的業務原因，只限 技能次數超過每局次數、動作序號已被使用、連猜次數超過三次 | 不支援 | 回應斷言：攔截到的錯誤依原因判定：技能次數超過每局次數為 `ck_rooms_skill_counts` 的檢查約束錯誤（MySQL 3819）；動作序號已被使用為 `pk_guesses` 的主鍵衝突（MySQL 1062）；連猜次數超過三次為 `ck_guesses_burst_index` 的檢查約束錯誤（MySQL 3819）；沒有錯誤或其他錯誤都算失敗<br>查證斷言：<br>・權威狀態：開新的資料庫連線，技能次數超過每局次數時查 `rooms` 該欄位仍為寫入前的值；其他原因時查該房間 `guesses` 的列數等於寫入前的列數 |

## Step 檔對照

每個句型歸屬一個模組與能力。Step 檔路徑相對於專案測試設定中本端點載入的 step 目錄；`shared` 只收不屬於任何模組領域的句型。

| 模組 | 能力 | Step 檔 | 句型 |
|---|---|---|---|
| shared | 系統狀態 | `shared/系統狀態.py` | `系統處於 {前置狀態}` |
| shared | 資料庫約束 | `shared/資料庫約束.py` | `資料庫拒絕這次寫入，因為 {原因}` |
| 技能 | 房間資料表 | `modules/技能/房間資料表.py` | `把 {玩家} 的 {技能} 剩餘次數寫成 {次數}` |
| 對戰 | 猜測紀錄資料表 | `modules/對戰/猜測紀錄資料表.py` | `{玩家} 已在動作序號 {序號} 猜 {四碼}`<br>`再寫入 {玩家} 在動作序號 {序號} 猜 {四碼} 的紀錄`<br>`寫入 {玩家} 連猜第 {次數} 次猜 {四碼} 的紀錄` |
