# 後端 DSL

## 參數對照

多列句型共用的「業務值 → 技術目標」對照，型別名稱就是小標題。只有一兩列用到的對照，直接寫在該列。值中獨立的 N 代表數字，X 代表任意名稱。

### `{玩家}`

| 值 | 身份與角色 |
|---|---|
| 甲 | 房主，請求帶甲的身份權杖，回應與歷史中的角色為 `host` |
| 乙 | 加入者，請求帶乙的身份權杖，回應與歷史中的角色為 `guest` |

## Given 句型

差異句：起點句（Background 或 Example 的第一句 Given）只建立起點，之後的 Given 用 When 句型把狀態推進到需要的樣子。step definition 要讓這些句型在 Given 與 When 都能使用；寫在 Given 時只執行動作，不算進「這次操作」，也不更新操作前的快照；失敗時不攔截錯誤，讓測試直接失敗。

| Given 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `系統處於 {前置狀態}` | 系統處於 {"對戰開始輪到甲"}<br>系統處於 {"雙方各猜兩次"} | ・**前置狀態** `{前置狀態}`（字串）：起點名稱，只限 對戰開始輪到甲、雙方各猜兩次 | 不支援 | 動作：只寫在 Background 或 Example 的第一句 Given。在測試行程內以 ASGITransport 建立應用程式並清空測試資料庫，依起點句上方的 `# 預設值：` 註解以 API 開房、加入、設定答案並開始；「雙方各猜兩次」再依註解的順序送出四次猜測<br>保存：玩家名稱對應的身份權杖與房間 id → 給之後以玩家名稱操作的步驟 |

## When 句型

| When 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `{玩家} 送出新答案 {四碼}` | {"甲"} 送出新答案 {"4567"} | ・**玩家** `{玩家}`（字串）：以誰的身份操作<br>・**四碼** `{四碼}`（字串）：新答案，原樣當字串送出 | 不支援 | 動作：先以該玩家身份 `GET /api/rooms/current` 讀一次，再 `POST /api/rooms/{roomId}/skills/change-answer`，帶 `answer` 為四碼<br>保存：<br>・這次的回應 → 給這次 Then 的回應斷言<br>・動作前讀到的 `my_answer` 與技能剩餘次數 → 給「系統拒絕這次…」的查證斷言<br>・新答案與被取代的答案 → 給「看不到…的新答案與舊答案」 |
| `{玩家} 猜 {四碼}` | {"甲"} 猜 {"5679"} | ・**玩家** `{玩家}`（字串）：以誰的身份操作<br>・**四碼** `{四碼}`（字串）：猜測的四碼 | 不支援 | 動作：`POST /api/rooms/{roomId}/guesses`，帶 `guess` 為四碼<br>保存：這次的回應 → 給這次 Then 的回應斷言 |

## Then 句型

| Then 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `{玩家} 的目前答案為 {四碼}` | {"甲"} 的目前答案為 {"4567"} | ・**玩家** `{玩家}`（字串）：誰的答案<br>・**四碼** `{四碼}`（字串）：預期的答案 | 不支援 | 回應斷言：狀態碼 200，回應 `my_answer` 等於四碼<br>查證斷言：<br>・再讀確認：以該玩家身份 `GET /api/rooms/current`，`my_answer` 等於四碼 |
| `雙方的技能剩餘次數如下：` | 雙方的技能剩餘次數如下： | （無） | ・**玩家**（字串，必填）：哪位玩家的次數<br>・**改答案**（整數，必填）：改答案剩餘次數<br>・**連猜三次**（整數，必填）：連猜三次剩餘次數 | 回應斷言：狀態碼 200，回應 `skills` 中每位玩家角色的 `change_answer_left`、`triple_guess_left` 等於各列<br>查證斷言：<br>・再讀確認：雙方各以自己的身份 `GET /api/rooms/current`，`skills` 同名欄位等於各列 |
| `{玩家} 的房間狀態中看不到 {玩家} 的新答案與舊答案` | {"乙"} 的房間狀態中看不到 {"甲"} 的新答案與舊答案 | ・**玩家** `{玩家}`（字串）：以誰的身份查詢<br>・**玩家** `{玩家}`（字串）：被改答案的玩家 | 不支援 | 回應斷言：狀態碼 200，回應 `history` 新增的改答案紀錄只有 `round`、`player`、`kind`，沒有任何四碼欄位<br>查證斷言：<br>・不該發生：以第一位玩家身份 `GET /api/rooms/current`，整份回應文字不含第二位玩家保存的新答案與被取代的答案 |
| `雙方的猜測歷史依序為：` | 雙方的猜測歷史依序為： | （無） | ・**回合**（整數，必填）：回合數<br>・**玩家**（字串，必填）：誰的紀錄<br>・**紀錄**（字串，必填）：使用改答案，或「猜 四碼，xAyB」 | 回應斷言：狀態碼 200，回應 `history` 筆數與表格相同，每筆的 `round`、`player` 與 `kind`、`guess`、`result` 逐列相同<br>查證斷言：<br>・再讀確認：雙方各以自己的身份 `GET /api/rooms/current`，`history` 逐列相同 |
| `系統拒絕這次{技能}，因為 {原因}` | 系統拒絕這次{"改答案"}，因為 {"本局次數已用完"} | ・**技能** `{技能}`（字串）：被拒絕的技能，只限 改答案<br>・**原因** `{原因}`（字串）：四碼規則不符（格式）對應 422 `four_code_invalid_format`，四碼規則不符（重複數字）對應 422 `four_code_duplicate_digits`，本局次數已用完對應 409 `skill_exhausted` | 不支援 | 回應斷言：狀態碼與 `code` 等於原因對應的值<br>查證斷言：<br>・再讀確認：以該玩家身份 `GET /api/rooms/current`，`my_answer` 與該技能剩餘次數都等於動作前保存的值 |

## Step 檔對照

每個句型歸屬一個模組與能力。Step 檔路徑相對於專案測試設定中本端點載入的 step 目錄；`shared` 只收不屬於任何模組領域的句型。

| 模組 | 能力 | Step 檔 | 句型 |
|---|---|---|---|
| shared | 系統狀態 | `shared/系統狀態.py` | `系統處於 {前置狀態}` |
| 技能 | 改答案 | `modules/技能/改答案.py` | `{玩家} 送出新答案 {四碼}`<br>`{玩家} 的目前答案為 {四碼}`<br>`{玩家} 的房間狀態中看不到 {玩家} 的新答案與舊答案`<br>`系統拒絕這次{技能}，因為 {原因}` |
| 技能 | 次數 | `modules/技能/次數.py` | `雙方的技能剩餘次數如下：` |
| 對戰 | 猜測 | `modules/對戰/猜測.py` | `{玩家} 猜 {四碼}`<br>`雙方的猜測歷史依序為：` |
