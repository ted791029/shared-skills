# 前端 DSL

## Given 句型

差異句：起點句（Background 或 Example 的第一句 Given）只建立起點，之後的 Given 用 When 句型把狀態推進到需要的樣子。step definition 要讓這些句型在 Given 與 When 都能使用；寫在 Given 時只執行動作，不算進「這次操作」，也不更新操作前的快照；失敗時不攔截錯誤，讓測試直接失敗。

| Given 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `系統處於 {前置狀態}` | 系統處於 {"對戰開始輪到甲"} | ・**前置狀態** `{前置狀態}`（字串）：起點名稱，只限 對戰開始輪到甲 | 不支援 | 動作：只寫在 Background 或 Example 的第一句 Given。後端與 MySQL 已實際啟動；每個 Example 先 `POST /api/test/reset` 清空資料，依起點句上方的 `# 預設值：` 註解以 API 開房、加入、設定答案、準備與開始，再為甲、乙各開一個瀏覽器情境（各自保存玩家身份）開啟對戰畫面；其他狀態由 Example 的差異句推進<br>等待：兩個情境的 `game-board` 出現<br>保存：玩家名稱對應的瀏覽器情境與身份 → 給之後以玩家名稱操作或讀取畫面的步驟 |
| `伺服器在 {玩家} 送出新答案時沒有回應` | 伺服器在 {"甲"} 送出新答案時沒有回應 | ・**玩家** `{玩家}`（字串）：在誰的情境注入 | 不支援 | 注入故障：在該玩家的情境以 `page.route` 攔截 `POST /api/rooms/*/skills/change-answer`，不回應直到測試結束（擬定） |
| `{玩家} 在猜測欄輸入 {四碼}` | {"甲"} 在猜測欄輸入 {"5679"} | ・**玩家** `{玩家}`（字串）：在誰的情境操作<br>・**四碼** `{四碼}`（字串）：輸入的四碼 | 不支援 | 動作：在該玩家的情境於 `guess-input` 輸入四碼，不送出 |

## When 句型

| When 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `{玩家} 開啟改答案` | {"甲"} 開啟改答案 | ・**玩家** `{玩家}`（字串）：在誰的情境操作 | 不支援 | 動作：在該玩家的情境點 `skill-change-answer`<br>等待：該情境的 `change-answer-dialog` 出現 |
| `{玩家} 送出新答案 {四碼}` | {"甲"} 送出新答案 {"4567"} | ・**玩家** `{玩家}`（字串）：在誰的情境操作<br>・**四碼** `{四碼}`（字串）：新答案 | 不支援 | 動作：在該玩家的情境於 `change-answer-input` 輸入四碼並點 `change-answer-submit`<br>等待：該情境的 `change-answer-dialog` 關閉，或 `four-code-hint`、`connection-banner` 出現<br>保存：送出的新答案與送出前的答案 → 給「看不到…的新答案與舊答案」「四碼規則提示」「連線中斷提示」的查證斷言 |
| `{玩家} 取消改答案` | {"甲"} 取消改答案 | ・**玩家** `{玩家}`（字串）：在誰的情境操作 | 不支援 | 動作：在該玩家的情境點 `change-answer-cancel`<br>等待：該情境的 `change-answer-dialog` 關閉 |
| `{玩家} 猜 {四碼}` | {"甲"} 猜 {"5679"} | ・**玩家** `{玩家}`（字串）：在誰的情境操作<br>・**四碼** `{四碼}`（字串）：猜測的四碼 | 不支援 | 動作：在該玩家的情境於 `guess-input` 輸入四碼並點 `guess-submit`<br>等待：兩個情境的 `guess-log` 都多一列 |

## Then 句型

| Then 句型 | 範例 | 句型參數 | Data Table 參數 | 測試撰寫語意 |
|---|---|---|---|---|
| `{玩家} 的畫面顯示目前答案 {四碼}` | {"甲"} 的畫面顯示目前答案 {"4567"} | ・**玩家** `{玩家}`（字串）：讀誰的畫面<br>・**四碼** `{四碼}`（字串）：預期的答案 | 不支援 | 回應斷言：該玩家情境的 `current-answer` 文字等於四碼<br>查證斷言：<br>・再讀確認：以該玩家身份呼叫 `GET /api/rooms/current`，`my_answer` 等於四碼（擬定） |
| `雙方畫面顯示技能剩餘次數：` | 雙方畫面顯示技能剩餘次數： | （無） | ・**玩家**（字串，必填）：哪位玩家的次數<br>・**改答案**（整數，必填）：改答案剩餘次數<br>・**連猜三次**（整數，必填）：連猜三次剩餘次數 | 回應斷言：動作所在情境的 `skill-counter` 每位玩家兩個數字與表格相同<br>查證斷言：<br>・跨視角：另一個情境的 `skill-counter` 也與表格相同 |
| `{玩家} 的畫面看不到 {玩家} 的新答案與舊答案` | {"乙"} 的畫面看不到 {"甲"} 的新答案與舊答案 | ・**玩家** `{玩家}`（字串）：讀誰的畫面<br>・**玩家** `{玩家}`（字串）：被改答案的玩家 | 不支援 | 回應斷言：第一位玩家情境的整頁文字不包含第二位玩家保存的新答案與舊答案<br>查證斷言：<br>・不該發生：以第一位玩家身份呼叫 `GET /api/rooms/current`，整份回應文字也不包含這兩個答案（擬定） |
| `{玩家} 的畫面顯示 {玩家} 使用了 {技能} 的提示` | {"乙"} 的畫面顯示 {"甲"} 使用了 {"改答案"} 的提示 | ・**玩家** `{玩家}`（字串）：讀誰的畫面<br>・**玩家** `{玩家}`（字串）：使用技能的玩家<br>・**技能** `{技能}`（字串）：改答案或連猜三次 | 不支援 | 回應斷言：第一位玩家情境的 `skill-notice` 文字為第二位玩家使用該技能的提示，文案依 ui-contract.md<br>查證斷言：<br>・再讀確認：以第一位玩家身份呼叫 `GET /api/rooms/current`，`history` 最後一筆為第二位玩家使用該技能（擬定） |
| `雙方的猜測歷史依序為：` | 雙方的猜測歷史依序為： | （無） | ・**回合**（整數，必填）：回合數<br>・**玩家**（字串，必填）：誰的紀錄<br>・**紀錄**（字串，必填）：使用改答案，或「猜 四碼，xAyB」 | 回應斷言：動作所在情境的 `guess-log` 列數與表格相同，每列的回合、玩家與紀錄文字逐列相同<br>查證斷言：<br>・跨視角：另一個情境的 `guess-log` 也逐列相同 |
| `{玩家} 的畫面顯示四碼規則提示` | {"甲"} 的畫面顯示四碼規則提示 | ・**玩家** `{玩家}`（字串）：讀誰的畫面 | 不支援 | 回應斷言：該玩家情境的 `four-code-hint` 可見，文字依 ui-contract.md 的四碼規則提示<br>查證斷言：<br>・再讀確認：以該玩家身份呼叫 `GET /api/rooms/current`，`my_answer` 仍為送出前保存的答案（擬定） |
| `{玩家} 的畫面顯示連線中斷提示` | {"甲"} 的畫面顯示連線中斷提示 | ・**玩家** `{玩家}`（字串）：讀誰的畫面 | 不支援 | 回應斷言：該玩家情境的 `connection-banner` 可見，文字依 ui-contract.md 的連線中斷文案（擬定）<br>查證斷言：<br>・再讀確認：以該玩家身份呼叫 `GET /api/rooms/current`，`my_answer` 仍為送出前保存的答案（擬定） |
| `{玩家} 的猜測欄仍為 {四碼}` | {"甲"} 的猜測欄仍為 {"5679"} | ・**玩家** `{玩家}`（字串）：讀誰的畫面<br>・**四碼** `{四碼}`（字串）：預期的內容 | 不支援 | 回應斷言：該玩家情境的 `guess-input` 值等於四碼<br>查證斷言：無，因為猜測欄內容只存在該玩家的瀏覽器，不會送到後端或對手畫面 |

## Step 檔對照

每個句型歸屬一個模組與能力。Step 檔路徑相對於專案測試設定中本端點載入的 step 目錄；`shared` 只收不屬於任何模組領域的句型。

| 模組 | 能力 | Step 檔 | 句型 |
|---|---|---|---|
| shared | 系統狀態 | `shared/系統狀態.js` | `系統處於 {前置狀態}` |
| shared | 連線 | `shared/連線.js` | `伺服器在 {玩家} 送出新答案時沒有回應`<br>`{玩家} 的畫面顯示連線中斷提示` |
| 技能 | 改答案 | `modules/技能/改答案.js` | `{玩家} 開啟改答案`<br>`{玩家} 送出新答案 {四碼}`<br>`{玩家} 取消改答案`<br>`{玩家} 的畫面顯示目前答案 {四碼}`<br>`{玩家} 的畫面看不到 {玩家} 的新答案與舊答案`<br>`{玩家} 的畫面顯示 {玩家} 使用了 {技能} 的提示`<br>`{玩家} 的畫面顯示四碼規則提示` |
| 技能 | 次數 | `modules/技能/次數.js` | `雙方畫面顯示技能剩餘次數：` |
| 對戰 | 猜測 | `modules/對戰/猜測.js` | `{玩家} 在猜測欄輸入 {四碼}`<br>`{玩家} 猜 {四碼}`<br>`雙方的猜測歷史依序為：`<br>`{玩家} 的猜測欄仍為 {四碼}` |
