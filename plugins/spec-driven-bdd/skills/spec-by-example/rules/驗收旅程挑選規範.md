# 驗收旅程挑選規範

## Rule 1 -- 每個 Example 是一段完整旅程

**強度：MUST**

每個 Example 都是一段可以現場 Demo 的完整旅程，以多組 When／Then 依序串起操作與看到的結果；不得把同一段旅程拆成多個 Example，也不得把旅程縮成只驗單一規則的一組 When／Then。

### Good Example

這個範例在同一個 Example 走完拖放、看到新順序、重新開啟、確認順序保存。

```gherkin
    Example: AC-05 把 10 月 1 日相簿拖放到 10 月 3 日相簿之前後重新開啟應用程式
      When 把相簿 "2026年10月1日（星期四）" 拖放到相簿 "2026年10月3日（星期六）" 之前
      Then 主頁依序顯示下列相簿：
        | 相簿                    | 照片數 |
        | 2026年10月1日（星期四） | 5      |
        | 2026年10月3日（星期六） | 2      |
        | 2026年10月2日（星期五） | 3      |
      When 重新開啟應用程式
      Then 主頁依序顯示下列相簿：
        | 相簿                    | 照片數 |
        | 2026年10月1日（星期四） | 5      |
        | 2026年10月3日（星期六） | 2      |
        | 2026年10月2日（星期五） | 3      |
```

### Bad Example

這個範例把同一段旅程拆成兩個 Example，第二個重新從起點開始，「拖放後的順序能保存」這段串接從沒被驗到，PM 也看不到完整的 Demo 流程。

```gherkin
    Example: AC-05 把 10 月 1 日相簿拖放到 10 月 3 日相簿之前
      When 把相簿 "2026年10月1日（星期四）" 拖放到相簿 "2026年10月3日（星期六）" 之前

    Example: AC-06 重新開啟應用程式
      When 重新開啟應用程式
```

## Rule 2 -- 每份 feature 只挑 2 至 3 個關鍵旅程

**強度：MUST**

每份 feature 只放 2 至 3 個 Example：第一個是該功能最核心的主旅程，其餘是只改變部分資料或操作、會走到不同結果的變種旅程。挑選順序依「PM Demo 時不看就無法接受這個功能」的程度，不追求涵蓋每一條 FR、NFR 與每一個驗收情境。只有一段旅程會走到不同結果、又不是 Demo 必看的功能，不另開 feature，也不得把它的驗證併進其他功能的旅程，交由 dsl-refine 依 spec.md 補充。標 `@開發發現` 的 AC 不計入。以下 Example 皆對照相簿排序可寫的旅程：

```text
拖放後重新開啟（主流程）、拖到另一本相簿上再取消（相簿不會被放進另一本相簿）、
自訂順序後匯入新日期（新相簿位置）、只用鍵盤排序、拖曳時顯示放置提示
```

### Good Example

這個範例挑主流程與兩個會走到不同結果的變種，鍵盤排序與放置提示留給後續的測試計畫。

```text
AC-05 拖放後重新開啟（主旅程）
AC-06 拖到另一本相簿上再取消
AC-07 自訂順序後匯入新日期
```

### Bad Example

這個範例為了涵蓋每個驗收情境放了五個旅程，PM 無法快速看出哪些是 Demo 必看的流程，驗收標準退化成測試清單。

```text
AC-05 拖放後重新開啟
AC-06 拖到另一本相簿上再取消
AC-07 自訂順序後匯入新日期
AC-08 只用鍵盤排序
AC-09 拖曳時顯示放置提示
```

## Rule 3 -- Then 只寫 PM 看得到的結果

**強度：MUST**

Then 只寫 PM 在 Demo 現場看得到或能親手確認的結果，例如畫面內容、重新開啟後的狀態、裝置上的原始檔案；不得寫只能從系統內部確認的結果，例如請求次數、資料表內容、暫存區檔案。

### Good Example

這個範例以主頁照片數與裝置上的原始檔案確認刪除結果，PM 現場就能親眼核對。

```gherkin
      Then 主頁依序顯示下列相簿：
        | 相簿                    | 照片數 |
        | 2026年10月3日（星期六） | 2      |
        | 2026年10月2日（星期五） | 3      |
        | 2026年10月1日（星期四） | 4      |
      And 裝置上照片 "P3" 的原始檔案位置、檔名與內容皆未改變
```

### Bad Example

這個範例以系統收到的請求次數與資料表筆數作為結果，PM 在 Demo 現場看不到也無法確認，驗收標準變成只有工程師能判斷。

```gherkin
      Then 系統收到 1 次刪除照片的要求
      And 照片資料表少了 1 筆
```

## Rule 4 -- NFR 只列入 PM 能現場 Demo 看到的

**強度：MUST**

NFR 與 FR 一樣只挑關鍵的：只有 PM 在 Demo 現場用一般操作就能親眼觀察或親手確認的 NFR（例如幾秒內出現、操作進行中畫面不凍結、重新開啟後與關閉前一致、別人看不到），才寫進既有功能旅程的 Then 並列入涵蓋註解；需要大量資料、多人同時操作、量測工具或掃描才能確認的 NFR（容量、壓力、無障礙掃描、長時間穩定）不列入，也不為它另寫旅程或另開 feature。以下 Example 皆對照此 spec.md 的 NFR：

```text
NFR-001（效能）：匯入進行中，使用者必須仍可瀏覽主頁面與已完成的相簿，介面不得凍結
NFR-015（容量）：系統必須支援至多 10,000 張照片的照片庫
```

### Good Example

這個範例把 PM 現場就能看到的 NFR-001 寫進匯入主旅程的 Then 並列入涵蓋，需要準備一萬張照片才能確認的 NFR-015 不列入。

```gherkin
    # 涵蓋：US1、FR-001、FR-003、NFR-001
    Example: AC-01 首次使用時一次匯入三天共 10 張照片
      When 一次匯入下列照片：
        | 拍攝日期   | 照片               |
        | 2026-10-01 | P1、P2、P3、P4、P5 |
        | 2026-10-02 | Q1、Q2、Q3         |
      And 在匯入進行中開啟相簿 "2026年10月1日（星期四）"
      Then 相簿頁依序顯示照片 "P1、P2、P3、P4、P5"
```

### Bad Example

這個範例為容量 NFR 另寫一段旅程，PM Demo 時得先準備一萬張照片，也無法以肉眼判斷是否達標，驗收標準退化成壓力測試。

```gherkin
    # 涵蓋：NFR-015
    Example: AC-10 照片庫已有 10,000 張照片時開啟主頁
      When 開啟主頁
      Then 2.5 秒內顯示第一屏相簿
```

## Rule 5 -- 涵蓋註解只列旅程實際驗到的需求

**強度：MUST**

`# 涵蓋：` 只列這段旅程有 Then 以它為驗證對象的使用者故事、FR 與 NFR；Then 只驗到需求中的一部分條件時也列入，沒有驗到的條件交由 dsl-refine 依 spec.md 補充，不為它另寫旅程。不得把旅程只經過、沒有 Then 以它為驗證對象的需求列進來；SC 是量測指標，不列入。以下 Example 皆對照此旅程與需求：

```gherkin
    Example: AC-08 在相簿頁刪除 10 月 1 日相簿的 P3
      When 開啟相簿 "2026年10月1日（星期四）"
      And 在相簿頁刪除照片 "P3"
      Then 相簿頁依序顯示照片 "P1、P2、P4、P5"
      When 返回主頁
      Then 主頁依序顯示下列相簿：
        | 相簿                    | 照片數 |
        | 2026年10月3日（星期六） | 2      |
        | 2026年10月2日（星期五） | 3      |
        | 2026年10月1日（星期四） | 4      |
      And 裝置上照片 "P3" 的原始檔案位置、檔名與內容皆未改變
```

```text
FR-010：相簿頁面必須以大小一致的平鋪縮圖呈現照片，預設依拍攝時間由早到晚排序
FR-017：使用者必須能從應用程式刪除照片；刪除僅將照片自應用程式移除，不得刪除或修改裝置上的原始檔案
NFR-012：使用者自應用程式刪除照片後，應用程式保存的該照片副本與縮圖必須一併移除，且不再出現在任何畫面中
```

### Good Example

這個範例列出刪除與原始檔不動的 FR-017；Then 只驗到 NFR-012 中「不再出現在畫面中」的部分，仍列入 NFR-012，副本與縮圖的移除交由 dsl-refine 補充；開啟相簿只是為了刪除照片而經過的操作，不列入 FR-010。

```gherkin
    # 涵蓋：US4、FR-017、NFR-012
```

### Bad Example

這個範例把只經過的開啟相簿（FR-010）也列入，後續追溯時會誤以為平鋪縮圖的大小與排序已由這個旅程驗收，實際上沒有任何 Then 以它為驗證對象。

```gherkin
    # 涵蓋：US2、US4、FR-010、FR-017、NFR-012
```
