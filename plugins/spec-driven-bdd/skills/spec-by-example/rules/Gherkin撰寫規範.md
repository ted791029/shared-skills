# Gherkin 撰寫規範

## Rule 1 -- Rule 名稱描述整段旅程要成立的規則

**強度：MUST**

Rule 名稱寫成「…必須…」或「…不能…」，描述這段旅程整體要成立的業務規則，不拆成只描述旅程中單一步驟的原子規則；同一條規則在一份 feature 只開一個 Rule 區塊。

### Good Example

這個範例的 Rule 名稱涵蓋拖放到相簿上與取消兩段，兩段都在驗證「拖放只能改變順序」。

```gherkin
  Rule: 拖放相簿只能改變順序

    Example: AC-06 把 10 月 1 日相簿拖到 10 月 3 日相簿上，再拖曳 10 月 2 日相簿後取消
```

### Bad Example

這個範例把旅程中的一個步驟寫成 Rule，取消拖曳那一段不屬於這條規則，PM 從 Rule 名稱看不出整段旅程要驗收什麼。

```gherkin
  Rule: 相簿放到另一本相簿上時必須插在它之前

    Example: AC-06 把 10 月 1 日相簿拖到 10 月 3 日相簿上，再拖曳 10 月 2 日相簿後取消
```

## Rule 2 -- Example 標題只寫資料情境

**強度：MUST**

Example 標題在 `AC-NN` 之後只寫「在什麼狀態、用什麼資料、做了什麼」，不寫預期結果（成功、被拒絕、顯示…）。

### Good Example

這個範例的標題只寫狀態與操作，結果交給 Then。

```gherkin
    Example: AC-07 自訂順序為 10 月 1 日、3 日、2 日後，匯入 10 月 5 日與 10 月 2 日的照片
```

### Bad Example

這個範例的標題寫出結果，與 Rule 名稱幾乎同句，PM 從標題得不到資料資訊，再加一個變種時標題會幾乎一樣。

```gherkin
    Example: AC-07 新相簿排在最前面
```

## Rule 3 -- Given 只寫與起點不同的部分

**強度：MUST**

Example 的 Given 在起點句之後只寫與該 AC 的起點不同的部分，以使用者會做的動作句推進到旅程需要的狀態；沒有使用者動作能造成的系統或外部條件（例如資料暫時無法取得、連線中斷、時間經過、裝置的設定），以一句寫出這個條件本身的條件句推進，只寫 PM 看得懂的條件，不寫造成它的技術手段。不得重寫起點已有的內容，也不得自創一個狀態名稱代替多個差異或這類條件。

### Good Example

這個範例以一句拖放推進到自訂順序，再以一句條件句寫出沒有使用者動作能造成的「原始檔案暫時無法讀取」，PM 看得到這個狀態是怎麼來的。

```gherkin
      Given 把相簿 "2026年10月1日（星期四）" 拖放到相簿 "2026年10月3日（星期六）" 之前
      And 照片 "P2" 的原始檔案暫時無法讀取
```

### Bad Example

這個範例自創一個狀態代替自訂順序與讀不到的照片，PM 看不出自訂成什麼順序、是哪一張照片讀不到，後續斷言中的相簿順序與照片也無從核對；下游還得為它另建一個起點。

```gherkin
      Given 系統處於 "已自訂順序且 P2 無法讀取"
```

## Rule 4 -- 步驟只寫業務語意

**強度：MUST**

步驟、表格儲存格、Rule 名稱與 Example 標題只寫 PM 看得懂的業務語意，不得出現 API 路徑、HTTP 方法與狀態碼、資料表與欄位、畫面元素的選擇器或屬性、測試替身、請求與儲存機制等技術說法。

### Good Example

這個範例只寫使用者的操作與看到的結果。

```gherkin
      When 在相簿頁刪除照片 "P3"
      Then 相簿頁依序顯示照片 "P1、P2、P4、P5"
```

### Bad Example

這個範例寫出 API 與回應欄位，PM 讀不懂，系統分析前也還沒決定 API 長什麼樣子，驗收標準被提前綁在實作上。

```gherkin
      When 呼叫 DELETE /api/photos/P3
      Then 回應 200 且 photoCount 為 4
```

## Rule 5 -- 一句 When 只寫一個動作

**強度：MUST**

每句 When 只寫一個動作，同一段的後續動作用 And 接續；不得把多個動作塞進同一句。

### Good Example

這個範例把開始拖曳與按下取消鍵寫成兩句。

```gherkin
      When 開始拖曳相簿 "2026年10月2日（星期五）"
      And 按下取消鍵
```

### Bad Example

這個範例把兩個動作塞進一句，後續定義句子的測試語意時得為這種組合另訂一個只用一次的句型。

```gherkin
      When 開始拖曳相簿 "2026年10月2日（星期五）" 後按下取消鍵
```

## Rule 6 -- 字串參數加雙引號

**強度：MUST**

步驟中可替換的字串參數一律加雙引號，數字參數不加引號，固定的句型文字不加引號。

### Good Example

這個範例的日期與照片名稱加雙引號，張數不加。

```gherkin
      When 匯入拍攝於 "2026-10-05" 的照片 "S1"
      Then 相簿頁顯示 1 張照片
```

### Bad Example

這個範例的字串參數沒有加引號，句型無法分辨參數從哪裡開始，「2026-10-05 的照片 S1」可能被整段當成同一個參數。

```gherkin
      When 匯入拍攝於 2026-10-05 的照片 S1
```

## Rule 7 -- 多筆資料用 Data Table 或列表參數

**強度：MUST**

同一句型連續三行以上只差參數值時，合成一句帶 Data Table 的步驟；只有一欄、而且值是照片、玩家這類短名稱的序列時，寫成以「、」分隔的列表參數。

### Good Example

這個範例以表格列出相簿與照片數，單欄的照片順序寫成列表參數。

```gherkin
      Then 主頁依序顯示下列相簿：
        | 相簿                    | 照片數 |
        | 2026年10月3日（星期六） | 2      |
        | 2026年10月2日（星期五） | 3      |
        | 2026年10月1日（星期四） | 5      |
      When 開啟相簿 "2026年10月2日（星期五）"
      Then 相簿頁依序顯示照片 "Q1、Q2、Q3"
```

### Bad Example

這個範例把同一句型連寫三行，PM 要逐行比對才看得出是在檢查主頁的相簿順序。

```gherkin
      Then 主頁第 1 本相簿是 "2026年10月3日（星期六）"
      And 主頁第 2 本相簿是 "2026年10月2日（星期五）"
      And 主頁第 3 本相簿是 "2026年10月1日（星期四）"
```

## Rule 8 -- 影響閱讀的預設值必須註解

**強度：MUST**

步驟沒有寫出、但會影響讀者判斷結果的預設值，在受它影響的第一個步驟正上方加一行 `# 預設值：…`，只寫業務語意；影響整段旅程的預設值放在起點句之後的第一個步驟正上方，起點本身的內容則寫在起點句上方。不影響判斷的預設值不寫。

### Good Example

這個範例在需要它的斷言正上方註解匯入順序與拍攝時間相反，PM 讀到這個斷言時才看得懂為什麼要驗證平鋪的照片順序。

```gherkin
      When 開啟相簿 "2026年10月1日（星期四）"
      # 預設值：P1～P5 依拍攝時間先後命名，匯入順序為 P5 到 P1
      Then 相簿頁依序顯示照片 "P1、P2、P3、P4、P5"
```

### Bad Example

這個範例沒有註解匯入順序，PM 以為照片本來就依時間匯入，看不出這個斷言在確認「依拍攝時間而非匯入順序排列」。

```gherkin
      When 開啟相簿 "2026年10月1日（星期四）"
      Then 相簿頁依序顯示照片 "P1、P2、P3、P4、P5"
```

## Rule 9 -- 所有 feature 共用同一組句型

**強度：MUST**

同一份 spec 的所有驗收 feature，把參數換成型別後文字相同、而且意思完全相同的步驟，必須使用同一個句型；意思不同的步驟必須使用不同的固定文字，讓任何一句只符合一個句型。

### Good Example

這個範例在匯入照片與相簿排序兩份 feature 都以同一句型檢查主頁順序。

```gherkin
# 匯入照片.feature
      And 主頁依序顯示下列相簿：
# 相簿排序.feature
      Then 主頁依序顯示下列相簿：
```

### Bad Example

這個範例在兩份 feature 對同一個結果使用不同說法，後續定義句子的測試語意時要為同一件事定義兩個句型，PM 也會以為兩者在檢查不同的東西。

```gherkin
# 匯入照片.feature
      And 主頁依序顯示下列相簿：
# 相簿排序.feature
      Then 主頁的相簿順序如下：
```
