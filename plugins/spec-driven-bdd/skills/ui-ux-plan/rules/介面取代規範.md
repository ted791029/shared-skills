# 介面取代規範

## Rule 1 -- 最近一次的描述從最新的 plan 往前找

**強度：MUST**

讀取要修改或移除的介面在先前 plan 的描述時，先依介面列的名稱與括號中的元素認出是哪個畫面區塊與它的**定位**，再從編號最大的先前 plan 往前，在各 plan 的 `ui/ui-contract.md` 找出描述它的介面（**定位**相同，或「沿用」列指向它較早的描述），以及「共用約定」中寫到它的約定。同一部分以較新的描述為準：第一個找到的介面是最近一次的描述，它以「沿用」指向的部分再到被指向的描述讀取，較新 plan 的共用約定改過的部分以共用約定為準。不得只讀最早建立這個畫面的 plan，也不得依其他文件的引用（例如 dsl.md 寫的介面 ID）決定讀哪一份。本 plan 撰寫 MOD 的一節時，**定位**照抄被修改介面的定位，「沿用」列指向每個沿用部分最近一次的描述（可能分屬多個 plan），之後的 plan 才找得到它。以下 Example 皆對照此介面列與先前的 plan：

```text
005 的介面列：| UI-01 | 對戰畫面技能列（技能視窗的按鈕順序） | 前端 | MOD | FR-002 |
002 的 ui/ui-contract.md：UI-01 對戰畫面技能介面，定位 `[data-testid="skill-bar"]`，含改答案與連猜視窗的按鈕與視窗焦點規則
003 的 ui/ui-contract.md：沒有定位為 `skill-bar` 的介面；共用約定寫「002 UI-01～UI-03 對戰畫面：新增聊天區，寬度 768px 以上改為兩欄」
004 的 ui/ui-contract.md：UI-03 技能視窗焦點介面，定位 `[data-testid="skill-bar"]`，改了視窗焦點規則；「沿用」列寫「其餘操作與文案，見 002 的 UI-01」
specs/truth/features/frontend/dsl.md：寫「依 ui-contract.md 002/UI-01 的視窗焦點規則」
```

### Good Example

這個範例從 004 往前找：004 的 UI-03 定位相同，是最近一次的描述；被沿用的部分讀 002 的 UI-01，版面讀 003 的共用約定；005 的 MOD 沿用同一個定位，「沿用」列分別指向各部分最近一次的描述。

```text
最近一次的描述：004 的 UI-03
- 視窗焦點規則：讀 004 的 UI-03
- 版面：讀 003 的共用約定（兩欄，聊天區在右欄）
- 其餘操作與文案：依「沿用」讀 002 的 UI-01
005 的 UI-01（MOD）：定位 `[data-testid="skill-bar"]`；「沿用」列寫「視窗焦點規則見 004 的 UI-03；版面見 003 的共用約定；其餘操作與文案見 002 的 UI-01」
```

### Bad Example

這個範例依 dsl.md 的引用只讀 002 的 UI-01，005 的 MOD 以舊的視窗焦點規則與單欄版面為基準撰寫，004、003 改過、PM 核准過的焦點規則與版面被改回原樣。

```text
最近一次的描述：002 的 UI-01（dsl.md 引用 002/UI-01）
- 視窗焦點規則：讀 002 的 UI-01
- 其餘操作、文案與版面：讀 002 的 UI-01
```

## Rule 2 -- 以舊介面 ID 的各種寫法找出引用處

**強度：MUST**

介面列有 MOD 或 DEL 時，必須以被修改介面所在的 plan 與介面 ID 的各種寫法搜尋 `specs/truth/` 與本 plan 資料夾：「002/UI-01」「002 的 UI-01」「002 UI-01」、含它的範圍（例如「002 UI-01～UI-03」），以及只寫「002 ui-contract.md」「002 的 UI 契約」的引用。逐處判斷引用的是這次改變或移除的部分，還是沿用的部分：引用沿用部分的仍然有效，不處理；引用改變或移除部分的，在本 plan `ui/` 中的由本 skill 改指向本 plan 的介面，屬於其他擁有者的列出檔案、位置與擁有者，經 dev-finding 交給該擁有者。已交付 plan 的檔案不修改。以下 Example 皆對照此介面列與搜尋結果：

```text
004 的介面列：| UI-03 | 技能視窗焦點介面（開啟改答案與連猜視窗時的焦點） | 前端 | MOD | FR-004 |
這次改變：開啟改答案與連猜視窗時焦點所在的元素；其餘沿用 002 的 UI-01
搜尋結果：
- specs/truth/features/frontend/dsl.md:48：「等待：依 ui-contract.md 002/UI-01 的視窗焦點規則——改答案：…」
- specs/truth/features/frontend/dsl.md:105：「文字等於 ui-contract.md 002/UI-01「技能操作沒有成功」的文案」
- specs/truth/features/frontend/dsl.md:110：「說明文字為 002 ui-contract.md 的連猜視窗說明」
- specs/plans/003-room-chat/ui/ui-contract.md：「002 UI-01～UI-03 對戰畫面：新增聊天區…」
```

### Good Example

這個範例逐處判斷：只有引用改變部分的 dsl.md:48 交給它的擁有者，引用沿用部分的保留，已交付的 003 不修改。

```text
- dsl.md:48 引用改變的視窗焦點規則 → 屬於 dsl-refine，經 dev-finding 交給 dsl-refine 改指向 004 的 UI-03
- dsl.md:105、:110 引用沿用的文案 → 仍有效，不處理
- 003 的 ui-contract.md 是已交付的 plan → 不修改
```

### Bad Example

這個範例只以「002/UI-01」一種寫法搜尋，漏掉只寫「002 ui-contract.md」的引用，又直接改寫其他擁有者的 dsl.md；這個改動沒有經過 dsl-refine 與 truth-changes 的紀錄，用到這個句型的 Example 也不會重新驗證。

```text
以「002/UI-01」搜尋，找到 dsl.md:48、:105 → 直接把 dsl.md:48 改成「依 ui-contract.md 004/UI-03 的視窗焦點規則」
```
