# 資料模型拆檔規範

## Rule 1 -- 資料表依模組分檔，入口檔匯入每一個模組檔

**強度：MUST**

每張資料表必須定義在它所屬模組的模組檔 `<模組>.dbml`，模組沿用 truth 既有的模組名稱，既有模組都不適用時才新增。入口檔 `data-model.dbml` 只放 Project Note（含交易邊界表）與每個模組檔一行 `reuse * from './<模組>'`，不定義資料表。新增模組檔時必須在入口檔加上一行，刪除模組檔時移除那一行。

### Good Example

這個範例新增「標籤」模組：資料表寫在 `標籤.dbml`，入口檔多一行匯入。

```dbml
reuse * from './相簿'
reuse * from './照片'
reuse * from './標籤'
```

### Bad Example

這個範例把新的資料表直接寫進入口檔，入口檔同時有匯入與定義；下一次修改標籤的資料表時找不到它的模組檔，truth 異動紀錄也只能記成入口檔的修改。

```dbml
reuse * from './相簿'
reuse * from './照片'

Table photo_tags {
  photo_id char(36) [not null, note: '被標記的照片']
  tag varchar(32) [not null, note: '標籤文字']
}
```

## Rule 2 -- 只增修盤點列出的對象

**強度：MUST**

只能新增、修改、刪除盤點結果列出的資料表、欄位、索引、關聯與交易邊界表的列。修改既有的資料表時在它原本的模組檔修改，同一個檔案的其他資料表與沒有列出的檔案一字不改，不得重排欄位、改寫 note 或調整格式；刪除資料表時連同指向它的 `Ref` 與其他模組檔對它的 `use` 一併刪除。Note 只寫修改後的現況，不寫「原為」「這次新增」等變更過程。以下 Example 皆對照此盤點結果與既有資料模型：

```text
盤點結果：
| MOD | `data/照片.dbml` ＞ Table `photos` | 新增欄位 `tag_count` | FR-021 |
既有資料模型：照片.dbml 定義 photos，有 7 個欄位
```

### Good Example

這個範例在 photos 原本的位置加上一個欄位，note 只寫欄位的意義，其他欄位與資料表都沒有異動。

```dbml
  has_thumbnail tinyint [not null, default: 0, note: '1 表示已有縮圖檔']
  tag_count int [not null, default: 0, note: '這張照片的標籤數']
  created_at datetime [not null, default: `CURRENT_TIMESTAMP`, note: '匯入完成時間']
```

### Bad Example

這個範例把變更過程寫進 note，又順手改寫了盤點沒有列出的 has_thumbnail 的 note；資料模型不再只描述現況，truth 異動紀錄也多出一筆沒有原因的修改。

```dbml
  has_thumbnail tinyint [not null, default: 0, note: '是否已產生縮圖檔（1 為是）']
  tag_count int [not null, default: 0, note: '004 新增；這張照片的標籤數，原本沒有此欄位']
  created_at datetime [not null, default: `CURRENT_TIMESTAMP`, note: '匯入完成時間']
```

## Rule 3 -- 工具產生的檔案不是資料模型

**強度：MUST**

資料模型只由入口檔 `data-model.dbml` 與模組檔 `<模組>.dbml` 組成，data-plan 只增修這兩種檔案。`specs/truth/data/` 中 DBML 檢視工具產生的檔案（例如 dbdiagram 的檢視設定 `data-model.dbdiagram`，只記錄深色模式、格線與資料表在畫面上的位置）不是規格：不得建立、修改、刪除或重新產生，不讀取它判斷資料模型，也不列入盤點與 `truth-changes.md`（核對異動時由 `specs/truth/.truthignore` 排除）。以下 Example 皆對照此盤點結果與資料夾：

```text
盤點結果：| MOD | `data/聊天.dbml` ＞ Table `chat_messages` | 新增欄位 `pinned` | FR-002 |
specs/truth/data/：data-model.dbml、房間.dbml、對戰.dbml、技能.dbml、聊天.dbml、data-model.dbdiagram
```

### Good Example

這個範例只修改盤點列出的模組檔，檢視設定檔維持原樣，也沒有出現在異動紀錄。

```text
修改 聊天.dbml：Table chat_messages 新增欄位 pinned
data-model.dbdiagram：工具的檢視設定，不是資料模型，不處理
```

### Bad Example

這個範例以為檢視設定要跟著資料模型重新產生，在裡面加上資料表的位置；這個檔案不是規格、核對也不會檢查它，改了卻讓人以為它是 data-plan 要維護的產出，之後每次增修資料模型都多一份沒有人能驗證的檔案要同步。

```text
修改 聊天.dbml：Table chat_messages 新增欄位 pinned
重新產生 data-model.dbdiagram：tablePositions 加上 chat_messages 的座標
```
