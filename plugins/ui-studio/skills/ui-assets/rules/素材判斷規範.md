# 素材判斷規範

## Rule 1 -- 依參數決定範圍與位置

**強度：MUST**

範圍、位置與可否詢問依呼叫者的參數決定；沒有參數時使用預設：

| 參數 | 沒有指定時 |
|---|---|
| 範圍 | 選定來源與取得素材都做 |
| 素材位置 | 專案根目錄的 `design/assets/` |
| 素材清單位置 | 專案根目錄的 `design/素材清單.md` |
| DESIGN.md 位置 | 專案根目錄的 `DESIGN.md` |
| 可否詢問 | 可以詢問 |

範圍只有取得素材而 DESIGN.md 沒有素材節時，先執行選定來源，再取得素材，並在回報中寫明這次另外選定了來源。

### Good Example

這個範例在沒有參數時依預設兩個範圍都做，並把檔案寫到預設位置。

```text
使用者：「首頁缺圖、圖示都是 emoji。」
參數：無 → 範圍：選定來源與取得素材；素材位置 design/assets/；素材清單 design/素材清單.md
```

### Bad Example

這個範例沒有參數時自行把素材寫進前端專案的 public/，等於修改了專案內容，也讓素材清單不知道放哪裡。

```text
使用者：「首頁缺圖、圖示都是 emoji。」
參數：無 → 把下載的圖示放進 public/icons/，直接替換 Home.tsx 中的 emoji
```

## Rule 2 -- 先找出專案已用的圖示套件

**強度：MUST**

選定或取得圖示前，必須先讀專案的相依清單（例如 package.json）與原始碼的 import，找出已經安裝或使用的圖示套件，以及 DESIGN.md 素材節記錄的圖示庫。已有時沿用，不得另選一套。

### Good Example

這個範例發現專案已在用 lucide-react，沿用而不另選。

```text
package.json：lucide-react 0.4xx；src/components/Nav.tsx：import { Menu } from 'lucide-react'
→ 圖示庫沿用 Lucide
```

### Bad Example

這個範例沒有查專案已用的套件就另選 Phosphor，同一個產品出現兩套線條粗細與風格不同的圖示。

```text
選定圖示庫：Phosphor（MIT）
```

## Rule 3 -- 區分真實照片與示意素材

**強度：MUST**

每個需要圖片的位置都必須判斷它是「必須是真實產品、人物或場所的照片」，還是「示意素材」。真實照片包括：產品實拍、店面與場所、團隊成員、客戶案例、作品集。真實照片只能使用使用者提供的檔案，不得以圖庫照片或生成圖片代替。

### Good Example

這個範例把診所的環境照片判為真實照片，只有說明保健觀念的區塊用示意插圖。

```text
首頁 hero：診所候診區 → 真實照片，請使用者提供
團隊介紹：三位醫師的照片 → 真實照片，請使用者提供
「如何預防流感」區塊 → 示意素材，可用插圖
```

### Bad Example

這個範例用圖庫的醫師照片代替真實的醫師，訪客會把模特兒當成這間診所的醫師，構成不實的呈現。

```text
團隊介紹：三位醫師 → 從 Unsplash 取三張穿白袍的照片
```

## Rule 4 -- 找出 emoji 與缺圖的位置

**強度：MUST**

必須逐一找出原型與正式畫面中以 emoji、文字符號或字元畫代替圖示的位置，以及版面預留了圖片卻沒有圖片、或內容需要圖片才能理解卻沒有圖片的位置。每個位置都寫出檔案、元件或選擇器，以及現況。

### Good Example

這個範例找出每個 emoji 圖示與缺圖位置，並寫出確切的位置。

```text
src/components/Nav.tsx:14 選單按鈕用「☰」
src/pages/Home.tsx:31 三個特色區塊用「🚀」「🔒」「⚡」當圖示
src/pages/Home.tsx:8 hero 預留 <div class="hero-image"> 但沒有圖片
```

### Bad Example

這個範例只寫「首頁有很多 emoji」，實作時要自己再找一次，也無法確認是否全部替換。

```text
首頁有很多 emoji 和缺圖，需要換成正式素材。
```
