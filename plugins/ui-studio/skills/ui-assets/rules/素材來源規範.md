# 素材來源規範

## Rule 1 -- 只選允許商用的來源

**強度：MUST**

選定的來源必須允許商用，並記下授權名稱與署名要求。可以選用的例子如下（使用前必須到來源確認目前的授權條款）：

| 類別 | 來源例子 | 授權 |
|---|---|---|
| 圖示 | Lucide、Phosphor、Heroicons、Tabler Icons、Material Symbols | ISC、MIT、MIT、MIT、Apache-2.0 |
| 插圖 | Open Peeps | CC0 |
| 照片 | Unsplash、Pexels | 各自的授權（允許商用，不得原樣販售） |
| 照片 | Wikimedia Commons | 逐檔不同，必須逐檔確認並依授權署名 |

授權不明、只限個人使用或禁止商用的來源不得選用。

### Good Example

這個範例選定允許商用的來源，並寫下署名要求。

```text
圖示：Phosphor 2.1（MIT），不需在畫面署名，授權全文附在素材清單
照片：Wikimedia Commons，逐檔確認；CC BY-SA 4.0 的照片需在圖說署名作者與授權
```

### Bad Example

這個範例選用從搜尋引擎找到的圖片，授權不明，產品上線後可能被要求下架或賠償。

```text
照片來源：Google 圖片搜尋「診所」的結果
```

## Rule 2 -- 一個專案只用一套圖示庫

**強度：MUST**

一個專案只能選用一套圖示庫，並固定一種線條風格（例如 Regular、1.5px 線條）；需要的圖示在選定的圖示庫找不到時，選語意最接近的圖示，並在回報中列出，不得混用另一套圖示庫。

### Good Example

這個範例在選定的圖示庫找不到「掛號」圖示時，以語意接近的圖示代替並列出。

```text
Phosphor 沒有「掛號」→ 使用 ClipboardText，回報：掛號以 ClipboardText 表示
```

### Bad Example

這個範例為了一個找不到的圖示另外引入 Material Symbols，畫面上同時出現兩種粗細與圓角不同的圖示。

```text
Phosphor 沒有「掛號」→ 這一個改用 Material Symbols 的 assignment
```

## Rule 3 -- 插圖與照片風格依視覺方向

**強度：SHOULD**

插圖風格與照片的取景、色調應依 DESIGN.md 的整體方向選擇，並在素材節寫出一句可判斷的描述；視覺方向不需要插圖或照片時，寫明「不使用」，不得為了填滿版面加入裝飾性的素材。

### Good Example

這個範例依「社區診所的櫃台」方向寫出可判斷的照片風格，並決定不使用插圖。

```text
照片：自然光、暖色調、真實的候診區與櫃台，不用擺拍的醫師特寫
插圖：不使用
```

### Bad Example

這個範例只寫「好看的照片」，無法判斷哪些照片符合，也為裝飾加入與方向無關的 3D 插圖。

```text
照片：好看、專業的照片
插圖：3D 風格的可愛角色，放在每個區塊
```

## Rule 4 -- 選定的來源寫進 DESIGN.md 的素材節

**強度：MUST**

使用者直接使用且 DESIGN.md 存在時，把選定的來源寫進 DESIGN.md 的「素材」節，只改這一節，不得改動其他節；DESIGN.md 不存在時不另建，只回報選定的來源並建議先以 ui-design 建立設計系統。被呼叫時不寫 DESIGN.md，改為回報選定的來源，由呼叫者寫入。

### Good Example

這個範例被 ui-design 呼叫，只回報選定的來源，由 ui-design 寫進 DESIGN.md。

```text
回報：圖示庫 Lucide 0.4（ISC），沿用已安裝的 lucide-react；插圖：不使用；照片：診所實景由使用者提供，示意照片取自 Unsplash
```

### Bad Example

這個範例被呼叫時自己改寫了 DESIGN.md，還順手調整了色彩節，在 SDD 流程中繞過了 truth 異動的盤點與紀錄。

```text
已更新 specs/truth/ui/DESIGN.md：新增素材節，並把 --color-accent 改得更亮以配合圖示
```
