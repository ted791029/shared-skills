# 素材取得規範

## Rule 1 -- 只寫入素材位置

**強度：MUST**

素材只能寫入素材位置與素材清單，不得修改專案的程式碼、樣式、設定與相依套件，也不得安裝圖示套件。正式畫面要替換的地方列在素材清單，由實作流程替換；原型由呼叫者引用素材。

### Good Example

這個範例把圖示存到素材位置，正式畫面的替換列進素材清單。

```text
寫入 design/assets/icons/menu.svg
素材清單「要替換的位置」：src/components/Nav.tsx:14 的「☰」→ menu.svg
```

### Bad Example

這個範例直接安裝套件並改寫元件，素材的取得變成了程式碼修改，繞過了實作流程。

```text
npm install @phosphor-icons/react；把 Nav.tsx 的「☰」改成 <List />
```

## Rule 2 -- 圖示只取自官方來源

**強度：MUST**

圖示的 SVG 只能取自選定圖示庫的官方套件或原始碼庫，不得憑記憶繪製或修改路徑後仍標為該圖示庫。專案已安裝該圖示套件時，不下載 SVG，在素材清單寫出要使用的元件名稱。

### Good Example

這個範例的專案已安裝 lucide-react，只在素材清單寫出元件名稱。

```text
專案已安裝 lucide-react → 素材清單：選單按鈕使用 <Menu />（lucide-react），不下載 SVG
```

### Bad Example

這個範例憑印象畫出一個選單圖示並標為 Phosphor，線條粗細與官方不同，授權紀錄也與實際內容不符。

```html
<!-- Phosphor List -->
<svg viewBox="0 0 24 24"><path d="M3 6h18M3 12h18M3 18h18" stroke="currentColor"/></svg>
```

## Rule 3 -- 生成素材必須標示

**強度：MUST**

環境有生圖工具時，才可以生成示意的插圖或照片，並在檔名與素材清單標示為生成、記下使用的工具與提示文字；沒有生圖工具時改用選定的開源來源。真實照片不得生成。

### Good Example

這個範例在有生圖工具時生成示意插圖，並完整標示。

```text
design/assets/illustrations/flu-prevention.generated.png
素材清單：來源「生成」，工具：<生圖工具名稱>，提示：「flat illustration of washing hands, warm palette」
```

### Bad Example

這個範例生成了看起來像實拍的診所照片且沒有標示，訪客會誤以為是這間診所的實景。

```text
design/assets/photos/clinic-lobby.png（生成，未標示）
```

## Rule 4 -- 拿不到素材時用標示清楚的佔位圖

**強度：MUST**

真實照片，或其他來源都拿不到的素材，必須放上標示清楚的佔位圖：畫面上看得出是佔位（例如灰底加上「待提供：候診區照片」與尺寸），檔名以 `placeholder-` 開頭，並列入素材清單與回報，請使用者提供。

### Good Example

這個範例為真實照片放上可辨識的佔位圖，並在回報中列出要使用者提供的檔案。

```text
design/assets/photos/placeholder-clinic-lobby.svg（灰底，文字「待提供：候診區照片 1600×900」）
回報：請提供候診區照片一張，建議 1600×900 以上
```

### Bad Example

這個範例用一張外觀完整的圖庫照片暫代，上線前沒有人發現要換，別家診所的照片就出現在正式網站上。

```text
design/assets/photos/clinic-lobby.jpg（Unsplash 的診所照片，暫代）
```

## Rule 5 -- 每個圖片附替代文字與顯示尺寸

**強度：MUST**

每個圖片素材都必須在素材清單寫出建議的替代文字（純裝飾時寫「裝飾，alt 留空」）與預計的顯示尺寸；照片另寫出需要的最大寬度，供實作流程產生對應尺寸的檔案。

### Good Example

這個範例寫出替代文字與顯示尺寸，裝飾圖明確標示 alt 留空。

```text
hero.jpg：alt「明亮的候診區，櫃台旁有兒童閱讀角」；顯示寬度 100vw，最大 1600px
divider-wave.svg：裝飾，alt 留空；高度 24px
```

### Bad Example

這個範例沒有寫替代文字與尺寸，實作時只能把檔名當 alt，並把原始的大圖直接塞進手機畫面。

```text
hero.jpg、divider-wave.svg
```

## Rule 6 -- 完成前檢查授權與遺漏

**強度：MUST**

完成前必須逐項確認：每個素材都有來源與授權紀錄、需要署名的已寫出署名方式、佔位圖與生成素材都已標示、找出的 emoji 與缺圖位置都已對應到素材或佔位圖。有遺漏時補齊後才回報。

### Good Example

這個範例逐項確認後發現一張 CC BY 照片缺署名，補上後才回報。

```text
檢查：8 個素材都有授權紀錄；pharmacy.jpg 為 CC BY 4.0，缺署名 → 補上「攝影：Jane Doe，CC BY 4.0」
emoji 位置 3 處、缺圖 2 處，皆已對應
```

### Bad Example

這個範例沒有檢查就回報完成，一張需要署名的照片沒有署名，正式上線後違反授權條款。

```text
素材已全部取得，共 8 個。
```
