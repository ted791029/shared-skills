# 配色規範

## Rule 1 -- 只調整配色

**強度：MUST**

單項改善配色時，只能修改顏色、色彩 token 與明暗主題。字型、版面結構與文案維持原樣，除非使用者明確要求一併修改。已確認的品牌色與語意色（成功、警告、錯誤）必須保留，不得藉著調整配色把整個視覺風格換掉。

### Good Example

這個範例保留原有品牌主色，只補上缺少的表面與次要文字角色。

```css
:root {
  --color-brand: oklch(55% 0.16 250); /* 原有品牌色，保留 */
  --color-surface-raised: oklch(98% 0.005 250);
  --color-text-secondary: oklch(45% 0.02 250);
}
```

### Bad Example

這個範例把品牌藍換成紫色，還順手改了標題字級，使用者只要求讓畫面顏色更有層次，結果品牌辨識被破壞、版面也跟著變動。

```css
:root { --color-brand: oklch(55% 0.2 300); }
h1 { font-size: 3rem; }
```

## Rule 2 -- 品牌色缺少時白話詢問

**強度：MUST**

DESIGN.md、既有 token 與程式碼都看不出品牌色，且畫面需要品牌色時，必須以白話詢問使用者是否有既定的品牌顏色，不得自行假設。提問避免色彩術語，並提供「沒有，交給你決定」的選項；使用者選擇交給 Claude 時，由 Claude 依產品性質決定。

### Good Example

這個範例用白話詢問品牌顏色，並讓使用者可以把決定交給 Claude。

```text
在調整顏色之前想先確認一件事：你們有沒有固定使用的品牌顏色？例如 logo、名片或官網上的代表色。
1. 有，我提供顏色（貼上色碼或圖片都可以）
2. 沒有，交給你依產品性質決定
```

### Bad Example

這個範例在不知道品牌色的情況下直接自訂一個主色，若使用者其實有既定品牌色，整套配色都要重做。

```text
我已經幫你把主色設定為綠色 #2E7D32，並套用到所有按鈕與連結。
```

## Rule 3 -- 以角色建立色彩 token

**強度：MUST**

顏色必須依角色定義成語意 token，至少涵蓋：底色與浮起表面、主要與次要文字、動作／焦點／選取、邊框與分隔線、成功／警告／錯誤／資訊；有圖表時再加資料分類或色階。元件只引用語意 token，切換主題時只重新對應語意 token。

### Good Example

這個範例先定義原始色值，再由語意 token 引用，元件只使用語意 token。

```css
:root {
  --blue-600: oklch(52% 0.17 255);
  --color-action: var(--blue-600);
  --color-focus: var(--blue-600);
  --color-text-primary: oklch(22% 0.02 255);
  --color-danger: oklch(55% 0.2 25);
}
.btn-primary { background: var(--color-action); }
```

### Bad Example

這個範例在各元件直接寫死色碼，同一個藍色散落在數十處，之後換主題或調整品牌色時必須逐一搜尋替換，必然漏改。

```css
.btn-primary { background: #1d4ed8; }
.link { color: #1d4ed8; }
.tab--active { border-color: #1e40af; }
```

## Rule 4 -- 新色盤使用 oklch

**強度：SHOULD**

沿用專案既有的色彩表示法。建立新的網頁色盤時使用 `oklch()`，色階以明度變化為主，越接近白色或黑色時調低彩度，不得在極亮或極暗處維持高彩度。需要穩定對比時使用不透明的實色，不以多層半透明疊色組成顏色。

### Good Example

這個範例的色階在兩端調低彩度，中段保留最高彩度。

```css
:root {
  --brand-50:  oklch(97% 0.02 250);
  --brand-500: oklch(58% 0.16 250);
  --brand-900: oklch(25% 0.06 250);
}
```

### Bad Example

這個範例在最淺與最深的色階都維持 0.16 的高彩度，淺色變得刺眼、深色則超出螢幕能顯示的範圍而失真。

```css
:root {
  --brand-50:  oklch(97% 0.16 250);
  --brand-900: oklch(25% 0.16 250);
}
```

## Rule 5 -- 色相依產品意義選擇

**強度：SHOULD**

主色的色相依產品的意義與視覺方向決定，不套用產業刻板印象（例如金融一律藍色、環保一律綠色），也不沿用框架的預設色。

### Good Example

這個範例為主打溫暖手作感的烘焙訂購服務選用帶紅的暖橙色，並註明理由。

```css
:root {
  /* 呼應烤色與手作溫度 */
  --color-brand: oklch(62% 0.15 45);
}
```

### Bad Example

這個範例直接使用框架預設的藍紫色當主色，畫面看起來和無數範本一樣，沒有產品自己的辨識度。

```css
:root { --color-brand: #6366f1; }
```

## Rule 6 -- 主要動作色不用於裝飾

**強度：MUST**

主要動作（主按鈕、主要連結）的顏色只能用在可操作的元素與焦點上，不得拿來塗裝飾線、背景圖形或一般標題。最強烈的顏色要集中承擔一個明確的區域或角色，不零散地灑在各處小點綴上。

### Good Example

這個範例只讓主按鈕與焦點框使用動作色，裝飾元素改用中性色。

```css
.btn-primary { background: var(--color-action); }
:focus-visible { outline: 2px solid var(--color-focus); }
.section-divider { border-color: var(--color-border); }
```

### Bad Example

這個範例把動作色同時用在標題、分隔線與圖示背景，使用者找不到真正可以按的按鈕。

```css
h2, .section-divider, .icon-bg { color: var(--color-action); border-color: var(--color-action); }
```

## Rule 7 -- 彩色底上的次要文字不用灰色

**強度：MUST**

有色背景上的次要文字，必須取該背景色相的較深或較淺色，或由前景色調出，不得使用一般灰色，也不得用 `opacity` 或半透明色調淡文字。

### Good Example

這個範例在藍色區塊上以同色相的淺藍作為次要文字。

```css
.promo { background: oklch(45% 0.14 255); color: oklch(98% 0.01 255); }
.promo .meta { color: oklch(85% 0.05 255); }
```

### Bad Example

這個範例在藍色區塊上使用灰色並調低透明度，文字顯得髒污，對比也隨背景變動而無法掌握。

```css
.promo .meta { color: #9ca3af; opacity: 0.7; }
```

## Rule 8 -- 對比達到 WCAG AA 門檻

**強度：MUST**

一般文字與背景的對比至少 4.5:1；大字（18.66px 粗體或 24px 以上）、控制元件、圖示與焦點框至少 3:1。門檻適用於所有狀態（hover、停用、錯誤）、浮層、圖片上的文字，以及淺色與深色兩種主題。

### Good Example

這個範例為停用按鈕另外設定仍可辨識的文字色，而不是直接降低整體透明度。

```css
.btn:disabled {
  background: oklch(92% 0.01 255);
  color: oklch(48% 0.02 255);
}
```

### Bad Example

這個範例的佔位文字用很淺的灰色，在白底上幾乎看不見，視力較弱的使用者讀不到提示。

```css
input::placeholder { color: #d1d5db; }
```

## Rule 9 -- 不只靠顏色傳達資訊

**強度：MUST**

狀態、錯誤、圖表分類等用顏色表達的資訊，必須同時有文字、圖示、形狀、圖樣或位置等非顏色線索。

### Good Example

這個範例的錯誤欄位除了紅框，還有圖示與文字說明。

```html
<input aria-invalid="true" aria-describedby="email-err" class="input input--error" />
<p id="email-err" class="field-error"><svg aria-hidden="true">…</svg>電子郵件格式不正確</p>
```

### Bad Example

這個範例只把欄位邊框變紅，色弱使用者看不出哪個欄位出錯，也不知道錯在哪裡。

```html
<input class="input" style="border-color: red" />
```

## Rule 10 -- 深色主題獨立設計

**強度：MUST**

深色主題必須另外定義表面的層次（越浮起越亮）與對比，不得用 `filter: invert()` 或把淺色主題的明度直接反轉。

### Good Example

這個範例為深色主題重新對應表面與文字 token，浮起的表面比底色亮。

```css
[data-theme="dark"] {
  --color-canvas: oklch(18% 0.01 255);
  --color-surface-raised: oklch(24% 0.012 255);
  --color-text-primary: oklch(94% 0.01 255);
}
```

### Bad Example

這個範例以反轉濾鏡產生深色模式，照片與品牌色全部變成負片，陰影也變成發光。

```css
[data-theme="dark"] body { filter: invert(1) hue-rotate(180deg); }
```

## Rule 11 -- 避免漸層文字

**強度：SHOULD**

預設不使用漸層填色的文字（`background-clip: text`），強調改用字重或字級，除非使用者需求明確要求。

### Good Example

這個範例以字重與實色強調關鍵字。

```css
.headline strong { font-weight: 800; color: var(--color-brand); }
```

### Bad Example

這個範例把標題做成漸層文字，看起來像大量生成的範本，漸層淺色段的對比也可能不足。

```css
.headline {
  background: linear-gradient(90deg, #6366f1, #ec4899);
  -webkit-background-clip: text;
  color: transparent;
}
```
