# 設計系統規範

## Rule 1 -- 記錄的值必須有程式碼依據

**強度：MUST**

DESIGN.md 中的每個色彩、字體、尺寸、圓角、間距、陰影值都必須能在程式碼中找到對應：

- 既有專案：從程式碼萃取，來源依序為 CSS custom properties（`--color-*`、`--font-*`、`--spacing-*`、`--radius-*`、`--shadow-*`、`--ease-*`、`--duration-*`）、Tailwind 設定的 `theme.extend`、CSS-in-JS 的 theme 檔、token 檔（如 `tokens.json`）、主要元件（按鈕、卡片、輸入框、導覽、對話框）的預設樣式、全域樣式表。
- 新畫面：記錄這次決定並已寫入原型或修改規格的確切值，寫成可直接放進程式碼的值。

不得寫入憑印象估計，或從未出現在程式碼、原型與修改規格中的值。

### Good Example

這個範例的值都可在既有 CSS 中找到對應，並保留原始值。

```markdown
- **深夜藍**（#1e2a44）：頁首與主要按鈕底色，來自 `--color-primary`。
- **標準圓角**（8px）：卡片與輸入框，來自 `--radius-md`。
```

### Bad Example

這個範例寫入的 #2b3a55 與 12px 在程式碼中都找不到，照 DESIGN.md 做出的新畫面會和既有頁面對不上。

```markdown
- **深夜藍**（#2b3a55）：主要品牌色。
- **標準圓角**（12px）：所有容器。
```

## Rule 2 -- 不得記錄未實作的意圖

**強度：MUST**

DESIGN.md 只記錄已存在，或這次已寫入原型或修改規格的內容。不得記錄專案沒有的元件、沒有用到的 token 層級（例如只有一個強調色時不得補出次要色與第三色）、空的尺度級距，或「未來希望」「應該要」這類沒有實作的規則。不相關的段落直接省略，不填入臆造的內容。

### Good Example

這個範例的專案只有一個強調色與按鈕、卡片兩種元件，就只記錄這些。

```markdown
### Primary
- **珊瑚橘**（#e8613c）：主要按鈕與連結。

### Neutral
- **紙白**（#fbfaf7）：頁面底色。
- **墨黑**（#1c1b19）：內文。
```

### Bad Example

這個範例為只有一個強調色的專案補出次要色，並記錄程式碼中不存在的 Chip 元件，後續做畫面的 agent 會照著使用不存在的值與元件。

```markdown
### Secondary
- **海灣藍**（#2f6f9f）：次要操作（規劃中）。

### Chips
- 標籤使用膠囊形、淺色底。
```

## Rule 3 -- 保留專案既有的取值格式

**強度：MUST**

色彩值必須沿用專案原始定義使用的格式：程式碼用 `oklch()`、`hsl()`、`rgb()` 或廣色域值，DESIGN.md 就照原格式記錄；只有在專案本身用 hex 或沒有既有定義時才用 hex。不得把原始值換算成另一種格式後當作正式值。

### Good Example

這個範例照程式碼原本的 `oklch()` 格式記錄。

```markdown
- **洋紅**（oklch(60% 0.25 350)）：強調色，來自 `--color-accent`。
```

### Bad Example

這個範例把程式碼中的 `oklch(60% 0.25 350)` 換算成近似的 hex，DESIGN.md 與程式碼出現兩個不完全相同的值，之後不知道哪個才是正確的。

```markdown
- **洋紅**（#d6247f）：強調色。
```

## Rule 4 -- 同一 token 只有一個值

**強度：MUST**

每個 token 在 DESIGN.md 中只能有一個值。同一個 token 在不同段落提到時，只能引用名稱或重複同一個值，不得在說明文字中寫出另一個不同的值。

### Good Example

這個範例在元件段落引用色彩段落已定義的 token 名稱，沒有另寫值。

```markdown
## Colors
- **森林綠**（#2f5d46）：`primary`，主要按鈕。

## Components
### Buttons
- **Primary：** 底色使用 `primary`（森林綠），白字。
```

### Bad Example

這個範例在元件段落把同一個主色寫成另一個值，實作時有兩個來源可選，畫面上的主色會不一致。

```markdown
## Colors
- **森林綠**（#2f5d46）：`primary`，主要按鈕。

## Components
### Buttons
- **Primary：** 底色 #355f4a。
```

## Rule 5 -- token 命名沿用專案慣例

**強度：MUST**

token 名稱必須沿用專案已使用的名稱與級距命名（例如 `oxblood-deep`、`surface-container-low`、`sm`／`md`／`lg` 或數字級距），不得改名成其他框架的預設名稱。專案沒有既有名稱時，以用途或描述命名（如 `surface-raised`、`text-muted`、`brand-coral`），不得以色階編號命名（如 `blue-800`、`gray-3`）。

### Good Example

這個範例沿用專案原本的 `surface-container-*` 命名。

```css
:root {
  --surface-container-low: #f4f1ec;
  --surface-container-high: #e7e2da;
}
```

### Bad Example

這個範例把專案原有的 `surface-container-low` 改成色階編號，程式碼與 DESIGN.md 的名稱對不起來，也看不出每個值的用途。

```css
:root {
  --gray-100: #f4f1ec;
  --gray-300: #e7e2da;
}
```

## Rule 6 -- 元件 token 引用基礎 token

**強度：MUST**

token 分兩層：基礎 token 存放實際的值（色彩、尺寸、圓角），元件或語意 token 引用基礎 token。基礎 token 之間不得互相引用；元件 token 應引用基礎 token，不直接寫死值。

### Good Example

這個範例的基礎 token 只放值，按鈕 token 引用基礎 token。

```css
:root {
  --color-forest: #2f5d46;
  --color-paper: #fbfaf7;
  --radius-sm: 4px;

  --button-primary-bg: var(--color-forest);
  --button-primary-text: var(--color-paper);
  --button-primary-radius: var(--radius-sm);
}
```

### Bad Example

這個範例讓基礎 token 互相引用，按鈕 token 又寫死值，改一個基礎色會連帶改到不相關的 token，按鈕卻不會跟著改。

```css
:root {
  --color-forest: #2f5d46;
  --color-border: var(--color-forest);
  --button-primary-bg: #2f5d46;
}
```

## Rule 7 -- 重複三次且用途相同才抽出

**強度：MUST**

寫死的值或相似的介面片段，只有在同一用途出現三次以上時，才整理成 token 或共用元件。外觀相似但用途不同的項目（例如外觀相近的「送出」按鈕與「篩選」切換鈕）保持分開。只出現一兩次的特例值不建 token，也不為每一個出現過的值都建 token。

### Good Example

這個範例把在三個頁面中都用作「次要說明文字」的同一組樣式抽成 token。

```css
/* 原本 settings.css、profile.css、billing.css 各寫一次 */
:root {
  --text-muted: #6b6760;
  --text-caption-size: 0.8125rem;
}
.caption { color: var(--text-muted); font-size: var(--text-caption-size); }
```

### Bad Example

這個範例把只在活動頁出現一次的值也建成 token，token 清單被一次性的值灌滿，後續的人分不出哪些是系統真正的值。

```css
:root {
  --promo-banner-bg-summer-2026: #ffcf4a;
  --promo-banner-offset-top: 37px;
}
```

## Rule 8 -- 描述寫出用途與確切值

**強度：SHOULD**

每個記錄的值應以描述性名稱開頭，括號附上確切值，並寫出用在哪裡、為什麼用。不得直接貼上 CSS class 名稱或 Tailwind 工具類別當作說明。

### Good Example

這個範例寫出描述名稱、確切值與使用位置。

```markdown
- **柔和圓角**（8px）：卡片與輸入框，讓表單區塊看起來友善但不幼稚。
- **墨黑**（#1c1b19）：所有內文與標題，在紙白底上維持高可讀性。
```

### Bad Example

這個範例直接貼上 class 名稱，沒有確切值也沒有用途，閱讀者得回頭翻程式碼才知道實際的值與使用時機。

```markdown
- `rounded-lg`
- `text-zinc-900`
```

## Rule 9 -- 只記錄視覺決定

**強度：MUST**

DESIGN.md 只記錄視覺系統。產品背景、受眾、商業目標等內容留在 PRODUCT.md，不得重複抄寫；只有會實際限制視覺的長期品牌承諾（例如必須使用的標誌、指定品牌色、無障礙需求）可以寫入。單一畫面的構圖或策略不得寫成整個系統的規則。

### Good Example

這個範例只寫入會限制視覺的品牌承諾。

```markdown
### Don't:
- **Don't** 改變標誌的品牌紅（#d52b1e），所有畫面一律使用原色。
```

### Bad Example

這個範例把產品受眾與單一首頁的構圖寫成系統規則，其他畫面（如後台表格）也會被迫套用首頁的大圖構圖。

```markdown
## Overview
本產品主要使用者為 25–35 歲的上班族，目標是提升訂閱轉換率。

### Do:
- **Do** 每個畫面第一屏都放全寬大圖與單一行動按鈕。
```

## Rule 10 -- 延伸時不改寫既有值

**強度：MUST**

DESIGN.md 已存在而這次是在既有視覺上做新畫面時，只能補上這次新增且已寫入原型或修改規格的 token 或元件，不得修改、刪除或重新命名既有的值。若這次需要變更既有系統的值，必須先用白話告訴使用者會影響哪些畫面並取得同意；發現程式碼已偏離 DESIGN.md 時，只回報差異，不得自行修正。

### Good Example

這個範例保留既有色彩，只補上這次新增的狀態色。

```markdown
### Neutral
- **紙白**（#fbfaf7）：頁面底色。
- **墨黑**（#1c1b19）：內文。

### 狀態
- **警示琥珀**（#c77d14）：這次新增，用於匯出失敗的提示列，來自 `--color-warning`。
```

### Bad Example

這個範例為了新畫面直接把既有的紙白改成另一個值，所有既有頁面的底色都跟著改變，使用者沒有同意過這項變更。

```markdown
### Neutral
- **紙白**（#ffffff）：頁面底色。（原為 #fbfaf7，配合新畫面調整）
```

## Rule 11 -- 素材節只記錄選定的來源

**強度：MUST**

DESIGN.md 的「素材」節只記錄 ui-assets 選定的圖示庫（名稱、版本、授權、線條風格）、插圖風格與照片來源，以及不使用某類素材的決定；個別檔案、來源網址與授權記在素材清單，不得寫進 DESIGN.md。

### Good Example

這個範例只寫出選定的來源與風格，個別檔案留在素材清單。

```markdown
## 素材

- **圖示庫**：Lucide 0.4（ISC），1.5px 線條，沿用程式碼中已安裝的 lucide-react。
- **插圖風格**：不使用插圖。
- **照片來源**：診所實景照片由使用者提供；示意照片取自 Unsplash，需依 Unsplash License 使用。
```

### Bad Example

這個範例把每張照片的網址與作者寫進 DESIGN.md，設計系統變成素材清單，換一張照片就要改設計系統，真正的視覺決定反而被淹沒。

```markdown
## 素材

- hero.jpg：https://unsplash.com/photos/abc123，作者 Jane Doe
- team.jpg：https://unsplash.com/photos/def456，作者 John Roe
```

## Rule 12 -- 動態以 token 記錄

**強度：MUST**

動態的時長與曲線必須以 `--duration-*` 與 `--ease-*` token 記在「動態」表，表格下方可以用一段文字說明動態原則；不得只用文字敘述時長與曲線。舊格式的 DESIGN.md 在轉 token 時被回報格式問題，必須照轉 token 腳本的說明調整表格格式，不得因此改動既有的值。

### Good Example

這個範例以 token 表記錄時長與曲線，原則寫在表格下方。

```markdown
## 動態

| token | 值 | 用途 |
|---|---|---|
| `--duration-feedback` | `150ms` | 按鈕與連結的顏色轉換 |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 所有進場與狀態轉換 |

只有一個設計過的時刻：勾選完成時打勾以 `--duration-check` 畫出。
```

### Bad Example

這個範例只用文字敘述時長與曲線，轉 token 腳本無法解析，原型與實作只能各自抄寫數值。

```markdown
## 動態

勾選完成時以 200ms 的 ease-out 畫出打勾，其餘互動只做 150ms 的顏色轉換。
```
