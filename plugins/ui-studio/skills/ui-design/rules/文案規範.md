# 文案規範

## Rule 1 -- 只改文字不改事實

**強度：MUST**

改善文案時只能修改介面上的文字（標籤、按鈕、提示、錯誤訊息、空狀態說明、替代文字），不得變更版面、配色、元件結構或功能。改寫必須保留原本的事實、產品專有名詞與品牌語氣；涉及事實宣稱、法律意義或可能是領域專有的詞彙時，必須先以白話詢問使用者再改。

### Good Example

這個範例只改按鈕文字，並對不確定的專有名詞先詢問。

```text
我把「提交」改成「送出報名」，讓人知道按下去會發生什麼。
另外畫面上有個詞叫「核銷」，這是你們業界的固定說法嗎？如果是，我就保留不動。
```

### Bad Example

這個範例在改文案時順便把「7 天內免費退貨」改成「隨時可退貨」，擅自改變了產品承諾，可能造成法律與客服糾紛。

```html
<p class="policy">隨時可退貨，安心購買</p>
```

## Rule 2 -- 缺少受眾資訊時白話詢問

**強度：MUST**

PRODUCT.md 或需求中沒有說明使用者是誰、對這個領域熟不熟、使用時的情緒（例如趕時間、擔心付款出錯）時，Claude 必須以白話詢問使用者，不得自行假設。語氣、用詞深淺等設計判斷由 Claude 依答案自行決定。

### Good Example

這個範例用白話詢問受眾的產品事實，沒有要使用者決定語氣。

```text
想先了解一下使用這個畫面的人：
1. 他們大多是第一次接觸這類系統，還是每天在用的熟手？
2. 他們通常是在什麼情況下打開這頁？例如月底趕著對帳，或是有空慢慢設定？
```

### Bad Example

這個範例把語氣這種設計判斷丟給使用者，並使用設計術語，門外漢無法回答。

```text
請問文案的 voice and tone 要偏 formal 還是 casual？microcopy 要走 playful 路線嗎？
```

## Rule 3 -- 按鈕寫出動作與對象

**強度：MUST**

按鈕與連結的文字必須描述按下後會發生的結果，結果不明顯時使用「動詞加對象」，不得描述手勢（例如「點這裡」）。同一個概念在整個產品中必須使用同一組名詞與動詞，不得為了變化而換詞。

### Good Example

這個範例的按鈕寫出動作與對象，並與頁面其他地方統一使用「專案」。

```html
<button type="submit">建立專案</button>
<a href="/projects">查看所有專案</a>
```

### Bad Example

這個範例用「點這裡」描述手勢，且同一概念混用「專案」「項目」，使用者無法預期結果，也會以為是兩種不同的東西。

```html
<button type="submit">確定</button>
<a href="/projects">點這裡查看所有項目</a>
```

## Rule 4 -- 破壞性操作寫出對象與後果

**強度：MUST**

刪除、取消訂閱、移除權限等破壞性操作必須寫出對象與後果。能安全復原時優先提供「復原」而不是確認對話框；必須確認時，訊息與按鈕都要寫出動作名稱，不得使用「是／否」「確定」「OK」「送出」。

### Good Example

這個範例在確認對話框中寫出對象與後果，按鈕直接寫出動作。

```html
<dialog>
  <h2>刪除「2026 年度預算」？</h2>
  <p>這份文件和裡面的 12 則留言會永久刪除，無法復原。</p>
  <button>保留文件</button>
  <button class="danger">刪除文件</button>
</dialog>
```

### Bad Example

這個範例只問「確定嗎」並用「是／否」當按鈕，使用者看不出要刪什麼、會失去什麼，容易誤刪。

```html
<dialog>
  <p>確定嗎？</p>
  <button>否</button>
  <button>是</button>
</dialog>
```

## Rule 5 -- 表單標籤常駐且先講要求

**強度：MUST**

每個欄位都必須有常駐顯示的標籤，placeholder 只能放範例，不得當標籤。格式與資格要求必須在送出前就顯示在欄位旁。驗證訊息要說明哪裡需要修正、怎麼修正，不得責怪使用者。

### Good Example

這個範例有常駐標籤、事先說明格式，錯誤訊息說明怎麼修正。

```html
<label for="phone">手機號碼</label>
<input id="phone" placeholder="0912345678" aria-describedby="phone-hint phone-error">
<small id="phone-hint">10 碼數字，不用加橫線</small>
<p id="phone-error" role="alert">號碼少了 1 碼，請確認是 10 碼數字</p>
```

### Bad Example

這個範例只用 placeholder 當標籤、錯誤訊息責怪使用者，開始輸入後標籤消失，使用者不知道這格要填什麼也不知道怎麼改。

```html
<input placeholder="手機號碼">
<p class="error">您輸入的格式錯誤！</p>
```

## Rule 6 -- 錯誤訊息說明失敗與復原

**強度：MUST**

錯誤訊息必須依序回答：什麼失敗了、原因（已知且有用時）、怎麼復原或還有什麼替代做法。不得以內部錯誤碼當主要訊息，不得承諾系統無法確定的原因或解法。涉及隱私、付款、刪除、失去存取權的訊息要嚴肅，不得開玩笑。

### Good Example

這個範例說明失敗的事、已知原因與復原方式，錯誤碼只作為次要資訊。

```html
<div role="alert">
  <p>付款沒有完成，信用卡尚未扣款。</p>
  <p>發卡銀行拒絕了這筆交易，請改用其他卡片或聯絡銀行。</p>
  <button>改用其他付款方式</button>
  <small>參考代碼：PAY-402</small>
</div>
```

### Bad Example

這個範例以錯誤碼當主要訊息又在付款失敗時開玩笑，使用者不知道錢有沒有被扣、該怎麼辦，還會覺得被輕視。

```html
<div role="alert">ERR_PAYMENT_402 哎呀！錢錢飛走了 🙈</div>
```

## Rule 7 -- 狀態文字誠實且具體

**強度：SHOULD**

載入文字要說出實際在做的事，等待較久時給出誠實的預期；有確定進度才顯示進度，不得捏造進度。空狀態要區分第一次使用、沒有搜尋結果、篩選後無資料、沒有權限、載入失敗，並提供下一步動作。例行的成功訊息保持簡短，只在會影響使用者下一步時才補充後續影響。

### Good Example

這個範例的空狀態說明是篩選造成的，並提供清除篩選的動作。

```jsx
<EmptyState
  title="沒有符合「未付款」的訂單"
  action={<button onClick={clearFilters}>清除篩選</button>}
/>
```

### Bad Example

這個範例在篩選無結果時顯示通用的「沒有資料」，使用者會以為資料遺失，不知道只要清除篩選就能看到訂單。

```jsx
<EmptyState title="沒有資料" />
```

## Rule 8 -- 同一件事只說一次

**強度：SHOULD**

標題已經說明狀態時，下方的介紹文字必須補充新資訊，否則刪除。說明文字要回答使用者心中的疑問，不得只是重述控制項名稱。

### Good Example

這個範例的說明文字回答了「為什麼要填」，沒有重複標籤。

```html
<label for="tax-id">統一編號</label>
<small>需要開立公司發票時才填</small>
```

### Bad Example

這個範例的標題、介紹與說明重複同一句話，使用者要多讀三次才拿到同樣的資訊，畫面也被無用文字佔滿。

```html
<h2>設定通知</h2>
<p>在這裡您可以設定通知。</p>
<label>通知設定</label><small>請設定您的通知</small>
```

## Rule 9 -- 文案必須可被翻譯

**強度：MUST**

訊息必須寫成完整句子，變數與數字以具名參數放入，讓譯者能調整語序，不得用字串片段拼接。不得為了塞進寬度而提前縮寫，版面要容許文字變長。

### Good Example

這個範例用完整句子與具名參數，譯者可以自由調整語序。

```js
t('cart.summary', { count: items.length, total: formatCurrency(sum) })
// zh-TW: "購物車有 {count} 件商品，共 {total}"
```

### Bad Example

這個範例用片段拼接句子，其他語言的語序與複數規則不同時，譯文會變成文法錯誤的句子。

```js
'購物車有 ' + items.length + ' 件商品，共 ' + sum + ' 元'
```

## Rule 10 -- 無障礙名稱與可見文字一致

**強度：MUST**

只有圖示的按鈕必須有無障礙名稱，且名稱要與可見標籤或實際結果一致。連結文字脫離上下文也要看得懂。有資訊的圖片的 `alt` 要傳達圖中資訊，裝飾圖片使用空的 `alt=""`。訊息不得只靠標點、顏色或圖示表達。

### Good Example

這個範例的圖示按鈕有清楚名稱，裝飾圖使用空 alt，連結文字單獨看也懂。

```html
<button aria-label="關閉通知"><svg aria-hidden="true">…</svg></button>
<img src="divider.svg" alt="">
<a href="/refund">了解退款規定</a>
```

### Bad Example

這個範例的圖示按鈕沒有名稱、裝飾圖寫了無意義 alt、連結只寫「更多」，螢幕閱讀器使用者聽到的只有「按鈕」「分隔線圖片」「更多」，無法操作。

```html
<button><svg>…</svg></button>
<img src="divider.svg" alt="分隔線圖片">
<a href="/refund">更多</a>
```
