# 首次使用規範

## Rule 1 -- 只改首次使用流程與空狀態

**強度：MUST**

首次使用改善只能修改歡迎畫面、初次設定、引導提示、導覽步驟與空狀態，不得改動產品其他畫面的版面、配色或功能，也不得為了引導而新增產品功能。

### Good Example

這個範例只在專案清單為空時顯示引導，清單有資料時的畫面不變。

```jsx
{projects.length === 0 ? <FirstProjectEmptyState /> : <ProjectList items={projects} />}
```

### Bad Example

這個範例為了引導順便重做了整個側邊導覽與首頁配色，使用者只要求改善新手流程，既有使用者卻發現整個產品變了樣。

```jsx
<NewSidebar theme="gradient" />
<OnboardingChecklist />
```

## Rule 2 -- 缺少關鍵時刻時白話詢問

**強度：MUST**

PRODUCT.md 或需求中沒有說明「使用者完成哪件事時會覺得這個產品值得用」，以及使用者的熟悉程度（新手、熟手、混合）時，Claude 必須以白話詢問使用者，不得自行假設。引導的形式（提示、導覽、空狀態）由 Claude 自行決定。

### Good Example

這個範例用白話詢問產品事實，沒有要使用者選擇引導形式。

```text
想先了解兩件事：
1. 新使用者第一次用的時候，完成哪件事會讓他覺得「這個好用」？例如第一次成功寄出報價單？
2. 來用的人大多是第一次接觸這類工具，還是從別的工具換過來的熟手？
```

### Bad Example

這個範例把設計判斷丟給使用者並使用術語，門外漢無法回答。

```text
你想要 product tour、checklist 還是 contextual tooltip？aha moment 要怎麼定義？
```

## Rule 3 -- 最短路徑到第一次成功

**強度：MUST**

引導必須把使用者最快帶到第一次真正完成一件事：初次設定只要求最少的必要資訊（其他之後再收），只介紹 1～3 個核心概念，多步驟時顯示進度（例如「第 1 步，共 3 步」），並提供預先填好的範例或範本。不得在使用者能使用產品之前強迫走完冗長的教學。

### Good Example

這個範例只收必要欄位，並讓使用者用範本直接完成第一份文件。

```jsx
<Step index={1} total={3}>
  <label htmlFor="team">團隊名稱</label>
  <input id="team" />
  <Button onClick={next}>下一步</Button>
</Step>
<Step index={3} total={3}><Button onClick={createFromTemplate}>用範本建立第一份報價單</Button></Step>
```

### Bad Example

這個範例在註冊時要求十幾個欄位並先看完八頁說明，使用者還沒看到產品價值就離開了。

```jsx
<SignupForm fields={['name','email','phone','company','title','size','industry','budget','source','address']} />
<IntroSlides count={8} skippable={false} />
```

## Rule 4 -- 可跳過且容易找到

**強度：MUST**

歡迎畫面、導覽與教學都必須提供「略過」或「我自己看看」的選項，放在明顯的位置，且不得阻擋使用者直接進入產品。

### Good Example

這個範例在導覽每一步都提供明顯的略過按鈕。

```jsx
<TourStep>
  <p>從這裡建立第一個專案</p>
  <Button onClick={next}>下一步</Button>
  <Button variant="ghost" onClick={endTour}>略過導覽</Button>
</TourStep>
```

### Bad Example

這個範例的略過連結是灰色小字藏在角落，熟悉的使用者找不到，只能被迫走完整個導覽。

```jsx
<a style={{ fontSize: 10, color: '#ccc', position: 'absolute', bottom: 4, right: 4 }}>skip</a>
```

## Rule 5 -- 在真實介面中示範

**強度：MUST**

引導必須在真實的產品介面中進行，讓使用者按真正的按鈕、用範例資料完成真正的動作，步驟文字描述工作流程（「建立專案」）而不是介紹控制項（「這是專案按鈕」）。不得做一個與產品分開的教學模式。

### Good Example

這個範例在真實介面中以範例資料引導使用者完成動作。

```jsx
<Spotlight target="#new-project">
  建立你的第一個專案，我們已經放好一份範例資料讓你試試看。
</Spotlight>
```

### Bad Example

這個範例另做一個假的教學頁面，使用者學完回到真正的產品時找不到對應的按鈕，學到的東西用不上。

```jsx
<Route path="/tutorial" element={<FakeDashboardDemo />} />
```

## Rule 6 -- 空狀態依類型給內容

**強度：MUST**

空狀態必須依類型設計。第一次使用要包含五項：這裡會出現什麼、為什麼有用、開始的按鈕、圖示或插圖、進一步的說明連結。使用者自己清空的狀態只需輕量提示與重新建立的方式；搜尋或篩選沒有結果要建議換關鍵字或清除篩選；沒有權限要說明原因與如何取得；載入失敗要說明發生什麼事並提供重試。

### Good Example

這個範例的第一次使用空狀態包含全部五項內容。

```jsx
<EmptyState icon={<FolderIcon />}>
  <h3>你的專案會出現在這裡</h3>
  <p>用專案整理工作，和團隊一起協作。</p>
  <Button>建立第一個專案</Button> <Button variant="secondary">從範本開始</Button>
  <a href="/help/projects">看 2 分鐘教學</a>
</EmptyState>
```

### Bad Example

這個範例的第一次使用只顯示一行「沒有資料」，新使用者不知道這裡是什麼、要怎麼開始，以為產品壞了。

```jsx
<p className="text-gray-400">沒有資料</p>
```

## Rule 7 -- 導覽步驟不超過 7 步

**強度：SHOULD**

導覽每一趟限制在 3～7 步，使用者可以自由前後切換，導覽期間不得鎖住整個介面，結束後可以從說明選單重新播放。

### Good Example

這個範例的導覽只有 4 步，不鎖住介面，並可從說明選單重播。

```js
const tour = createTour({ steps: [s1, s2, s3, s4], allowInteraction: true });
helpMenu.add({ label: '重新播放導覽', onClick: () => tour.start() });
```

### Bad Example

這個範例的導覽有 15 步且鎖住整個畫面，使用者記不住前面的內容，也無法中途試做任何動作。

```js
createTour({ steps: allFifteenSteps, blockInteraction: true, allowClose: false });
```

## Rule 8 -- 看過的引導不再出現

**強度：MUST**

引導與提示必須記錄完成與關閉狀態，已完成或已關閉的不得重複出現，回訪的使用者不得再看到初次引導。提示要能關閉並提供「不再顯示」。存在瀏覽器時，鍵值必須包含帳號 ID 與引導版本，避免共用電腦時一個帳號的紀錄影響另一個帳號。

### Good Example

這個範例以帳號 ID 與版本號記錄完成狀態。

```js
const key = `onboarding-completed:v1:${userId}`;
if (!localStorage.getItem(key)) startOnboarding();
onComplete(() => localStorage.setItem(key, 'true'));
```

### Bad Example

這個範例每次登入都重新顯示同一個提示，關閉也沒有記錄，熟悉的使用者每天都要再關一次，感覺被打擾。

```js
useEffect(() => { showTooltip('reports'); }, []);
```

## Rule 9 -- 不說教不過度慶祝

**強度：SHOULD**

引導文字要簡潔，不解釋使用者本來就懂的常見操作（例如「點擊按鈕可以送出」）。完成第一次成功時可以簡短肯定並指出下一步，但預設避免全螢幕彩帶、連續彈窗等誇張慶祝。

### Good Example

這個範例在完成時簡短肯定並給出下一步。

```jsx
<Toast>第一份報價單已寄出。<a href="/clients">接著邀請客戶查看</a></Toast>
```

### Bad Example

這個範例解釋顯而易見的操作並用全螢幕彩帶慶祝，使用者覺得被當成新手，也被擋住無法繼續工作。

```jsx
<Tooltip>這是搜尋框，在這裡輸入文字就可以搜尋喔！</Tooltip>
<FullscreenConfetti duration={5000} />
```
