# 精簡規範

## Rule 1 -- 只刪減、合併或收起

**強度：MUST**

精簡畫面時，只能刪除、合併或收起（延後顯示）既有的元素、資訊與樣式。不得新增功能、改寫成新的視覺風格，或更換品牌的字型與顏色，除非使用者明確要求。

### Good Example

這個範例把三個重複的匯出按鈕合併成一個下拉選單，沒有新增其他東西。

```html
<details class="menu">
  <summary class="btn-secondary">匯出</summary>
  <ul><li><button>CSV</button></li><li><button>Excel</button></li><li><button>PDF</button></li></ul>
</details>
```

### Bad Example

這個範例在精簡時順手加入新的搜尋功能並換了整頁字型，使用者只要求清掉雜亂的部分，畫面反而多了沒要求的東西。

```html
<input type="search" placeholder="搜尋…" class="new-search" />
<style>body { font-family: "Manrope", sans-serif; }</style>
```

## Rule 2 -- 主要目標不明時白話詢問

**強度：MUST**

程式碼與 PRODUCT.md 看不出使用者來到這個畫面最主要要完成的一件事時，必須先以白話詢問，不得自行猜測哪些功能可以刪。

### Good Example

這個範例用白話詢問使用者在這個畫面最常做的事。

```text
想先確認：大部分人打開這個頁面，最主要是要做哪一件事？
1. 查看本月的營收數字
2. 新增一筆訂單
3. 其他（請簡單描述）
其他功能我會保留，但會往後放或收起來。
```

### Bad Example

這個範例沒有確認就以自己的判斷刪除功能，若被刪掉的正是使用者每天要用的功能，畫面雖然變乾淨卻不能用了。

```text
我判斷「批次匯入」很少用，已經從頁面移除了。
```

## Rule 3 -- 只留一個主要動作

**強度：MUST**

每個畫面或區塊只能有一個視覺上最突出的主要動作，次要動作少量並降低樣式，其餘改為文字連結或收進選單。

### Good Example

這個範例只有「儲存」使用主按鈕樣式，其他動作退為次要或收進選單。

```html
<div class="actions">
  <button class="btn-primary">儲存</button>
  <button class="btn-secondary">預覽</button>
  <details class="more"><summary>更多</summary>…複製、封存…</details>
</div>
```

### Bad Example

這個範例並排五個同樣醒目的主按鈕，使用者不知道下一步該按哪一個。

```html
<button class="btn-primary">儲存</button>
<button class="btn-primary">預覽</button>
<button class="btn-primary">複製</button>
<button class="btn-primary">封存</button>
<button class="btn-primary">分享</button>
```

## Rule 4 -- 同一資訊只說一次

**強度：SHOULD**

同一件事只在畫面上出現一次。刪除重述前文的標題、重複的說明段落與可有可無的行銷用語，保留真正的意思。

### Good Example

這個範例只用一個標題說明區塊內容，直接進入表單。

```html
<h2>付款資訊</h2>
<form>…</form>
```

### Bad Example

這個範例的標題、副標與說明段落重複講同一件事，使用者要讀三遍才看到表單。

```html
<h2>付款資訊</h2>
<p class="subtitle">請填寫您的付款資訊</p>
<p>在這個區塊中，您可以填寫付款資訊以完成付款。</p>
<form>…</form>
```

## Rule 5 -- 次要內容延後顯示

**強度：SHOULD**

不是每次都需要的進階選項與細節，收進有明確入口的展開區、分頁或下一步，不要全部同時攤開。入口的文字必須說清楚裡面有什麼。

### Good Example

這個範例把進階設定收進展開區，入口寫明內容。

```html
<details>
  <summary>進階設定（逾時時間、重試次數）</summary>
  …
</details>
```

### Bad Example

這個範例把十幾個進階欄位與基本欄位一起攤開，第一次使用的人被大量選項嚇到，找不到必填的欄位。

```html
<form>
  <label>名稱</label><input />
  <label>逾時時間</label><input />
  <label>重試次數</label><input />
  <label>回呼網址</label><input />
  <!-- …再十個進階欄位 -->
</form>
```

## Rule 6 -- 限制顏色與字體的種類

**強度：SHOULD**

精簡後的畫面保留 1～2 個品牌或裝飾色加上中性色，不用到 5～7 種；成功、警告、錯誤等語意色保留，並各自搭配非顏色的線索。字體使用一套字型家族、3～4 種字級、2～3 種字重。

### Good Example

這個範例把字級收斂為四級、字重收斂為兩種。

```css
:root {
  --text-sm: 0.875rem; --text-base: 1rem;
  --text-lg: 1.25rem;  --text-xl: 1.75rem;
  --weight-regular: 400; --weight-bold: 650;
}
```

### Bad Example

這個範例同一頁用了七種字級與五種裝飾色，畫面看起來零亂，使用者分不出哪些差異代表意義。

```css
.a { font-size: 13px; color: #f59e0b; }
.b { font-size: 15px; color: #10b981; }
.c { font-size: 17px; color: #8b5cf6; }
.d { font-size: 19px; color: #ec4899; }
.e { font-size: 22px; color: #06b6d4; }
```

## Rule 7 -- 禁止巢狀卡片

**強度：MUST**

卡片內不得再放卡片。精簡時遇到巢狀卡片，移除內層卡片的外框與背景，改用間距或分隔線分組。

### Good Example

這個範例移除內層卡片，以間距區分區塊。

```html
<article class="card">
  <h3>帳戶</h3>
  <section class="stack">…基本資料…</section>
  <section class="stack">…通知設定…</section>
</article>
```

### Bad Example

這個範例保留卡片中的卡片，框線層層相疊，畫面仍然雜亂，精簡沒有做到。

```html
<article class="card">
  <div class="card"><div class="card">…</div></div>
</article>
```

## Rule 8 -- 不刪必要功能與資訊

**強度：MUST**

精簡不得移除使用者完成任務或做決定需要的功能與資訊（例如價格、限制條件、錯誤說明），也不得移除表單標籤、`aria-label` 等無障礙必要內容，或把圖示按鈕的文字拿掉到看不懂用途。

### Good Example

這個範例把可見的欄位標籤縮短，但仍保留標籤與無障礙名稱。

```html
<label for="qty">數量</label>
<input id="qty" type="number" />
<button aria-label="刪除此項目"><svg aria-hidden="true">…</svg></button>
```

### Bad Example

這個範例為了簡潔刪掉欄位標籤，只留佔位文字，輸入後提示消失，螢幕閱讀器也讀不出欄位名稱。

```html
<input type="number" placeholder="數量" />
<button><svg>…</svg></button>
```

## Rule 9 -- 刪除功能前先確認

**強度：MUST**

要整個移除某個功能或選項（不是合併或收起）時，必須先以白話向使用者說明要移除什麼、為什麼，以及是否另有入口可以找到，取得同意後才刪除。

### Good Example

這個範例在刪除前用白話說明理由與替代入口。

```text
「列印」按鈕和瀏覽器本身的列印功能重複，我想把它從工具列拿掉，需要時仍可以用鍵盤 Ctrl+P 列印。可以移除嗎？
```

### Bad Example

這個範例直接刪掉功能才告知使用者，若該功能有人依賴，使用者要回頭追查哪裡被改掉。

```text
我已經移除了工具列上的「列印」與「另存範本」按鈕，畫面更簡潔了。
```

## Rule 10 -- 一併清除不再使用的程式碼

**強度：SHOULD**

刪除元素後，一併移除只被它使用的 CSS、元件與檔案，並把相似的樣式合併，減少元件的變體數量。

### Good Example

這個範例在移除橫幅元件後，同時刪掉它專用的樣式檔與匯入。

```diff
- import PromoBanner from "./PromoBanner";
- import "./PromoBanner.css";
```

### Bad Example

這個範例只把元件從畫面拿掉，專用的 CSS 與元件檔都留著，之後的人不知道哪些程式碼還在使用。

```diff
- <PromoBanner />
  // PromoBanner.jsx 與 PromoBanner.css 仍保留在專案中
```
