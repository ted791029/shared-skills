# 動態規範

## Rule 1 -- 動態必須有工作

**強度：MUST**

只在動態有工作時加入：回應使用者的操作、讓狀態變化或空間關係看得懂、在導覽或版面變化時保持連續、在有意義的時刻引導注意、表現選定的視覺世界。不得因為某個區塊「靜態看起來空」就為它加動畫。

### Good Example

這個範例只為能說明變化的兩處加入動態。

```text
對話框開啟：從觸發按鈕的位置展開，說明它從哪裡來（連續）
儲存成功：按鈕的勾選圖示畫出（回應操作）
其餘區塊：不加動畫
```

### Bad Example

這個範例為每個區塊都加上捲動顯示，動畫沒有說明任何變化，使用者每捲一段就要等一次。

```text
所有 section：進入畫面時淡入並上移 24px，依序延遲 100ms
```

## Rule 2 -- 先寫出動態主張

**強度：MUST**

實作前必須寫出動態主張，並記在修改規格或檢查報告的「動態主張」：焦點時刻（至多一個，可以沒有）、需要連續性的狀態或導覽變化、需要回饋的操作、效能預算（哪些效果成本高、多久觸發一次）。焦點時刻必須來自這個產品與畫面；通用的淡入上移、hover 浮起、視差、捲動顯示不算主張。

### Good Example

這個範例的焦點時刻來自產品本身的完成時刻，其餘只做回饋與連續。

```text
動態主張
- 焦點時刻：任務全部完成時，清單收合成一行「今天都完成了」
- 連續性：新增的項目從輸入框位置滑入清單
- 回饋：勾選框按下時立即填色
- 效能預算：只動 transform 與 opacity，收合動畫每天至多觸發一次
```

### Bad Example

這個範例的主張只是通用效果的清單，看不出與這個產品有什麼關係，任何網站都能套用。

```text
動態主張：頁面載入時淡入、卡片 hover 浮起、捲動時視差、按鈕有彈跳回饋
```

## Rule 3 -- 依意義選擇手法

**強度：SHOULD**

應依動畫要傳達的意義選擇手法：連續與關係用共享元素、FLIP 或 View Transitions；焦點與深度用有範圍的模糊、陰影或亮度；揭示與構圖用遮罩或裁切；狀態與回饋用能讓因果清楚的最小變化。不疊加多種手法製造特效；清單以清單出現時才依序出現，總延遲不超過 300ms。

### Good Example

這個範例用共享元素說明縮圖與大圖是同一張照片。

```text
點縮圖開啟燈箱：以 View Transitions 讓縮圖放大成大圖，背景淡出
```

### Bad Example

這個範例同時疊加旋轉、模糊、彈跳與粒子，意義被特效淹沒，低階裝置也會掉幀。

```text
開啟燈箱：縮圖旋轉 180 度、背景模糊、大圖彈跳進場並噴出粒子
```

## Rule 4 -- 時長與曲線依距離與後果

**強度：MUST**

時長依移動距離與後果選擇，並以 DESIGN.md 的動態 token 表示：

| 時長 | 用途 |
|---|---|
| 100–150ms | 立即回饋（按下、勾選） |
| 150–300ms | 一般狀態變化 |
| 300–500ms | 版面、疊層或畫面轉場 |
| 500–800ms | 刻意設計的焦點進場 |

退場必須比進場快。曲線使用減速曲線（例如 `cubic-bezier(0.16, 1, 0.3, 1)`）；不得使用彈跳、彈性或超出終點再回彈的曲線。

### Good Example

這個範例依用途選擇時長，退場比進場快，曲線使用減速。

```css
.dialog { transition: opacity var(--duration-overlay) var(--ease-out), transform var(--duration-overlay) var(--ease-out); }
.dialog[data-closing] { transition-duration: 200ms; }
:root { --duration-overlay: 320ms; --ease-out: cubic-bezier(0.16, 1, 0.3, 1); }
```

### Bad Example

這個範例讓按鈕回饋花 600ms 並使用彈跳曲線，使用者按下後要等半秒才看到反應，像是畫面卡住。

```css
.button:active { transition: transform 600ms cubic-bezier(0.68, -0.55, 0.27, 1.55); }
```

## Rule 5 -- hover 不移動自己

**強度：MUST**

hover 動畫不得移動被 hover 的元素本身，也不得擠壓相鄰元素或佔走它們的指標範圍，必須由子元素承擔位移；需要等待的預覽只在進入時延遲，離開時不延遲。

### Good Example

這個範例讓卡片本身保持不動，由內層承擔上移。

```css
.card:hover .card-surface { transform: translateY(-2px); }
```

### Bad Example

這個範例讓卡片本身上移，游標停在卡片下緣時，卡片移開後 hover 消失又移回，畫面不停閃動。

```css
.card:hover { transform: translateY(-4px); }
```

## Rule 6 -- 依執行環境實作

**強度：MUST**

動畫必須用執行環境已有的能力表達：宣告式狀態用 CSS transition 或 keyframes；需要中斷與排序時用 Web Animations API 或專案既有的動畫函式庫；跨狀態的連續用 View Transitions。不得為了一個效果新增依賴；預設狀態的內容必須可見（腳本失效時內容仍在）；不得動畫 width、height、top、left、margin 等版面屬性；`will-change` 只在動畫期間設定。原生平台依原生平台規範。

### Good Example

這個範例用 CSS 動畫 transform 與 opacity，內容預設可見。

```css
.toast { opacity: 1; transform: none; transition: opacity 200ms var(--ease-out), transform 200ms var(--ease-out); }
.toast[data-entering] { opacity: 0; transform: translateY(8px); }
```

### Bad Example

這個範例為了一個淡入效果新增動畫函式庫，並以 height 做展開，每一格都觸發版面重算，內容在腳本失效時也一直是隱藏的。

```js
import { animate } from 'some-animation-lib';
el.style.height = '0'; el.style.opacity = '0';
animate(el, { height: '320px', opacity: 1 });
```

## Rule 7 -- 每個動畫都有減少動態的版本

**強度：MUST**

每個網頁動畫都必須有 `prefers-reduced-motion: reduce` 的替代版本：移除或減少空間移動，保留有意義的透明度、顏色與狀態變化；確認操作的回饋在減少動態時仍必須看得懂，不得整批關掉所有過渡。

### Good Example

這個範例在減少動態時移除位移，保留淡入讓狀態變化仍可察覺。

```css
@media (prefers-reduced-motion: reduce) {
  .dialog { transition: opacity 150ms linear; transform: none; }
}
```

### Bad Example

這個範例在減少動態時關掉所有過渡，勾選與儲存成功的回饋瞬間跳變，使用者不確定操作是否生效。

```css
@media (prefers-reduced-motion: reduce) {
  * { transition: none !important; animation: none !important; }
}
```

## Rule 8 -- 非必要循環在看不到時停止

**強度：MUST**

非必要的循環動畫在離開畫面或分頁隱藏時必須停止，並尊重自動播放與聲音的偏好。

### Good Example

這個範例在背景動畫離開畫面時暫停。

```js
new IntersectionObserver(([entry]) => {
  bg.getAnimations().forEach((a) => (entry.isIntersecting ? a.play() : a.pause()));
}).observe(bg);
```

### Bad Example

這個範例的背景動畫永遠在跑，使用者捲到頁尾或切到其他分頁時仍持續耗電。

```css
.hero-bg { animation: drift 12s linear infinite; }
```

## Rule 9 -- 以影格驗證動態

**強度：MUST**

新增或修改動態時，必須在原型或局部示意上以畫面擷取的 motion 擷取正常與減少動態各一次，進場與退場分開擷取（退場以 `--setup` 先開啟），並檢視每一格與 filmstrip；不得只看單一元素或單張截圖就說流暢。無法實測時，改為讀原型、局部示意或修改規格，檢查時長、曲線與減少動態版本，報告寫明「未以影格驗證」。

### Good Example

這個範例分別擷取對話框的進場與退場，正常與減少動態各一次。

```bash
uv run "<ui-design>/scripts/畫面擷取.py" motion design/prototype/dialog.html --click "#open" --region "[role=dialog]"
uv run "<ui-design>/scripts/畫面擷取.py" motion design/prototype/dialog.html --click "#open" --region "[role=dialog]" --reduced-motion
uv run "<ui-design>/scripts/畫面擷取.py" motion design/prototype/dialog.html --setup open.json --click "#close" --region "[role=dialog]"
```

### Bad Example

這個範例只截一張開啟後的畫面就判定動畫流暢，進場中途的跳動與減少動態時是否仍有回饋都沒有被看到。

```text
截圖：對話框已開啟，畫面正常 → 動畫流暢
```

## Rule 10 -- 時長與曲線寫進 DESIGN.md

**強度：MUST**

這次新增或變更的時長與曲線，必須依設計系統規範以 `--duration-*`、`--ease-*` token 寫回 DESIGN.md 的動態表，原型與修改規格引用這些 token，不另寫數值。

### Good Example

這個範例新增對話框的時長 token，原型以 token 引用。

```markdown
| `--duration-overlay` | `320ms` | 對話框與抽屜的進場 |
```

### Bad Example

這個範例在原型裡直接寫 320ms，DESIGN.md 沒有這個值，下一個畫面的對話框又選了另一個時長，同類動畫的節奏開始不一致。

```css
.dialog { transition: transform 320ms cubic-bezier(0.16, 1, 0.3, 1); }
```
