# 實測規範

## Rule 1 -- 依用法選擇實測對象

**強度：MUST**

實測對象依用法決定：做新畫面或目標是原型時擷取原型；收尾與單項改善時，先擷取正式畫面作為現況，再擷取局部示意；技術檢查時只擷取正式畫面。正式畫面的實測只讀。

### Good Example

這個範例在收尾時先擷取正式的設定頁，再擷取修改後的局部示意，兩者可以對照。

```text
用法：收尾（設定頁）
shot http://localhost:5173/settings --out <暫存>/現況
shot design/prototype/settings-form.html --out <暫存>/示意
```

### Bad Example

這個範例在收尾時只擷取局部示意，正式設定頁在 390px 的破版從未被看到，修改規格也就沒有寫到它。

```text
用法：收尾（設定頁）
shot design/prototype/settings-form.html
```

## Rule 2 -- 預設擷取四種寬度與每種狀態

**強度：MUST**

沒有特別指定時，在 390、768、1024、1440 四種寬度擷取完整頁面；原型有 `?state=` 狀態時，每種狀態都要擷取；DESIGN.md 的色彩有暗色值時，亮色與暗色都要擷取。

### Good Example

這個範例擷取原型的三種狀態與兩種色彩模式。

```bash
uv run "<ui-design>/scripts/畫面擷取.py" shot design/prototype/home.html --states loading,empty,error --color-scheme light,dark
```

### Bad Example

這個範例只擷取 1440 的成功狀態，手機寬度的溢出與空狀態的版面都沒有被檢查。

```bash
uv run "<ui-design>/scripts/畫面擷取.py" shot design/prototype/home.html --widths 1440
```

## Rule 3 -- 正式畫面只用既有的啟動方式

**強度：MUST**

擷取正式畫面時，只能使用呼叫者帶入的網址，或專案既有的開發伺服器啟動指令（例如 package.json 的 dev script）；不得修改程式碼、不得安裝或更新專案的相依套件。伺服器由這次啟動的，結束後必須關閉。不知道如何啟動時詢問使用者；不可詢問時退回讀程式碼，報告寫明「無法啟動，未實測」。

### Good Example

這個範例以專案既有的 dev script 啟動，擷取後關閉自己啟動的伺服器。

```text
package.json：「dev": "vite"」→ 背景執行 npm run dev → 擷取 http://localhost:5173/settings → 關閉這次啟動的 vite
```

### Bad Example

這個範例為了讓頁面跑起來而更新套件並修改設定檔，正式專案的相依與設定被設計流程改動。

```text
npm run dev 失敗 → 執行 npm install vite@latest，並修改 vite.config.ts 的 port → 擷取畫面
```

## Rule 4 -- 截到登入頁時不得當成結果

**強度：MUST**

腳本的 `suspected_login` 只是提示，必須以最終網址與截圖內容確認：確認是登入頁或與目標不符的頁面時，不得把它當成目標畫面的結果，改為讀程式碼檢查，報告寫明「需要登入，未實測」。目標畫面本身含有密碼欄位（例如變更密碼）而網址正確時，照常採用。

### Good Example

這個範例檢查截圖後發現被導向登入頁，改為讀程式碼並寫明原因。

```text
suspected_login：true，最終網址 /login，截圖是登入表單 → 設定頁需要登入，未實測，改讀 src/pages/Settings.tsx
```

### Bad Example

這個範例把被導向的登入頁截圖當成設定頁的結果，報告列出的是登入頁的問題，設定頁其實沒有被檢查。

```text
suspected_login：true，最終網址 /login → 照常判讀：axe 違規 2 項，列入設定頁的檢查報告
```

## Rule 5 -- 無法實測時先詢問再退回

**強度：MUST**

腳本以結束碼 3（找不到 Chromium）結束時，可以詢問就先詢問使用者是否執行 `uv run --with playwright playwright install chromium` 安裝；安裝 Chromium 是為了實測，不屬於效能規範所說的效能工具。使用者拒絕、呼叫者標明不可詢問，或擷取因其他原因失敗（找不到 uv、依賴下載失敗、目標無法開啟、逾時）時，退回讀程式碼檢查，報告的實測結果寫明「未實測」與原因。

### Good Example

這個範例在不可詢問時退回讀程式碼，並在報告寫明原因。

```text
畫面擷取.py 結束碼 3（找不到 Chromium），呼叫者標明不可詢問
→ 改讀 ui/prototype/*.html 檢查；檢查報告「實測結果」：未實測（環境沒有 Chromium）
```

### Bad Example

這個範例在擷取失敗後沒有寫明，檢查報告看起來像實測過，讀者以為各寬度的版面都確認過了。

```text
畫面擷取.py 結束碼 3 → 改讀程式碼；檢查報告「實測結果」：各寬度正常
```

## Rule 6 -- 每張截圖都要親自檢視

**強度：MUST**

必須親自打開檢視每一張截圖與影格，不得只看 report.json 的數字下結論；空白、截錯區域、寬度或狀態不符的截圖必須重擷，不得據以判斷。

### Good Example

這個範例逐張檢視截圖，發現 390px 的錯誤狀態截圖是空白後重擷。

```text
light-390-error.png：整張空白 → 錯誤狀態的腳本需要較長時間，加長 --timeout 重擷 → 重擷後可見錯誤訊息被截斷，列入問題
```

### Bad Example

這個範例只看報告的數字就判定沒有問題，截圖中兩個按鈕重疊的情況沒有被發現，因為重疊不會出現在溢出統計裡。

```text
report.json：overflow 0、offscreen 0、axe 0 → 版面沒有問題
```

## Rule 7 -- 逐項判讀 axe-core 的結果

**強度：MUST**

axe-core 的每一項違規都必須判讀：確認屬實的依技術檢查規範的嚴重度列入問題；誤判（例如原型刻意省略的區塊）寫出理由後排除。位置寫選擇器與寬度，能對回原始碼時附上檔案與行號。不得照單全收，也不得整批略過。

### Good Example

這個範例逐項判讀，屬實的列為問題並對回原始碼，誤判寫出理由。

```text
image-alt（serious）：.hero img，所有寬度 → 屬實，P1，src/components/Hero.tsx:18
region（moderate）：原型的 states.html 沒有 main 地標 → 排除：states.html 只是狀態入口，不是產品畫面
```

### Bad Example

這個範例把所有違規整批貼進報告，讀者無法分辨哪些要修、哪些是誤判，也沒有嚴重度可以排序。

```text
axe 違規 24 項：image-alt、region、landmark-one-main、color-contrast……（全文附後）
```

## Rule 8 -- 原型有嚴重問題時修正一輪

**強度：MUST**

原型或局部示意有 P0 或 P1 的問題時，必須修正並重新擷取與檢查一輪；修正後仍存在的問題列入報告，不再迴圈。正式畫面的問題不在這裡修正，寫進修改規格。

### Good Example

這個範例修正原型在 390px 的溢出後重擷一輪，仍存在的 P2 問題列入報告。

```text
第一輪：P1 390px .plan-table 超出畫面 → 改為卡片列表 → 重擷 → 已解決
剩下：P2 1440px 標題行長 92 字元 → 列入檢查報告
```

### Bad Example

這個範例發現 P1 問題後只列入報告就交付，原型帶著已知的破版交給實作，實作照著原型做出同樣的問題。

```text
P1 390px .plan-table 超出畫面 → 列入檢查報告，原型不修改
```

## Rule 9 -- 截圖放在專案外

**強度：MUST**

截圖、影格與 report.json 放在系統暫存資料夾（腳本的預設），或呼叫者指定的位置；不得寫進專案中會被版控追蹤的位置。技術檢查時不得在專案內產生任何檔案；開發伺服器自己產生的快取不算。

### Good Example

這個範例使用腳本預設的暫存資料夾，專案內沒有多出檔案。

```text
shot http://localhost:5173/settings → 輸出 C:\Users\<user>\AppData\Local\Temp\ui-design-shot-x8k2\
```

### Bad Example

這個範例把截圖寫進專案根目錄的 screenshots/，技術檢查改動了專案內容，截圖也可能被誤 commit。

```text
shot http://localhost:5173/settings --out ./screenshots
```
