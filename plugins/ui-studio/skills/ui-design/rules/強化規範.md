# 強化規範

## Rule 1 -- 只改指定的區塊

**強度：MUST**

讓設計更有張力時，只能修改使用者指定的目標區塊。目標以外的區塊、全站共用樣式與設計系統的定義都不得更動，也不得藉機把整頁改成新的風格。

### Good Example

這個範例只在首頁主視覺的專屬 class 上加強，共用的按鈕與標題樣式不動。

```css
.home-hero__title { font-size: var(--text-display); font-weight: 800; }
.home-hero { padding-block: var(--space-24); }
```

### Bad Example

這個範例為了讓主視覺更醒目而改了全站的 `h1` 與 `.btn`，其他頁面的標題與按鈕跟著變大，使用者沒要求的地方全被改動。

```css
h1 { font-size: 5rem; font-weight: 900; }
.btn { padding: 1.25rem 2.5rem; }
```

## Rule 2 -- 目標不明時白話詢問

**強度：MUST**

使用者沒有說清楚要強化哪個區塊，或沒有說哪些地方必須保持原樣時，必須先以白話詢問，不得自行挑選區塊動手。提問以畫面上看得到的區塊名稱描述，不使用設計術語。

### Good Example

這個範例用畫面上看得到的區塊讓使用者選擇，並確認哪些地方不能動。

```text
想確認一下要加強哪一塊：
1. 最上方的大標題與介紹
2. 中間的方案價格區
3. 最下方的「立即試用」區
另外，有沒有哪些地方一定要維持現在的樣子？
```

### Bad Example

這個範例在不知道目標的情況下直接改了整頁，還用術語描述，使用者既沒機會選擇，也看不懂改了什麼。

```text
我已經提高整頁的 visual hierarchy 與 contrast ratio，並強化了 hero 的 typographic scale。
```

## Rule 3 -- 不新增系統沒有的元素

**強度：MUST**

不得新增設計系統裡沒有的顏色、字型、圓角、陰影或其他基本元素。既有系統確實無法表達所需的強度時，必須先以白話向使用者說明要新增的具體項目與用途，取得同意後才新增。

### Good Example

這個範例在系統不足時先用白話說明要加什麼、為什麼，等待使用者同意。

```text
目前的顏色裡沒有夠深的底色能讓這一區跳出來。我想新增一個「深藍色底」，只用在這一區當背景，讓它成為整頁的重點。可以加嗎？
```

### Bad Example

這個範例直接加入系統裡沒有的霓虹色與新字型，強化後的區塊看起來像另一個品牌，和整站格格不入。

```css
.pricing { background: #ff00e6; font-family: "Bebas Neue", sans-serif; }
```

## Rule 4 -- 放大系統既有的手法

**強度：SHOULD**

先找出頁面其他區塊已經用到、而目標區塊沒有用到的強烈手法（最大一級的標題字級、品牌的代表圖形、留白與節奏），把這些既有手法在目標區塊用到最強。強化後要更像同一個品牌，而不是不像。

### Good Example

這個範例沿用首頁已用過的最大字級 token 與品牌斜線圖形，套用到原本平淡的區塊。

```css
.testimonial__quote { font-size: var(--text-display); }
.testimonial::before { content: ""; background: var(--brand-slash-pattern); }
```

### Bad Example

這個範例為目標區塊自創一套全新的字級數值與圖形，雖然變醒目了，卻和頁面其他區塊脫節，看起來像拼貼進來的。

```css
.testimonial__quote { font-size: 4.37rem; }
.testimonial::before { background: radial-gradient(circle, #f0f 0%, transparent 70%); }
```

## Rule 5 -- 不以堆疊特效充當張力

**強度：MUST**

不得用增加陰影、光暈、漸層、模糊、動畫等特效來讓區塊「看起來更強」。張力要來自層級、尺寸對比與節奏。

### Good Example

這個範例以拉大標題與內文的尺寸差距、增加上下留白來製造張力。

```css
.feature-hero h2 { font-size: var(--text-display); }
.feature-hero p { font-size: var(--text-body); max-width: 40ch; }
.feature-hero { padding-block: var(--space-24); }
```

### Bad Example

這個範例在區塊上疊加光暈、多層陰影與脈動動畫，畫面變得吵雜，反而沒有任何一處真正突出。

```css
.feature-hero {
  box-shadow: 0 0 40px #6366f1, 0 20px 60px rgb(0 0 0 / 0.4);
  animation: pulse 2s infinite;
}
```

## Rule 6 -- 一個決定性的改變

**強度：SHOULD**

在目標區塊中選定一個最主要的改變並做到徹底，同時讓區塊內其他元素退後，使這個改變能被看清楚。不得把區塊內每個元素都同時加大加粗。

### Good Example

這個範例把數據大幅放大，同時把說明文字縮小變淡，讓數據成為唯一焦點。

```css
.stat__value { font-size: var(--text-display); font-weight: 800; }
.stat__label { font-size: var(--text-caption); color: var(--color-text-secondary); }
```

### Bad Example

這個範例把數據、說明與按鈕全部一起放大加粗，每個元素都在搶注意力，區塊反而變得更平。

```css
.stat__value, .stat__label, .stat__cta { font-size: 2rem; font-weight: 800; }
```

## Rule 7 -- 保留既有文案與主張

**強度：MUST**

目標區塊既有的文案、數據與主張屬於範圍的一部分，必須保留，除非使用者提供替換內容。強化方向需要真實證據（客戶名稱、數據、照片）而畫面沒有時，必須以白話向使用者索取，不得自行編造。

### Good Example

這個範例保留原本的文案，在需要真實數據時向使用者索取。

```text
這一區如果能放一個實際的成效數字會更有說服力，例如「已有多少家店在使用」。你們有可以公開的數字嗎？沒有的話我就維持現在的文字。
```

### Bad Example

這個範例為了讓區塊更有份量而自行加上虛構的數據，產品對外說出不實的宣稱。

```html
<p class="stat__value">10,000+</p>
<p class="stat__label">全球企業信賴使用</p>
```

## Rule 8 -- 結構本身要能表達重點

**強度：SHOULD**

把文案拿掉只看結構時，層級與系統的手法仍要能看出這個區塊是什麼、為什麼重要。張力不能只靠把字放大。需要圖片的位置要放能說明產品的真實內容（畫面截圖、成品照片），不放純裝飾的圖庫照片。

### Good Example

這個範例以大尺寸的產品實際畫面撐起區塊，結構本身就說明了重點。

```html
<section class="showcase">
  <h2 class="showcase__title">…</h2>
  <img class="showcase__screen" src="/img/dashboard-real.png" alt="報表頁面實際畫面" />
</section>
```

### Bad Example

這個範例只把標題放到極大，並配上與產品無關的圖庫照片，拿掉文字後結構什麼也說不出來。

```html
<section class="showcase">
  <h2 style="font-size: 7rem">…</h2>
  <img src="/img/stock-team-smiling.jpg" alt="" />
</section>
```

## Rule 9 -- 既有互動行為不變

**強度：MUST**

目標區塊中驅動動作的元素（按鈕、連結、表單、追蹤用的屬性）強化後必須維持相同的行為、目的地與可存取名稱。

### Good Example

這個範例只更換按鈕的 class，連結目的地與追蹤屬性保持不變。

```html
<a href="/signup" data-track="hero-cta" class="btn btn--lg">免費試用</a>
```

### Bad Example

這個範例重寫按鈕時把連結改成 `<div>` 並遺漏追蹤屬性，鍵盤無法操作，行銷數據也中斷了。

```html
<div class="btn btn--lg" onclick="location.href='/signup'">免費試用</div>
```
