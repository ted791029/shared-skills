# 驚喜規範

## Rule 1 -- 只在選定的時刻加入

**強度：MUST**

加入有個性的細節時，只能修改選定時刻相關的元件、文案與動態。其他區塊的配色、字體、版面不得更動，除非使用者明確要求。

### Good Example

這個範例只在完成首筆訂單的成功畫面加入專屬動態，其他畫面不受影響。

```css
.first-order-success__badge { animation: badge-settle 600ms cubic-bezier(0.25, 1, 0.5, 1) both; }
```

### Bad Example

這個範例為了增加趣味，把全站按鈕都加上晃動動畫並換成圓滾滾的字型，所有畫面的風格都被改掉。

```css
button { animation: wiggle 1s infinite; font-family: "Fredoka", sans-serif; }
```

## Rule 2 -- 只在值得的時刻加入

**強度：MUST**

驚喜只能放在有意義的時刻：首次使用、完成一件需要努力的事、從錯誤中恢復、熟練後發現實用的功能、需要等待的時候。不得為一般的點擊、切換分頁或例行儲存製造慶祝效果。

### Good Example

這個範例只在使用者完成整份申請時顯示祝賀，一般的欄位儲存只顯示簡短確認。

```jsx
{status === "application-submitted" && <Celebration />}
{status === "draft-saved" && <span className="hint">已儲存</span>}
```

### Bad Example

這個範例每次按下儲存都噴出彩帶，使用者一天要按幾十次，很快就覺得煩躁。

```jsx
<button onClick={() => { save(); fireConfetti(); }}>儲存</button>
```

## Rule 3 -- 反應強度與頻率成比例

**強度：SHOULD**

反應的強度要配合行為的頻率與重要性：重大里程碑可以有較大的反應，例行操作只需要讓人確定完成。重複的互動在第一百次時仍要令人舒服，變化只能在可預期的範圍內。

### Good Example

這個範例依里程碑大小分級，例行完成只換圖示，第一百筆才顯示較大的祝賀。

```js
const feedback = count === 100 ? "milestone" : "check";
```

### Bad Example

這個範例每完成一項待辦都跳出全螢幕祝賀，使用者每次都得關掉視窗才能繼續，驚喜變成阻礙。

```js
onTaskDone(() => openModal(<FullScreenCelebration />));
```

## Rule 4 -- 不得延遲或阻擋主要任務

**強度：MUST**

驚喜細節不得延遲、阻擋或遮住主要任務，必須可以略過。等待畫面要呈現真實的進度或有用的資訊，不得假裝在處理，也不得為了播放效果延後完成。

### Good Example

這個範例在上傳時顯示真實的進度與檔案名稱，完成後立即可以繼續操作。

```jsx
<p>正在上傳 {file.name}（{progress}%）</p>
```

### Bad Example

這個範例在資料已經回傳後，仍刻意等待 3 秒播完動畫才顯示結果，使用者白白多等。

```js
const data = await fetchReport();
await sleep(3000); // 讓動畫播完
render(data);
```

## Rule 5 -- 錯誤時先說問題與解法

**強度：MUST**

錯誤與恢復的時刻必須先說明發生了什麼問題、要怎麼解決。可以用溫暖的語氣降低壓力，但涉及金錢、資料遺失、隱私或工作被卡住時，不得開玩笑或使用俏皮語氣。

### Good Example

這個範例的付款失敗訊息先說問題與解法，語氣平穩。

```html
<p role="alert">付款沒有成功，卡片沒有被扣款。請確認卡號後再試一次，或改用其他付款方式。</p>
```

### Bad Example

這個範例在付款失敗時開玩笑，使用者正擔心錢有沒有被扣，卻看不到任何說明，只覺得被輕忽。

```html
<p>哎呀！錢包好像在鬧脾氣 🙈 晚點再試試吧～</p>
```

## Rule 6 -- 尊重減少動態與輔助技術

**強度：MUST**

驚喜用的動態必須在 `prefers-reduced-motion: reduce` 時關閉或改為不移動的呈現；非必要的循環動畫在不可見時停止。鍵盤、觸控與螢幕閱讀器使用者都要能正常完成任務，裝飾性動畫元素加上 `aria-hidden="true"`。

### Good Example

這個範例在使用者偏好減少動態時改為淡入，並把裝飾元素對螢幕閱讀器隱藏。

```css
.success-burst { animation: burst 500ms ease-out; }
@media (prefers-reduced-motion: reduce) {
  .success-burst { animation: fade-in 150ms linear; }
}
```

### Bad Example

這個範例的循環動畫不理會減少動態的設定，對動態敏感的使用者可能頭暈不適。

```css
.mascot { animation: bounce-around 2s infinite; }
```

## Rule 7 -- 聲音需經使用者同意

**強度：MUST**

不得在使用者未開啟的情況下自動播放聲音，必須遵守系統或頁面的靜音設定，並提供關閉的方式。

### Good Example

這個範例只在使用者於設定中開啟音效後才播放。

```js
if (settings.soundEnabled) successSound.play();
```

### Bad Example

這個範例在完成時直接播放音效，使用者在辦公室或會議中會突然發出聲音。

```js
onComplete(() => new Audio("/sfx/tada.mp3").play());
```

## Rule 8 -- 使用產品自己的語言

**強度：SHOULD**

有個性的文案必須用產品自己的詞彙與情境，讓相鄰產品無法原封不動拿去用。寧可清楚中性，也不要通用的俏皮話。

### Good Example

這個範例的空狀態文案使用記帳產品自己的情境，並帶出下一步。

```html
<p>這個月還沒有任何支出紀錄。拍下第一張發票，我們幫你自動分類。</p>
<button>拍發票</button>
```

### Bad Example

這個範例使用任何產品都能套用的俏皮話，沒有產品特色，也沒有告訴使用者下一步。

```html
<p>這裡空空的耶～ 🌵</p>
```

## Rule 9 -- 不加入未經要求的事實宣稱

**強度：MUST**

驚喜文案不得加入使用者沒有提供的事實或數據，例如排名、使用人數、節省的時間。

### Good Example

這個範例的完成訊息只描述使用者剛完成的事實。

```html
<p>本月 12 筆發票都分類好了。</p>
```

### Bad Example

這個範例自行加上「打敗 90% 的使用者」，產品沒有這項數據，等於對使用者說了不實的話。

```html
<p>本月發票都分類好了，你打敗了 90% 的使用者！</p>
```

## Rule 10 -- 依賴與資源成本要相稱

**強度：SHOULD**

不得為了單一時刻引入體積大的動畫函式庫或大型素材檔。能用 CSS 或少量 SVG 完成的效果，不加新的套件。

### Good Example

這個範例用 CSS 與一個小型 SVG 完成完成勾勾的動畫。

```css
.check path { stroke-dasharray: 24; stroke-dashoffset: 24; animation: draw 300ms ease-out forwards; }
@keyframes draw { to { stroke-dashoffset: 0; } }
```

### Bad Example

這個範例只為了一個完成動畫就安裝整套動畫播放器與大型動畫檔，頁面載入變慢，代價遠大於效果。

```bash
npm install lottie-web
# 另外加入 800KB 的 success.json 動畫檔
```

## Rule 11 -- 個性強度由 Claude 判斷

**強度：SHOULD**

品牌能表現多活潑或多嚴肅，由 Claude 依 PRODUCT.md 的產品性質、使用者與語氣自行判斷，不丟回給使用者決定。只有在無法判斷某個時刻的後果（例如是否涉及付款或刪除資料）這類產品事實時，才以白話詢問。

### Good Example

這個範例只詢問影響判斷的產品事實，語氣強度由 Claude 自行決定。

```text
想確認一件事：使用者按下「結束專案」之後，專案裡的資料會被刪除，還是只是封存、之後還能打開？
```

### Bad Example

這個範例把設計判斷丟給使用者，門外漢不知道怎麼回答，只能隨便選一個。

```text
請問你希望驚喜的程度是 playful、whimsical 還是 subtle？動畫要用 spring 還是 ease-out？
```
