# 版面規範

## Rule 1 -- 只調整版面結構

**強度：MUST**

單項改善版面時，只能修改元素的排列順序、分組、間距、欄數、尺寸與響應式結構。字型、字級、配色、文案與既有視覺風格維持原樣，除非使用者明確要求一併修改。

### Good Example

這個範例只調整間距與排列方式，原本的字型與顏色宣告保持不變。

```css
.pricing {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr));
  gap: var(--space-6);
  /* 原有的 font-family 與 color 未更動 */
}
```

### Bad Example

這個範例在改版面時順手把標題字型與主色換掉，使用者只要求調整排版，結果整個畫面的風格被改變，原本確認過的設計被推翻。

```css
.pricing {
  display: grid;
  gap: var(--space-6);
  font-family: "Playfair Display", serif;
  color: oklch(45% 0.18 280);
}
```

## Rule 2 -- 主從順序依產品優先順序

**強度：MUST**

畫面中最重要的元素（主要內容或主要任務）必須在尺寸、位置或留白上最先被看到，次要元素與各群組依序退後。把細節模糊後（瞇眼看），仍要能分辨出主要元素、次要元素與主要群組的先後。層級依產品優先順序決定，不沿用框架或範本的預設排列。

### Good Example

這個範例讓主要的結帳摘要占較大欄寬並排在前面，次要的推薦商品縮小退到側欄。

```css
.checkout {
  display: grid;
  grid-template-columns: minmax(0, 2fr) minmax(0, 1fr);
  gap: var(--space-8);
}
.checkout__summary { grid-column: 1; }
.checkout__recommend { grid-column: 2; font-size: var(--text-sm); }
```

### Bad Example

這個範例把主要摘要與推薦商品排成三等分欄位，瞇眼看時分不出哪一塊最重要，使用者找不到要完成的任務。

```css
.checkout {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
}
```

## Rule 3 -- 以距離分組而非加容器

**強度：SHOULD**

相關的元素彼此靠近，不同群組之間拉開距離，優先用間距表達分組。只有在間距不足以區分時才加上邊框、背景或卡片。

### Good Example

這個範例用群組內小間距、群組間大間距區分表單區段，不額外加外框。

```css
.form-section { display: flex; flex-direction: column; gap: var(--space-2); }
.form { display: flex; flex-direction: column; gap: var(--space-8); }
```

### Bad Example

這個範例每個區段都包一層有邊框和陰影的方框，但群組內外的間距相同，分組仍然靠框線硬撐，畫面變得擁擠又雜亂。

```css
.form-section {
  border: 1px solid var(--border);
  box-shadow: 0 2px 8px rgb(0 0 0 / 0.08);
  padding: var(--space-4);
  margin-bottom: var(--space-4);
}
```

## Rule 4 -- 間距使用固定級距

**強度：MUST**

所有間距必須取自專案既有的間距級距（token 或設計系統變數）。專案沒有級距時，建立以 4px 為基數的級距（例如 4、8、12、16、24、32、48、64），不得出現 13px、27px 這類單次使用的數值。

### Good Example

這個範例的間距全部引用以 4px 為基數的級距變數。

```css
:root {
  --space-1: 4px; --space-2: 8px; --space-3: 12px;
  --space-4: 16px; --space-6: 24px; --space-8: 32px;
}
.card { padding: var(--space-4) var(--space-6); }
```

### Bad Example

這個範例寫入 13px、27px 等任意數值，間距無法在各畫面之間保持一致，之後調整時也無從統一。

```css
.card { padding: 13px 27px; margin-bottom: 19px; }
```

## Rule 5 -- 間距要有鬆緊節奏

**強度：SHOULD**

群組內使用緊的間距，群組之間使用寬的間距，標題上方的留白大於標題下方，讓鬆緊對比形成節奏。不得全畫面重複同一個間距值，讓所有元素看起來份量相同。

### Good Example

這個範例讓標題上方留白大於下方，標題與所屬內文靠近、與上一區段分開。

```css
.section + .section { margin-top: var(--space-16); }
.section h2 { margin-top: var(--space-12); margin-bottom: var(--space-3); }
```

### Bad Example

這個範例所有元素一律使用 16px 間距，標題與上下內容距離相同，讀者看不出標題屬於哪一段。

```css
.section > * { margin: 16px 0; }
```

## Rule 6 -- 重複卡片只用於同等內容

**強度：SHOULD**

只有在內容真的彼此同等（例如商品列表）時才用一排相同的卡片。預設避免以「圖示＋標題＋一段文字」的同尺寸卡片當作整頁的主結構，除非使用者需求明確要求。

### Good Example

這個範例把功能介紹改為一個主要功能搭配較小的次要功能列表，依重要性排出差異。

```html
<section class="features">
  <article class="feature feature--lead">…主要功能與示意…</article>
  <ul class="feature-list">
    <li>匯出報表</li>
    <li>排程寄送</li>
  </ul>
</section>
```

### Bad Example

這個範例把重要性不同的功能都放進三張同尺寸的圖示卡片，畫面變成千篇一律的範本，讀者分不出哪個功能最重要。

```html
<div class="grid-3">
  <div class="card"><svg>…</svg><h3>快速</h3><p>…</p></div>
  <div class="card"><svg>…</svg><h3>安全</h3><p>…</p></div>
  <div class="card"><svg>…</svg><h3>簡單</h3><p>…</p></div>
</div>
```

## Rule 7 -- 禁止巢狀卡片

**強度：MUST**

卡片內不得再放卡片。內層需要分組時改用間距、分隔線或標題。

### Good Example

這個範例在卡片內以間距與分隔線區分子區塊。

```html
<article class="card">
  <h3>訂單摘要</h3>
  <dl class="summary">…</dl>
  <hr class="divider" />
  <dl class="summary">…</dl>
</article>
```

### Bad Example

這個範例在卡片裡再包一層帶邊框與陰影的卡片，形成框中框，層級混亂且浪費空間。

```html
<article class="card">
  <h3>訂單摘要</h3>
  <div class="card card--inner">…</div>
</article>
```

## Rule 8 -- 響應式以結構調整

**強度：MUST**

在窄、中、寬三種寬度下，必須依內容重要性重新排列、收合或換行，而不是只把同一個版面等比縮小。窄寬度時重要內容要排在前面，不得出現水平捲動。

### Good Example

這個範例在窄寬度改為單欄、把主要內容排在前面，寬螢幕才展開側欄。

```css
.layout { display: grid; gap: var(--space-6); }
@media (min-width: 64rem) {
  .layout { grid-template-columns: minmax(0, 1fr) 20rem; }
}
```

### Bad Example

這個範例在所有寬度都固定三欄，手機上每欄被擠到只剩幾個字寬，還出現水平捲動。

```css
.layout { display: grid; grid-template-columns: 400px 400px 400px; }
```

## Rule 9 -- 視覺順序與 DOM 順序一致

**強度：MUST**

鍵盤 Tab 順序、螢幕閱讀器讀取順序必須與畫面上的視覺順序一致。不得用 `order`、`flex-direction: row-reverse` 或絕對定位讓視覺順序與 DOM 順序相反；需要不同順序時直接調整 DOM。

### Good Example

這個範例直接在 HTML 中把主要按鈕排在前面，視覺與鍵盤順序相同。

```html
<div class="actions">
  <button class="btn-primary">送出</button>
  <button class="btn-secondary">取消</button>
</div>
```

### Bad Example

這個範例用 `order` 把取消按鈕移到畫面前方，鍵盤使用者按 Tab 時焦點跳動順序與看到的不同，容易按錯。

```css
.actions .btn-secondary { order: -1; }
```

## Rule 10 -- 兄弟元素間距用 gap

**強度：SHOULD**

同一容器內相鄰元素的間距使用 `gap`，不在子元素上各自加 `margin` 再用 `:last-child` 抵銷。

### Good Example

這個範例由容器的 `gap` 統一控制列表項目間距。

```css
.tag-list { display: flex; flex-wrap: wrap; gap: var(--space-2); }
```

### Bad Example

這個範例在每個子元素加右邊距，換行後第一欄與最後一欄的距離不一致，還得額外寫規則抵銷。

```css
.tag-list > * { margin-right: 8px; margin-bottom: 8px; }
.tag-list > *:last-child { margin-right: 0; }
```

## Rule 11 -- 觸控範圍不因圖示小而縮小

**強度：MUST**

可點擊元素的點擊範圍至少 44×44px，即使看得到的圖示或文字較小，也要用 padding 或偽元素擴大點擊範圍。

### Good Example

這個範例的圖示只有 16px，但按鈕本身有 44px 的最小尺寸。

```css
.icon-btn {
  min-width: 44px;
  min-height: 44px;
  display: inline-grid;
  place-items: center;
}
.icon-btn svg { width: 16px; height: 16px; }
```

### Bad Example

這個範例的關閉按鈕只有 16×16px，手機使用者很難點中，常常誤觸旁邊的元素。

```css
.close-btn { width: 16px; height: 16px; padding: 0; }
```

## Rule 12 -- 以極端內容確認結構

**強度：MUST**

完成後必須以實測截圖或讀原型逐條確認：很長的文字、空的清單、翻譯後變長的字串、放大到 200% 與固定（sticky）元素出現時，版面不會溢出、重疊或被截斷。容器要允許換行或設定 `min-width: 0`，不得用固定高度裝可變長度的內容。

### Good Example

這個範例讓 grid 子項可以縮小並允許長字串斷行，長商品名稱不會撐破版面。

```css
.product-row { display: grid; grid-template-columns: minmax(0, 1fr) auto; }
.product-row__name { overflow-wrap: anywhere; }
```

### Bad Example

這個範例把名稱欄設為固定高度並隱藏溢出，商品名稱一長就被截掉，使用者看不到完整內容。

```css
.product-row__name { height: 24px; overflow: hidden; white-space: nowrap; }
```
