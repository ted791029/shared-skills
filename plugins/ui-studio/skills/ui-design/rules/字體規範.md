# 字體規範

## Rule 1 -- 只調整字體

**強度：MUST**

單項改善字體時，只能修改字型、字級、字重、行高、字距、行長、斷行與字型載入方式。配色、版面結構與文案維持原樣，除非使用者明確要求一併修改。專案已確認的字型家族必須保留並改善用法，不得自行換成另一套字型。

### Good Example

這個範例保留原有的字型家族，只調整字級、行高與行長。

```css
.article {
  font-family: var(--font-body); /* 沿用原本的字型 */
  font-size: 1.0625rem;
  line-height: 1.65;
  max-width: 68ch;
}
```

### Bad Example

這個範例在調整行高時把字型換成另一套、背景色也一起改掉，使用者只要求改善閱讀感，結果品牌原有的字體與配色被推翻。

```css
.article {
  font-family: "Inter", sans-serif;
  line-height: 1.65;
  background: oklch(97% 0.01 90);
}
```

## Rule 2 -- 內文字級不低於 16px

**強度：MUST**

網頁內文字級至少 `1rem`（16px）。只有資料密集的表格、標註等特定角色，或平台慣例另有規定時才可更小。

### Good Example

這個範例的內文使用 `1rem`，只有表格內的輔助標註使用較小字級。

```css
body { font-size: 1rem; }
.data-table .note { font-size: 0.8125rem; }
```

### Bad Example

這個範例把整頁內文設為 13px，一般使用者閱讀吃力，長時間閱讀容易疲勞。

```css
body { font-size: 13px; }
```

## Rule 3 -- 內文行長 45 到 75 字元

**強度：MUST**

段落文字的行寬必須介於 `45ch` 到 `75ch`；文章、說明文件等長篇閱讀的正文以 `65ch` 到 `75ch` 為準。行寬較寬時行高要加大，行寬較窄時行高可略降。

### Good Example

這個範例限制文章段落最寬 `70ch`，並配合較寬的行寬使用 1.7 的行高。

```css
.prose p { max-width: 70ch; line-height: 1.7; }
```

### Bad Example

這個範例讓段落撐滿整個寬螢幕，一行超過一百多個字，讀者換行時容易找錯下一行。

```css
.prose p { width: 100%; line-height: 1.4; }
```

## Rule 4 -- 文字角色層級分明

**強度：MUST**

標題、內文、標籤、輔助說明、數據等角色必須不用讀內容就能分辨。相鄰角色的字級比例至少 1.2 倍，或同時以字重、間距、明暗拉開差異，不得只差 1～2px。同一角色在所有畫面與狀態中使用相同的設定，並以用途命名 token。

### Good Example

這個範例建立一組以用途命名的字級，相鄰層級的比例約 1.25 倍。

```css
:root {
  --text-caption: 0.8rem;
  --text-body: 1rem;
  --text-subtitle: 1.25rem;
  --text-title: 1.563rem;
  --text-display: 2.441rem;
}
```

### Bad Example

這個範例的副標與內文只差 1px、字重也相同，讀者分不出哪一行是副標，層級形同虛設。

```css
.subtitle { font-size: 17px; font-weight: 400; }
.body { font-size: 16px; font-weight: 400; }
```

## Rule 5 -- 大標題字級與字距上限

**強度：MUST**

展示用大標題字級不得超過 `6rem`，字距（`letter-spacing`）不得小於 `-0.04em`。行銷頁大標題可以用 `clamp()` 隨寬度縮放；產品介面與閱讀頁的字級保持固定，不隨視窗寬度變動。

### Good Example

這個範例的行銷頁大標題以 `clamp()` 縮放，上限 `6rem`，字距控制在 `-0.03em`。

```css
.hero-title {
  font-size: clamp(2.5rem, 6vw, 6rem);
  letter-spacing: -0.03em;
}
```

### Bad Example

這個範例的標題寬螢幕上放大到 10rem、字距壓到 -0.08em，字母互相黏在一起，手機上也會溢出畫面。

```css
.hero-title { font-size: 10rem; letter-spacing: -0.08em; }
```

## Rule 6 -- 字型家族越少越好

**強度：SHOULD**

使用能讓層級清楚的最少字型家族，通常一到兩套。加入第二套字型時，它必須承擔第一套做不到的角色（例如程式碼、展示標題），不得只為了「看起來比較豐富」而增加。等寬字型只用於程式碼、數據或量測值，不當成「科技感」的裝飾。

### Good Example

這個範例內文與標題共用一套字型，只有程式碼區塊另用等寬字型。

```css
:root {
  --font-ui: "Noto Sans TC", sans-serif;
  --font-code: "JetBrains Mono", monospace;
}
body, h1, h2 { font-family: var(--font-ui); }
code, pre { font-family: var(--font-code); }
```

### Bad Example

這個範例同一頁用了三套字型，並把等寬字型拿來排一般標題，風格互相打架，等寬字型也失去代表程式碼的意義。

```css
h1 { font-family: "Space Mono", monospace; }
h2 { font-family: "Lora", serif; }
body { font-family: "Poppins", sans-serif; }
```

## Rule 7 -- 字型必須實際引入

**強度：MUST**

指定的字型必須從 Google Fonts 等字型來源以 `<link>` 或 `@font-face` 引入。展示標題不得用 Impact、Arial Black 或系統預設字型充數，也不得在找不到指定字型時改用電腦裡最接近的字型。

### Good Example

這個範例以 `<link>` 從 Google Fonts 引入標題字型，CSS 中才引用。

```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link href="https://fonts.googleapis.com/css2?family=Fraunces:wght@600;800&display=swap" rel="stylesheet" />
<style>
  h1 { font-family: "Fraunces", Georgia, serif; }
</style>
```

### Bad Example

這個範例在 CSS 寫了字型名稱卻沒有引入，大部分使用者的電腦沒有這套字型，實際顯示的是系統預設字型，設計意圖完全落空。

```css
h1 { font-family: "Fraunces", Impact, sans-serif; }
```

## Rule 8 -- 只載入用到的字重並避免隱形文字

**強度：SHOULD**

只載入畫面實際用到的字重與字型檔。`@font-face` 必須設定 `font-display: swap`，並提供字形尺寸相近的後備字型，避免字型載入前文字看不見或載入後版面跳動。

### Good Example

這個範例只載入 400 與 700 兩個字重，並設定 `font-display: swap` 與後備字型。

```css
@font-face {
  font-family: "Brand Sans";
  src: url("/fonts/brand-sans-400.woff2") format("woff2");
  font-weight: 400;
  font-display: swap;
}
body { font-family: "Brand Sans", "Helvetica Neue", Arial, sans-serif; }
```

### Bad Example

這個範例一次載入九個字重卻只用到兩個，也沒有設定 `font-display`，網路慢時文字長時間空白，載入完成後整頁又跳動一次。

```html
<link href="https://fonts.googleapis.com/css2?family=Brand+Sans:wght@100;200;300;400;500;600;700;800;900" rel="stylesheet" />
```

## Rule 9 -- 深色底淺色字要補償

**強度：SHOULD**

深色背景上的淺色文字要同時略增行高（約 +0.05～0.1）、略增字距（約 +0.01em），字型顯得太細時再加一階字重。

### Good Example

這個範例在深色區塊略增行高、字距與字重。

```css
.dark-panel p {
  line-height: 1.75;   /* 淺色底為 1.65 */
  letter-spacing: 0.01em;
  font-weight: 450;    /* 淺色底為 400 */
}
```

### Bad Example

這個範例把淺色底的文字設定原封不動用在深色底，細字在深色背景上發散、顯得更細，閱讀吃力。

```css
.dark-panel p { line-height: 1.5; font-weight: 300; }
```

## Rule 10 -- 標題與內文的斷行設定

**強度：SHOULD**

標題與短的置中文字設定 `text-wrap: balance`，內文設定 `text-wrap: pretty`。手動斷行（`<br>`）只能放在詞組之間，且必須確認在每個顯示寬度下都不會斷在行中間。

### Good Example

這個範例以 CSS 讓標題各行平均、內文避免最後一行只剩一個字。

```css
h1, h2, .hero-tagline { text-wrap: balance; }
p { text-wrap: pretty; }
```

### Bad Example

這個範例在標題中間硬塞 `<br>`，寬螢幕上看起來正常，到手機上卻變成一行只剩一個字的破碎斷行。

```html
<h1>讓每一筆訂單<br>都準時出貨</h1>
```

## Rule 11 -- 保留使用者的文字縮放

**強度：MUST**

字級使用 `rem` 等可隨使用者設定縮放的單位，不得在 viewport 設定 `maximum-scale=1` 或 `user-scalable=no`，也不得用固定高度的容器裝文字，導致放大後文字被截斷。

### Good Example

這個範例的 viewport 允許縮放，字級以 `rem` 設定。

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<style>.label { font-size: 0.875rem; }</style>
```

### Bad Example

這個範例鎖住縮放，視力不佳的使用者無法放大文字閱讀。

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no" />
```

## Rule 12 -- 數字使用等寬數字

**強度：MAY**

表格、價格、計時器等需要上下對齊或會跳動的數字，可設定 `font-variant-numeric: tabular-nums`。

### Good Example

這個範例讓金額欄的數字等寬，上下列的位數對齊。

```css
.amount { font-variant-numeric: tabular-nums; text-align: right; }
```

### Bad Example

這個範例的倒數計時器使用比例數字，每秒數字寬度改變，整行文字跟著左右抖動。

```css
.countdown { font-variant-numeric: proportional-nums; }
```

## Rule 13 -- 搜尋字體只在需要換字型時

**強度：MUST**

單項改善字體時，只有在專案沒有已確認的字型家族，或使用者明確要求更換字型時，才搜尋字體搭配的候選；搜尋到的候選依視覺方向規範 Rule 11 篩選。專案已有確認的字型時，只改善用法，不搜尋也不更換。

### Good Example

這個範例的專案已有確認的字型，只調整字級與行高，沒有搜尋。

```text
既有字型：Noto Sans TC（DESIGN.md 已確認）
改善：內文行高 1.4 → 1.6、標題字距收緊，不搜尋字體搭配
```

### Bad Example

這個範例在已有確認字型的專案中搜尋並換成另一套字型，使用者只想讓文字好讀一點，整個產品的字體氣質卻被改掉。

```text
既有字型：Noto Sans TC（DESIGN.md 已確認）
搜尋 typography "friendly readable" → 換成 Nunito + Inter
```
