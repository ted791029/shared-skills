# 品質底線規範

## Rule 1 -- 文字對比必須達門檻

**強度：MUST**

一般內文與 placeholder 文字對背景的對比必須至少 4.5:1，大字（24px 以上，或 18.66px 以上且粗體）與介面元件（按鈕邊框、圖示、focus 外框）至少 3:1，數值以實測的渲染後對比為準，圖示、元件邊框、疊在圖片上的文字與未實測時以對比檢查腳本的計算結果為準。放在有色底上的次要文字，顏色必須從該底色的色相或前景色調出，不得直接用中性灰。

### Good Example

這個範例的內文與 placeholder 都使用高對比色，藍色底上的次要文字從同一色相調亮，而不是套用灰色。

```css
:root {
  --surface: oklch(98% 0.01 250);
  --text: oklch(25% 0.02 250);
  --text-placeholder: oklch(45% 0.02 250);
}
.banner { background: oklch(45% 0.15 255); color: oklch(98% 0.01 255); }
.banner .meta { color: oklch(88% 0.05 255); }
```

### Bad Example

這個範例把 placeholder 設成淺灰、在藍色底上用灰色次要文字，對比低於 4.5:1，弱視使用者讀不到提示，灰字在彩色底上也顯得髒。

```css
input::placeholder { color: #c4c4c4; }
.banner { background: #2457c5; }
.banner .meta { color: #9a9a9a; }
```

## Rule 2 -- 陰影必須有位移與柔和模糊

**強度：SHOULD**

用來表達層次的 `box-shadow` 必須同時有垂直位移與柔和的模糊半徑。位移為 0 的彩色光暈只是裝飾，不得當作層次手段。

### Good Example

這個範例的陰影帶有向下位移與漸層模糊，讀者能感受到卡片浮在底面上方。

```css
.popover {
  box-shadow:
    0 1px 2px oklch(20% 0.02 250 / 0.08),
    0 8px 24px oklch(20% 0.02 250 / 0.12);
}
```

### Bad Example

這個範例用零位移的紫色光暈代替陰影，元素沒有前後層次，只是在周圍發光，畫面看起來像套用了現成模板。

```css
.popover {
  box-shadow: 0 0 24px rgba(139, 92, 246, 0.6);
}
```

## Rule 3 -- 間距必須組內緊、組間寬

**強度：SHOULD**

同一組相關元素之間的間距必須明顯小於不同組之間的間距，標題上方的空間必須大於標題下方的空間。檢查時讀 CSS 中實際套用的 margin、padding、gap 值逐一比對，不憑印象判斷。

### Good Example

這個範例的欄位與標籤只隔 0.375rem，不同欄位組隔 2rem，標題上方 3rem、下方 0.75rem，標題明確屬於下方內容。

```css
.field { display: grid; gap: 0.375rem; }
.form-section { display: grid; gap: 2rem; }
.form-section h2 { margin-block: 3rem 0.75rem; }
```

### Bad Example

這個範例所有間距都是 1rem，標題上下等距，讀者分不出標題屬於上一段還是下一段，欄位分組也看不出來。

```css
.field, .form-section { display: grid; gap: 1rem; }
.form-section h2 { margin: 1rem 0; }
```

## Rule 4 -- 字體量尺必須符合門檻

**強度：SHOULD**

內文行寬必須在 45–75ch，長篇閱讀的正文在 65–75ch，大標題字級最大 6rem，`letter-spacing` 不得低於 -0.04em，標題使用 `text-wrap: balance`，字級與字重的級距要一眼看得出差別。必須以真實文案讀過每個斷點的樣式，確認沒有文字溢出或被截斷。

### Good Example

這個範例限制內文行寬、大標題用 `clamp()` 封頂在 6rem，字距不低於下限，標題啟用平衡換行，窄螢幕縮小字級避免長標題溢出。

```css
.article p { max-width: 70ch; }
h1 {
  font-size: clamp(2.5rem, 6vw, 6rem);
  letter-spacing: -0.03em;
  text-wrap: balance;
}
@media (max-width: 480px) { h1 { font-size: 2.25rem; } }
```

### Bad Example

這個範例內文沒有行寬上限、大標題 9rem 且字距壓到 -0.08em，寬螢幕一行超過一百字難以閱讀，字母黏在一起，手機上長標題直接溢出畫面。

```css
.article p { max-width: none; }
h1 { font-size: 9rem; letter-spacing: -0.08em; white-space: nowrap; }
```

## Rule 5 -- 動態只能有一個設計過的時刻

**強度：SHOULD**

整個畫面只安排一個經過設計的動態時刻，不得到處散落效果，也不得讓每個區塊套用同一個進場動畫。時長與曲線依動態規範 Rule 4（減速曲線，焦點進場至多 800ms），元素的預設狀態必須已經可見（動畫失效時內容仍在）。除了 `transform` 與 `opacity`，在保持流暢的前提下也可以使用 `filter: blur()`、`backdrop-filter`、`clip-path`、`mask` 與陰影。

### Good Example

這個範例只讓首屏主視覺以 `clip-path` 展開，時長在焦點進場的範圍內並使用減速曲線，元素預設可見，並提供減少動態的替代。

```css
.hero-visual { clip-path: inset(0 0 0 0); }
@media (prefers-reduced-motion: no-preference) {
  .hero-visual { animation: reveal 700ms cubic-bezier(0.16, 1, 0.3, 1) both; }
}
@keyframes reveal { from { clip-path: inset(0 0 100% 0); } }
```

### Bad Example

這個範例讓所有區塊都從透明淡入上移，預設狀態是 `opacity: 0`，畫面每一段都在動、沒有重點，腳本失效時整頁內容是空白。

```css
section { opacity: 0; transform: translateY(40px); transition: all 0.6s ease; }
section.in-view { opacity: 1; transform: none; }
```

## Rule 6 -- 互動狀態必須完整

**強度：MUST**

每個互動元件都必須有 hover、disabled、loading、error、empty 狀態，鍵盤操作時必須有可見的 focus 樣式。畫面必須使用真實內容、控制項必須真的能操作、版面在各斷點都要成立。檢查時逐一找出程式碼中對應每個狀態的樣式或分支。

### Good Example

這個範例的按鈕有 hover、focus、disabled 與 loading 樣式，清單在沒有資料時顯示空狀態並提供下一步。

```jsx
<button className="btn" disabled={saving} aria-busy={saving}>
  {saving ? <Spinner /> : null}
  {saving ? '儲存中…' : '儲存變更'}
</button>
{items.length === 0
  ? <EmptyState title="還沒有任何專案" action={<a href="/projects/new">建立第一個專案</a>} />
  : <ProjectList items={items} />}
```

### Bad Example

這個範例只寫了預設樣式，送出時沒有 loading、失敗時沒有錯誤訊息、沒有資料時一片空白，使用者重複點擊按鈕也不知道是否成功。

```jsx
<button className="btn" onClick={save}>Submit</button>
<ProjectList items={items} />
```

## Rule 7 -- 瀏覽器預設外觀必須主題化

**強度：SHOULD**

不是自己畫的瀏覽器元件也必須套用設計的色彩：文字選取（`::selection`）、輸入游標（`caret-color`）、自訂捲軸、focus 外框、連結底線位移（`text-underline-offset`），以及表格數字（`font-variant-numeric: tabular-nums`）都要從配色 token 設定，不得維持瀏覽器預設。

### Good Example

這個範例把選取、游標、捲軸、focus 外框、底線位移與表格數字全部接上配色 token。

```css
::selection { background: var(--accent-soft); color: var(--text); }
:root { caret-color: var(--accent); scrollbar-color: var(--border-strong) transparent; }
:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }
a { text-underline-offset: 0.2em; }
table td { font-variant-numeric: tabular-nums; }
```

### Bad Example

這個範例只設定了品牌色按鈕，選取文字仍是瀏覽器預設的藍底、focus 外框被移除、表格數字寬度不一，畫面細節露出「拼湊而成」的痕跡，鍵盤使用者也找不到目前位置。

```css
.btn-primary { background: var(--accent); }
*:focus { outline: none; }
```

## Rule 8 -- 文案必須說出動作與恢復方法

**強度：MUST**

文案使用產品自己的語言。按鈕與連結必須寫出按下後會發生的動作，錯誤訊息必須同時寫出發生了什麼問題以及使用者可以怎麼做。

### Good Example

這個範例的按鈕寫出具體動作，錯誤訊息說明原因並提供恢復方式。

```jsx
<button type="submit">寄出邀請</button>
<p role="alert">邀請沒有寄出：這個 Email 已經是團隊成員。請改輸入其他 Email。</p>
```

### Bad Example

這個範例的按鈕只寫「確定」、錯誤只寫「發生錯誤」，使用者不知道按下會做什麼，也不知道失敗後該怎麼辦。

```jsx
<button type="submit">確定</button>
<p role="alert">發生錯誤</p>
```

## Rule 9 -- 需求項目必須全部涵蓋

**強度：MUST**

使用者需求中的每一項都必須出現在畫面上，而且使用者在幾秒內就能找到。完成前逐條對照需求與程式碼，標出每項需求對應的元件。

### Good Example

這個範例在完成前逐條列出需求對應的元件，確認沒有遺漏，也沒有藏在需要多次點擊才找得到的位置。

```text
需求 1「可依日期篩選訂單」 → OrderFilters.tsx 的 <DateRangePicker>，位於列表上方
需求 2「可匯出 CSV」     → OrderToolbar.tsx 的「匯出 CSV」按鈕，位於列表右上
需求 3「顯示退款狀態」   → OrderRow.tsx 的狀態欄
```

### Bad Example

這個範例宣稱完成，但匯出功能只放在「更多」選單的第二層，退款狀態沒有實作，使用者找不到或根本沒有需求中的功能。

```text
已完成訂單列表頁面，包含篩選、匯出與狀態顯示。
（實際：匯出藏在「更多 > 進階 > 匯出」，退款狀態欄未實作）
```

## Rule 10 -- 禁止標題上方的小標籤

**強度：MUST**

標題上方不得放 eyebrow／kicker 小標籤（例如大寫小字、加寬字距的分類文字）。這是絕對禁止的作法，任何需求都不例外；標題本身要承擔份量，刪掉小標籤，讓標題直接說話。

### Good Example

這個範例只保留標題與說明文字，標題自己傳達重點。

```html
<section class="features">
  <h2>每天少花一小時對帳</h2>
  <p>銀行明細匯入後自動比對發票，只把對不上的項目留給你。</p>
</section>
```

### Bad Example

這個範例在標題上方加了大寫加寬字距的小標籤，是一眼就能認出的模板痕跡，也分散了標題的份量。

```html
<section class="features">
  <span class="eyebrow">FEATURES</span>
  <h2>每天少花一小時對帳</h2>
</section>
```

## Rule 11 -- 避免預設的頁面骨架

**強度：SHOULD**

需求沒有明確要求時，不得使用下列頁面骨架；發現時必須改寫該元素的結構，不是把效果調淡：

- 以「圖示＋標題＋文字」組成的等大卡片當作頁面主結構。
- hero-metric 樣板：大數字、小標籤、幾個輔助數據加一個強調色。
- 區段編號（01／02／03），除非順序本身是讀者需要的資訊。
- 用 modal 承載不需要打斷流程、也不需要鎖定焦點的任務。

### Good Example

這個範例以內容本身的結構排版：步驟清單用有序列表，因為順序是讀者需要的資訊；編輯個人資料在原頁面展開，不開 modal。

```html
<ol class="setup-steps">
  <li><h3>連結銀行帳戶</h3><p>選擇你的銀行並登入授權。</p></li>
  <li><h3>匯入發票</h3><p>上傳本月的電子發票檔。</p></li>
</ol>
<details class="profile-edit">
  <summary>編輯個人資料</summary>
  <form>…</form>
</details>
```

### Bad Example

這個範例把功能介紹做成三張等大圖示卡片，並加上與順序無關的 01／02／03，頁面看起來和任何模板網站一模一樣。

```html
<div class="grid-3">
  <div class="card"><span>01</span><Icon/><h3>快速</h3><p>…</p></div>
  <div class="card"><span>02</span><Icon/><h3>安全</h3><p>…</p></div>
  <div class="card"><span>03</span><Icon/><h3>簡單</h3><p>…</p></div>
</div>
```

## Rule 12 -- 避免預設的表面裝飾

**強度：SHOULD**

需求沒有明確要求時，不得使用下列表面裝飾；發現時必須改寫元素，不是把效果調淡：

- 漸層文字；強調改用字重或字級。
- 純裝飾用途的玻璃與模糊效果。
- 圓角框單側的色條（單邊 border、inset 陰影或偽元素），任何顏色或狀態都一樣；改用完整邊框、底色或前置圖示與文字標籤。
- 硬位移陰影（`box-shadow: 4px 4px 0`），除非整個視覺方向本來就是 neobrutalism。
- 用 sparkline、進度環、柔陰影圓角方塊填充版面，代替真正的內容。
- 用 monospace 字體扮演「技術感」，而不是用在程式碼、資料或量測值上。
- 用圓形、多邊形或 radial-gradient 遮罩粗略模擬照片主體的輪廓；改用從圖片本身取得的透明遮罩或去背素材，做不到就不做。

### Good Example

這個範例的提醒框用完整邊框與淺底色加上前置圖示，強調文字用字重，monospace 只用在訂單編號。

```css
.notice { border: 1px solid var(--warning-border); background: var(--warning-soft); border-radius: 8px; }
.notice svg { color: var(--warning); }
.headline strong { font-weight: 700; }
.order-id { font-family: var(--font-mono); }
```

### Bad Example

這個範例的標題用漸層文字、提醒框用左側色條、卡片用硬位移陰影，三種都是類別預設樣式，畫面看起來像 AI 套版而不是為這個產品設計。

```css
.headline { background: linear-gradient(90deg, #6366f1, #ec4899); -webkit-background-clip: text; color: transparent; }
.notice { border-left: 4px solid #f59e0b; border-radius: 8px; }
.card { box-shadow: 4px 4px 0 #000; }
```

## Rule 13 -- 大標題不得用系統字體充數

**強度：SHOULD**

有自己視覺方向的頁面，大標題字體不得使用系統字體（Impact、Arial Black、平台預設 sans-serif）。必須挑選氣質符合視覺方向的字體，從 Google Fonts 等字型來源以 `<link>` 或 `@font-face` 引入；用電腦上剛好裝了的相近字體代替，視為不合格。

### Good Example

這個範例從 Google Fonts 引入符合視覺方向的標題字體，並設定後備字體。

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link href="https://fonts.googleapis.com/css2?family=Fraunces:opsz,wght@9..144,600&display=swap" rel="stylesheet">
<style>
  h1, h2 { font-family: "Fraunces", Georgia, serif; }
</style>
```

### Bad Example

這個範例直接用 Impact 當大標題字體，沒有引入任何字型，標題氣質和視覺方向無關，在沒有安裝該字體的裝置上還會退回別的字。

```css
h1, h2 { font-family: Impact, "Arial Black", sans-serif; }
```

## Rule 14 -- 圖示不得用 emoji 或符號代替

**強度：SHOULD**

圖示必須來自正式的圖示庫或自繪 SVG，全站使用一致的線條粗細與風格，不得用 emoji 或 Unicode 符號充當圖示系統。

### Good Example

這個範例使用同一套圖示庫，線條粗細一致，並標示裝飾性圖示不需朗讀。

```jsx
import { Bell, Settings } from 'lucide-react';

<Bell size={20} strokeWidth={1.75} aria-hidden="true" />
<Settings size={20} strokeWidth={1.75} aria-hidden="true" />
```

### Bad Example

這個範例用 emoji 當導覽圖示，各平台顯示不一、無法跟隨配色，螢幕閱讀器還會念出「鈴鐺」「齒輪」等多餘文字。

```jsx
<a href="/notifications">🔔 通知</a>
<a href="/settings">⚙️ 設定</a>
```

## Rule 15 -- 亮色或暗色依使用情境決定

**強度：SHOULD**

亮色或暗色主題必須依使用情境決定：誰在用、在哪裡用、周圍光線如何，不得依產品類別套用刻板印象（例如「開發工具就用暗色」）。決定的理由要能從產品背景中找到依據。

### Good Example

這個範例依使用情境決定主題：診所櫃檯在明亮室內長時間操作，因此用亮色底。

```css
/* 使用情境：診所櫃檯人員白天在明亮室內使用，因此預設亮色 */
:root { --surface: oklch(99% 0.005 90); --text: oklch(22% 0.01 90); }
```

### Bad Example

這個範例只因為產品是「數據分析工具」就預設暗色，沒有考慮使用者在明亮辦公室長時間閱讀報表，深色底反而增加眼睛負擔。

```css
/* 分析工具都用暗色比較專業 */
:root { --surface: #0b0b0f; --text: #e5e5e5; }
```

## Rule 16 -- 禁止巢狀卡片

**強度：MUST**

卡片內不得再放卡片（帶邊框、底色或陰影的容器）。這一條沒有例外，需求的措辭也不能讓它成立；內層需要分組時改用間距、分隔線或小標題。

### Good Example

這個範例在設定卡片內以小標題與分隔線區分兩組選項，沒有第二層容器。

```html
<section class="card">
  <h3>通知</h3>
  <label><input type="checkbox" /> Email 通知</label>
  <hr class="divider" />
  <h4>提醒時間</h4>
  <select>…</select>
</section>
```

### Bad Example

這個範例在設定卡片內再包一層帶邊框與陰影的卡片，形成框中框，層級變得混亂並浪費空間，畫面也帶有明顯的套版感。

```html
<section class="card">
  <h3>通知</h3>
  <div class="card shadow">
    <label><input type="checkbox" /> Email 通知</label>
  </div>
</section>
```
