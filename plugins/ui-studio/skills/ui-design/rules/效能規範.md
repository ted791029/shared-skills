# 效能規範

## Rule 1 -- 只改效能不犧牲功能與無障礙

**強度：MUST**

效能改善只能修改影響載入與執行速度的程式碼，不得改變畫面外觀、文案或功能。不得為了速度移除替代文字、焦點樣式、鍵盤操作等無障礙支援，也不得讓既有功能失效。

### Good Example

這個範例把大圖換成較小的 WebP，畫面外觀與替代文字都不變。

```html
<img src="product-800.webp" width="800" height="800" alt="不鏽鋼保溫瓶，霧面黑">
```

### Bad Example

這個範例為了減少繪製而移除所有焦點外框，鍵盤使用者再也看不到目前停在哪個按鈕，無法操作頁面。

```css
*:focus { outline: none; }
```

## Rule 2 -- 先找出真正的瓶頸

**強度：MUST**

動手前必須先判斷慢在哪裡（初次載入、操作回應、動畫）、原因是什麼（過大的圖片、過重的 JavaScript、反覆觸發版面計算）、影響誰（所有人、只有手機、慢速網路），並先修影響最大的一項。不得在主要瓶頸未處理前做微小優化，也不得優化本來就不慢的地方。

### Good Example

這個範例先指出最大的瓶頸與依據，再說明要修什麼。

```text
首頁變慢的主因是主視覺圖：程式碼載入的是 4000px、3.2MB 的 JPG，但畫面上只顯示 800px 寬。我會先處理這張圖，其他小地方影響不大，暫時不動。
```

### Bad Example

這個範例在 3.2MB 主視覺圖還沒處理時，先把各元件包上 `memo()`，花了力氣卻幾乎感覺不到差別。

```jsx
export default memo(Footer);
export const Badge = memo(({ label }) => <span>{label}</span>);
```

## Rule 3 -- 只用 Lighthouse 或程式碼判斷

**強度：MUST**

量測只能使用 Lighthouse，或直接讀程式碼判斷（圖片實際尺寸與顯示尺寸、匯入的套件大小、首屏載入的資源、會在捲動或輸入時反覆執行的程式）。修改前後必須用同一種方式比較。不得要求使用者安裝或執行其他效能工具。

### Good Example

這個範例從程式碼找出整包載入的大型套件，並說明修改後的差異。

```text
我從程式碼看到首頁一開始就載入整個圖表套件（約 400KB），但圖表在頁面下方才會出現。改成捲到那裡才載入後，首屏需要下載的 JavaScript 會少掉這一大塊。
```

### Bad Example

這個範例要使用者安裝額外的監控與分析工具才能開始，門外漢無法完成，工作卡住。

```text
請先安裝 webpack-bundle-analyzer 並接上 Sentry Performance，把報告貼給我後我再開始優化。
```

## Rule 4 -- 核心網頁指標門檻

**強度：MUST**

修改規格與原型的目標必須符合：最大內容繪製 LCP 小於 2.5 秒、互動到下一次繪製 INP 小於 200ms、累計版面位移 CLS 小於 0.1，提出的修改不得讓任何一項變差。修改規格必須寫出現況的量測值與預期改善的指標，修改後的量測由實作流程在修改程式碼後進行。

### Good Example

這個範例以三項門檻回報修改前後的 Lighthouse 數值。

```text
修改前：LCP 4.1 秒、INP 180ms、CLS 0.24
修改後：LCP 2.1 秒、INP 170ms、CLS 0.02（三項都在門檻內）
```

### Bad Example

這個範例只看總分，沒有發現 CLS 從 0.05 惡化到 0.3，使用者會在載入時看到按鈕跳動而點錯。

```text
Lighthouse 效能分數從 72 提升到 85，優化完成。
```

## Rule 5 -- 圖片依顯示尺寸與格式提供

**強度：SHOULD**

圖片要使用 WebP 或 AVIF、依顯示尺寸提供對應大小（不得用 3000px 的圖顯示在 300px 的位置）、以 `srcset` 提供多種寬度，品質壓縮在 80–85% 左右，首屏以下的圖片加上 `loading="lazy"`。

### Good Example

這個範例提供 WebP 多種寬度並延遲載入首屏以下的圖片。

```html
<img src="team-800.webp"
     srcset="team-400.webp 400w, team-800.webp 800w"
     sizes="(max-width: 600px) 100vw, 400px"
     width="800" height="533" loading="lazy" alt="團隊合照">
```

### Bad Example

這個範例在 400px 寬的位置放 3000px 的 PNG，使用者要多下載數 MB 的資料，手機上載入特別慢。

```html
<img src="team-original.png" style="width: 400px" alt="團隊合照">
```

## Rule 6 -- 首屏內容不得延遲載入

**強度：MUST**

一打開頁面就看得到的內容（主視覺圖、標題區的圖片）不得加上 `loading="lazy"` 或延後載入，最大內容的圖片要優先載入。

### Good Example

這個範例讓首屏主視覺立即且優先載入。

```html
<link rel="preload" as="image" href="hero-1200.webp">
<img src="hero-1200.webp" fetchpriority="high" width="1200" height="600" alt="新品上市">
```

### Bad Example

這個範例把首屏主視覺設為延遲載入，瀏覽器要等版面算完才開始下載，LCP 明顯變慢。

```html
<img src="hero-1200.webp" loading="lazy" alt="新品上市">
```

## Rule 7 -- 預留空間避免版面跳動

**強度：MUST**

圖片、影片、嵌入內容與廣告位必須預先保留空間（設定 `width`、`height` 或 `aspect-ratio`），不得在既有內容上方插入後載入的內容。

### Good Example

這個範例用 `aspect-ratio` 先保留影片區的空間。

```css
.video-embed { aspect-ratio: 16 / 9; width: 100%; }
```

### Bad Example

這個範例在載入完成後才把通知列插到頁面最上方，整頁內容被往下推，使用者正要點的按鈕突然移位而點錯。

```js
fetch('/api/notice').then(r => r.json()).then(n => {
  document.body.prepend(renderNoticeBar(n));
});
```

## Rule 8 -- 動畫不動版面屬性

**強度：SHOULD**

移動與淡入淡出動畫使用 `transform` 與 `opacity`，預設避免動畫 `width`、`height`、`top`、`left`、margin 等會觸發重新排版的屬性。模糊、濾鏡、陰影等效果可以使用，但要限制在小而獨立的區域。`will-change` 只加在已知昂貴且即將動畫的元素上，不得全面套用。

### Good Example

這個範例用 `transform` 做側欄滑入，`will-change` 只加在這個元素。

```css
.drawer { transform: translateX(-100%); transition: transform 240ms ease-out; will-change: transform; }
.drawer.open { transform: translateX(0); }
```

### Bad Example

這個範例動畫 `left` 並對所有元素加上 `will-change`，每一格都要重新排版，大量合成圖層也耗盡手機記憶體。

```css
* { will-change: transform, opacity; }
.drawer { left: -300px; transition: left 240ms; }
.drawer.open { left: 0; }
```

## Rule 9 -- 大型程式碼按需載入

**強度：SHOULD**

首屏用不到的大型元件、路由與套件要用動態匯入延後載入，並移除沒有使用的套件與第三方腳本。非關鍵的腳本加上 `defer` 或 `async`。

### Good Example

這個範例讓圖表元件在需要時才載入。

```jsx
const SalesChart = lazy(() => import('./SalesChart'));
<Suspense fallback={<ChartSkeleton />}><SalesChart /></Suspense>
```

### Bad Example

這個範例為了一個日期格式化函式匯入整個套件，首屏多下載數百 KB 卻只用到其中一小段。

```js
import _ from 'lodash';
import moment from 'moment';
const label = moment(date).format('YYYY/MM/DD');
```

## Rule 10 -- 字型載入不阻擋文字

**強度：SHOULD**

字型要設定 `font-display: swap` 或 `optional`，只載入實際用到的字重，使用 woff2，首屏用到的字型可以 preload；從 Google Fonts 引入時在網址加上 `display=swap` 並只列出用到的字重。

### Good Example

這個範例只載入兩個用到的字重並設定 `display=swap`。

```html
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@400;700&display=swap" rel="stylesheet">
```

### Bad Example

這個範例載入全部九種字重且沒有 `display=swap`，中文字型檔很大，字型下載完之前畫面上的文字都是空白。

```html
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@100;200;300;400;500;600;700;800;900" rel="stylesheet">
```

## Rule 11 -- 執行期避免重複運算

**強度：SHOULD**

讀取版面尺寸與寫入樣式要分批進行，不得在迴圈中交替讀寫。超過數百筆的長清單使用虛擬捲動或 `content-visibility: auto`；捲動與輸入事件的處理要節流或防抖，JavaScript 動畫使用 `requestAnimationFrame`。

### Good Example

這個範例先一次讀完所有高度，再一次寫入。

```js
const heights = items.map(el => el.offsetHeight);
items.forEach((el, i) => { el.style.height = `${heights[i] * 2}px`; });
```

### Bad Example

這個範例在迴圈中交替讀寫，每次讀取都強迫瀏覽器重新計算版面，清單一長畫面就卡住。

```js
items.forEach(el => {
  const h = el.offsetHeight;
  el.style.height = `${h * 2}px`;
});
```
