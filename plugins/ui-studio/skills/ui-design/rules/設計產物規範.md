# 設計產物規範

## Rule 1 -- 不得修改專案程式碼

**強度：MUST**

任何用法都不得修改專案的原始碼、樣式、設定檔與相依套件，只能寫入設計產物：原型、局部示意、PRODUCT.md、DESIGN.md、tokens、修改規格、檢查報告，以及 ui-assets 取得的素材與素材清單。即使修法很小、很明確，也必須寫進修改規格，由實作流程（例如 SDD 的 implement）修改程式碼。

### Good Example

這個範例把設定頁的修正寫成修改規格，專案的元件檔沒有被改動。

```text
用法：收尾（設定頁）
產出：design/修改規格-設定頁.md 第 3 項：`src/pages/Settings.tsx` 的儲存按鈕在送出中沒有停用 → 送出中停用並顯示「儲存中…」
專案檔案：未修改
```

### Bad Example

這個範例直接改了專案的元件檔，繞過實作流程與測試，按鈕的 `data-testid` 被改名後驗收測試找不到元素。

```text
用法：收尾（設定頁）
已修改 src/pages/Settings.tsx：儲存按鈕改為 <SubmitButton data-testid="save">，送出中停用。
```

## Rule 2 -- 做新畫面產出靜態原型

**強度：MUST**

做新畫面時，每個頁面產出一個可直接以瀏覽器開啟的 HTML 原型，只使用內嵌的假資料，不呼叫後端或外部服務；有 tokens.css 時把它的內容原樣放進原型的 `<style>`，不另行抄寫數值。呼叫者沒有指定位置時，原型放在專案根目錄的 `design/prototype/`，每個頁面一個檔案。

### Good Example

這個範例把 tokens.css 原樣放進原型，頁面樣式全部引用 token。

```html
<!-- design/prototype/home.html -->
<style>
/* 以下為 tokens.css 原文 */
:root { --color-paper: oklch(97% 0.012 85); --space-4: 16px; }
/* 頁面樣式 */
body { background: var(--color-paper); padding: var(--space-4); }
</style>
```

### Bad Example

這個範例把 token 的值手抄進樣式，DESIGN.md 之後調整色彩時原型不會跟著改，兩邊的值開始分歧。

```html
<style>
body { background: #faf7f0; padding: 16px; }
</style>
```

## Rule 3 -- 既有畫面產出修改規格

**強度：MUST**

收尾與單項改善既有畫面時，必須以修改規格交付：每一項寫出優先順序、位置（檔案與元件，或選擇器與寬度）、現況、改成什麼（確切值或 token）與依據的規範。需要讓人看到修改後的樣子時，附上只涵蓋受影響區塊的局部示意 HTML；不得為了示意重做整頁原型。呼叫者沒有指定位置時，修改規格寫在 `design/修改規格-<畫面名稱>.md`，局部示意放在 `design/prototype/`。

### Good Example

這個範例的每一項都寫出確切的位置、現況與改法，並只為改變外觀的一項附上局部示意。

```markdown
| 優先 | 位置 | 現況 | 改成 | 依據 | 示意 |
|---|---|---|---|---|---|
| P1 | `src/pages/Settings.tsx` 儲存按鈕 | 送出中仍可點擊 | 送出中停用，文字改為「儲存中…」 | 強韌規範 Rule 8 | — |
| P2 | `.settings-form` 欄位間距，390px | 欄位之間 `4px` | `var(--space-4)` | 版面規範 Rule 4 | design/prototype/settings-form.html |
```

### Bad Example

這個範例只寫出感想，沒有位置與確切的值，實作的人無法照著修改，也無法驗收是否改對。

```markdown
- 設定頁看起來有點擠，間距可以再寬一點。
- 按鈕狀態要再處理。
```

## Rule 4 -- 修改原型時以舊原型為底

**強度：MUST**

目標本身是原型時（例如呼叫者要求修改既有原型，或介面標為 MOD），直接修改該原型檔，以最新的同一頁原型為底，只改這次要改的部分，沒有改變的區塊保持一致。

### Good Example

這個範例以上一版的相簿頁原型為底，只改這次新增的排序控制。

```text
目標：ui/prototype/album.html（MOD：新增排序控制）
做法：複製 plan 003 的 album.html，只在工具列加入排序下拉選單與它的三種狀態，其餘區塊不動。
```

### Bad Example

這個範例重新撰寫整頁原型，原本的格線、文案與定位屬性都被換掉，與上一版的契約和測試對不起來。

```text
目標：ui/prototype/album.html（MOD：新增排序控制）
做法：依新的想法重寫 album.html，順便把格線改成瀑布流。
```
