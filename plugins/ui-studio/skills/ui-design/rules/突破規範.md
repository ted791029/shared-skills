# 突破規範

## Rule 1 -- 開始前白話告知較大膽

**強度：MUST**

使用者要求突破常規時，Claude 的第一段回覆必須用白話告訴使用者：這次的改法會比平常大膽，可能用到較新的瀏覽器功能，舊手機或舊瀏覽器會看到較簡單的版本。不得使用固定開場白、符號橫幅或「overdrive」「WebGL」等術語當開場。

### Good Example

這個範例用白話先說明這次會比較大膽，以及舊裝置會看到什麼。

```text
這次我會用比較大膽的做法，讓畫面有平常網頁少見的效果。效果會用到比較新的瀏覽器功能，舊手機或舊瀏覽器會自動改看簡單但一樣好用的版本，不會壞掉。
```

### Bad Example

這個範例用符號橫幅與術語開場，使用者看不懂接下來要發生什麼，也不知道舊裝置會受影響。

```text
──── ⚡ OVERDRIVE ────
》》》 Entering overdrive mode... 啟用 WebGPU shader pipeline。
```

## Rule 2 -- 動手前提出方向並等待同意

**強度：MUST**

寫任何程式碼前，Claude 必須提出 2～3 個方向，每個方向用白話描述「使用者會看到、感覺到什麼」與代價（舊裝置的表現、載入變慢多少、做起來多複雜），並標出 Claude 推薦的一個，等使用者回覆後只做被同意的方向。不得在使用者回覆前開始實作。

### Good Example

這個範例在動手前列出三個白話方向與代價，標出推薦，並停下等待回覆。

```text
我想到三種做法，請選一個（直接回「照推薦」也可以）：

1.（推薦）按下「查看詳情」時，卡片會平順地放大變成詳情頁，不會突然跳頁。幾乎所有瀏覽器都支援，不影響速度。
2. 首頁背景加上會跟著滑鼠流動的光影。很吸睛，但舊筆電可能變慢，我會讓舊裝置改看靜態背景。
3. 往下捲動時，各區塊依序淡入並帶一點景深。中等複雜，Firefox 會改看沒有動畫的版本。
```

### Bad Example

這個範例沒有提出選項就直接實作，使用者無法在大改前喊停，做出不適合的效果時只能整批丟掉。

```text
我已經幫首頁加上 WebGL 粒子背景與捲動視差，程式碼改好了。
```

## Rule 3 -- 依畫面性質選突破點

**強度：SHOULD**

突破點必須配合畫面性質：行銷頁、作品集等展示型畫面可以用感官效果（捲動帶動的揭示、著色器背景、電影感轉場）；表格、表單、對話框等功能型畫面的突破點在操作手感（從觸發按鈕變形展開的對話框、10 萬列仍流暢的虛擬捲動、即時驗證）；資料量大的畫面在流暢度（Canvas／WebGL 繪製、資料狀態之間的動畫過渡）。功能型畫面不得加上與任務無關的裝飾特效。

### Good Example

這個範例在設定頁用「即時儲存加狀態過渡」當突破點，提升的是操作手感。

```jsx
<Switch
  checked={enabled}
  onChange={(v) => {
    setEnabled(v);            // 先樂觀更新畫面
    save({ enabled: v }).catch(() => setEnabled(!v));
  }}
/>
<span className="save-status" data-state={status}>已儲存</span>
```

### Bad Example

這個範例在設定頁加上粒子背景，特效與設定任務無關，只會讓頁面顯得突兀又拖慢效能。

```jsx
<SettingsPage>
  <ParticleBackground count={2000} />
  <SettingsForm />
</SettingsPage>
```

## Rule 4 -- 只改體驗不改產品功能

**強度：MUST**

突破只能改變既有功能「感覺起來」如何，不得新增產品能力，例如即時協作、離線模式、新的後端 API。這類需求屬於產品決策，Claude 必須告知使用者這超出畫面改善範圍，不得自行實作。

### Good Example

這個範例讓既有的清單展開為詳情頁時有形變轉場，功能本身沒變。

```css
.card { view-transition-name: var(--card-id); }
::view-transition-group(*) { animation-duration: 320ms; }
```

### Bad Example

這個範例為了「感覺很厲害」加上 WebSocket 即時協作，等於擅自新增產品功能與後端依賴，超出畫面改善的範圍。

```js
const socket = new WebSocket('wss://api.example.com/collab');
socket.onmessage = (e) => applyRemoteEdit(JSON.parse(e.data));
```

## Rule 5 -- 新技術必須有可用的退路

**強度：MUST**

每個新技術效果都必須漸進增強：先以功能偵測包住，不支援時退回仍然好看、好用的版本。捲動驅動動畫用 `@supports (animation-timeline: scroll())` 包住（Firefox 只在 flag 下支援）；WebGPU 必須同時檢查 `'gpu' in navigator` 與 `navigator.gpu.requestAdapter()` 不為 null，否則退回 WebGL2，再退回純 CSS。不得使用沒有退路的前沿 API。

### Good Example

這個範例依序偵測 WebGPU、WebGL2，最後保留純 CSS 版本。

```js
if ('gpu' in navigator && await navigator.gpu.requestAdapter()) {
  initWebGPU(canvas);
} else if (canvas.getContext('webgl2')) {
  initWebGL2(canvas);
} else {
  document.body.classList.add('static-hero'); // CSS 版本仍完整呈現
}
```

### Bad Example

這個範例只檢查 `navigator.gpu` 存在，GPU 被封鎖或無頭環境時 `requestAdapter()` 回傳 null，畫面直接空白。

```js
const adapter = await navigator.gpu.requestAdapter();
const device = await adapter.requestDevice();
```

## Rule 6 -- 效果必須維持 60fps

**強度：MUST**

效果以每秒 60 格為目標，在中階裝置上可能低於 50 格時必須簡化。WebGL context、WASM 模組等重資源只在接近可視範圍時才初始化，離開畫面的繪製必須暫停。不得交付在中階裝置上會卡頓的效果。

### Good Example

這個範例在區塊接近畫面時才初始化，離開畫面就暫停繪製。

```js
const io = new IntersectionObserver(([entry]) => {
  if (entry.isIntersecting) { scene ??= initScene(canvas); scene.play(); }
  else scene?.pause();
}, { rootMargin: '200px' });
io.observe(canvas);
```

### Bad Example

這個範例在頁面載入時就初始化 WebGL 並持續繪製，使用者看不到時仍在耗 CPU 與電量，中階手機會明顯卡頓。

```js
const scene = initScene(canvas);
function loop() { scene.render(); requestAnimationFrame(loop); }
loop();
```

## Rule 7 -- 聲音必須由使用者開啟

**強度：MUST**

任何音效或 Web Audio 都必須預設關閉，只在使用者明確按下開啟後才播放。不得在載入或捲動時自動發聲。

### Good Example

這個範例提供預設關閉的音效開關，使用者按下才建立 AudioContext。

```jsx
<button aria-pressed={soundOn} onClick={() => { ensureAudioContext(); setSoundOn(!soundOn); }}>
  {soundOn ? '關閉音效' : '開啟音效'}
</button>
```

### Bad Example

這個範例在頁面載入時就播放音效，使用者在辦公室或公共場所會被嚇到，且多數瀏覽器會阻擋而產生錯誤。

```js
window.addEventListener('load', () => new Audio('/whoosh.mp3').play());
```

## Rule 8 -- 只做一個亮點

**強度：MUST**

一個畫面只放一個突破性的亮點，不得疊加多個互相競爭的特效。

### Good Example

這個範例只讓主視覺有捲動揭示，其他區塊維持安靜。

```css
@supports (animation-timeline: scroll()) {
  .hero-title { animation: reveal linear both; animation-timeline: scroll(); }
}
.features, .pricing { /* 不加特效 */ }
```

### Bad Example

這個範例同時加上游標光暈、視差背景與文字打字機效果，三個效果搶注意力，沒有一個能被記住，畫面只剩雜亂。

```jsx
<CursorGlow />
<ParallaxBackground layers={5} />
<TypewriterHeadline />
```

## Rule 9 -- 不以特效掩蓋基本問題

**強度：MUST**

如果畫面的版面、字體或配色本身有明顯問題，Claude 不得用特效蓋過去，必須用白話告知使用者先處理這些基本問題，並說明建議改善的項目。

### Good Example

這個範例在發現基本問題時先用白話說明，而不是直接加特效。

```text
加特效之前我先提醒：目前首頁的文字大小和間距不一致，看起來有點亂。加了動畫會讓亂的地方更明顯。建議先整理版面和字體，再來加亮點效果。
```

### Bad Example

這個範例無視版面已經雜亂，直接疊上動畫，使用者會以為效果不好看，實際上問題出在基本版面。

```text
已加上捲動揭示動畫，版面的部分維持原樣。
```

## Rule 10 -- 以影格與原型確認效果細節

**強度：SHOULD**

完成後 Claude 必須依動態規範 Rule 9 以影格驗證效果，並讀原型逐條確認：緩動曲線與時長是否刻意設定（不是預設值）且符合動態規範 Rule 4、交錯動畫的延遲是否一致、退路分支是否真的會被執行、離開畫面時是否暫停，並修正不符之處後才結束。

### Good Example

這個範例明確設定減速曲線與交錯延遲，退路分支也有實際樣式。

```css
.item { transition: transform 420ms cubic-bezier(0.22, 1, 0.36, 1); transition-delay: calc(var(--i) * 40ms); }
@supports not (animation-timeline: scroll()) { .item { opacity: 1; transform: none; } }
```

### Bad Example

這個範例使用預設 `ease` 且沒有退路樣式，不支援的瀏覽器中元素停在 `opacity: 0` 永遠看不見。

```css
.item { opacity: 0; transition: all 0.3s ease; }
```
